Приложение «Pseudex»

Спецификация взаимодействия с API Сервиса «Яндекс.Директ» · версия 1.0 · 17.09.2026

1. Назначение

«Pseudex» — служебный модуль внутренней операторской панели компании, развёрнутой на собственном сервере в Российской Федерации. Приложение не является продуктом для третьих лиц и не предоставляет доступ к рекламным кампаниям кому-либо, кроме владельца аккаунта pseudex-owner.

Задача модуля — собрать в одном месте расход и результаты рекламных кампаний рядом с бизнес-показателями собственного продукта, чтобы эффективность размещения оценивалась по деньгам (регистрации и оплаты), а не по кликам.

Владелец аккаунта однократно выдаёт приложению доступ по OAuth. Обмен кода авторизации на токены выполняется один раз; далее приложение получает access_token из refresh_token автоматически.

3. Используемые методы API

Все обращения — POST https://api.direct.yandex.com/json/v5/<сервис> с телом {"method": "…", "params": {…}}.

СервисМетодНазначениеСостояние
campaignsget список кампаний: идентификатор, название, состояние, бюджет реализовано
reportsget отчёт по расходу, показам, кликам и конверсиям в разработке
campaignsupdate приостановка и возобновление собственных кампаний планируется
Изменение ставок, бюджетов и текстов объявлений в автоматическом режиме приложением не выполняется. Решение о запуске, остановке и изменении кампаний принимает владелец аккаунта.

4. Какие данные передаются и получаются

Получаются из Директа: идентификаторы и названия кампаний, их состояние, расход и статистика показов и кликов. Данные отображаются в закрытой операторской панели и раз в неделю включаются в служебную сводку, направляемую владельцу аккаунта.

Передаются в Директ: приостановка и возобновление кампаний по решению владельца (планируется). Иных сведений приложение в Директ не отправляет.

Отдельно от Директа приложение обращается к API Яндекс.Метрики (api-metrika.yandex.net, счётчик 112743085) и передаёт туда офлайн-конверсии — факт регистрации, активации ключа и оплаты. Это делается для оценки эффективности рекламы по конечному результату. Передаётся только идентификатор клика (yclid) и сумма оплаты; персональные данные клиентов в Метрику не уходят.

5. Безопасность и хранение

  • refresh_token хранится в защищённом файле окружения на сервере приложения (права 600), доступ к серверу — только у владельца.
  • access_token не сохраняется на диск: он выводится из refresh_token и живёт в оперативной памяти процесса.
  • Учётные данные приложения не хранятся в исходном коде и не передаются третьим лицам.
  • Доступ к операторской панели закрыт паролем и вторым фактором (TOTP); панель недоступна для поисковых систем.
  • Каждое раскрытие сохранённого значения в панели записывается в журнал с указанием пользователя и времени.

6. Интерфейс

Экран доступен только после входа в панель; публичного адреса у него нет. Доступ к API отображается на экране явно, чтобы состояние подключения нельзя было перепутать с отсутствием данных.
