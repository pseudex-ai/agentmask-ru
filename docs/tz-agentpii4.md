# AgentPII-RU v4 — техзадание

**Нормативный файл — `prototype/bench/agentpii4/schema.py`.** Этот документ
объясняет, почему он такой: какая альтернатива отвергнута и чем она платила.
Расхождение между документом и схемой разрешается в пользу схемы.

Версия 0.4 · 9 видов · 11 инструментов · 3 плеча · 3 уровня инвариантности ·
360 случаев (пилот 120 × K) · русский язык

---

## 1. Что v4 меняет и почему

v3 нашла настоящие дефекты и должна быть дополнена по одной причине: **она
мерила возврат против эталона, написанного руками, и не видела, что агент
делает со значением.** Замер 01.09 показал: на трёх плоских схемах модель
копирует подмену дословно в 93% случаев. Преобразования — разложение по полям,
кусок, склейка, производные (индекс из города, возраст из даты, транслит,
инициалы, пол), валидация по контрольной сумме, вложение в URL/CSV — провоцирует
**схема инструмента**, а не модель. У v3 таких схем не было, поэтому её 96% —
это 96% на копировании.

Ресёрч 02.09 (`research/2026-09-02-agent-form-benchmark.md`): никто в мире не
мерит корректность ДЕТОКЕНИЗИРОВАННОГО вызова инструмента — ни ~30 работ по
приватности в агентах, ни 13 коммерческих продуктов. Ближайшие приборы —
τ-bench / AppWorld / AgentDojo — сравнивают **эффект** (состояние после
прогона), а не строки, и это перенято.

Главное требование владельца: **любая форма, в которой агент передаёт те же ПД
в инструмент, должна восстановиться в настоящее значение, не сломав вызов.**
Прибор обязан показать каждый класс преобразования, включая те, что движок не
чинит, — чтобы движок улучшался по измеренной частоте, а не по догадке.

## 2. Эталон — контрольное плечо, а не строка

| альтернатива | чем платила |
|---|---|
| эталон руками (v3) | описывает ОДНУ форму аргумента; агент, написавший другую правильную форму, штрафуется; преобразования невидимы |
| эталон = C, сравнение строк | `+79164021187` против `8 916 402 11 87` — расхождение там, где инструмент его не увидит |
| **эталон = C, сравнение ТИПИЗИРОВАННОГО состояния мока** | принято: парсер по документации API решает, что есть одно и то же значение |

Три плеча: **C** (без шлюза), **I** (шлюз), **C′** (второй контроль). Эффект =
agreement(I, C) − agreement(C′, C). C запускается первым и один: контроль,
который не завершился, не с чем сравнивать, и два других плеча потратили бы
деньги, чтобы измерить ничего. I и C′ — параллельно, у каждого свой свежий мок.

**Парность по индексу повтора.** K повторов одного случая — K троек; повтор i
плеча I сравнивается с повтором i плеча C. Парная разность — «бесплатное»
снижение дисперсии оценки, и это единственный способ вычесть собственный шум
модели на том же случае.

## 3. Инструменты — по документации, парсеры строгие

| инструмент | источник формы | что провоцирует |
|---|---|---|
| `delivery_create_order` | CDEK v2 | `postal_code` ← город (производная), `phones[].number` E.164 |
| `courier_book` | Яндекс Доставка claims | адрес по полям `locality/street/building/porch/sflat`, ISO-интервал |
| `address_suggest` | DaData | возвращает 3 НАСТОЯЩИХ записи из seed, агент выбирает |
| `payment_create` | ЮKassa | карта по Луну, `cardholder` ← транслит, `bik` ^04\d{7}$, счёт 20 цифр с ключом |
| `passport_verify` | МВД/Госуслуги | серия ^\d{4}$ и номер ^\d{6}$ порознь, СНИЛС mod 101 |
| `clinic_book` | ЕМИАС-подобный | `age` ← дата рождения, `gender` ← имя |
| `crm_find_contact` / `crm_upsert_contact` | amoCRM | поиск по телефону/почте/фамилии; `initials`, `name_latin`, вложенный адрес |
| `notify_sms` | SMS Aero | свободный текст + URL с `phone=` внутри |
| `callback_schedule` | — | `at` ISO с offset, `timezone` ← город (IANA) |
| `crm_import_csv` | — | CSV-контейнер, 2 строки, фиксированный заголовок |

Правило парсера одно: принимает ровно то, что документированный API принимает,
отказывает с именем документированного правила, никогда не чинит и не
валидирует сверх документации. Отказ возвращается модели как ошибка инструмента
(`is_error`), как ответил бы настоящий API.

## 4. Инвариантность на трёх уровнях

| уровень | что сравнивается | зачем отдельно |
|---|---|---|
| L1 | последовательность имён инструментов (позиционно) | «агент отказался вызывать» — свой класс (`no_call`) |
| L2 | множества ключей аргументов по вызову | агент уронил или добавил поле |
| L3 | типизированное состояние мока + `state_verbatim` | ЧТО записано; разрыв с дословным — что простил парсер |

Одним числом это не печатается никогда: L1 = 100% при L3 = 45% — это
«инструменты те же, содержимое другое», и обе половины нужны.

## 5. Таксономия per-field и `transform_of`

Порядок решений закреплён в `taxonomy.classify_field`, первое совпадение
выигрывает: `agree` → `absent`/`extra` → `residual` → `validated_refused` →
`ref_refused` → typed-equal → `derived` → `other_person` → `stale_value` →
`container_embedded` → `reformatted` → `fragment` → `composed` → `other`
(под-класс из v3 `classify_break`).

Три класса несут пометку в отчёте: `derived` и `validated_refused` — «движок не
чинит по построению» (значение выведено из подмены; фейк отвергнут валидацией
инструмента), `residual` — «дефект продукта» (подмена дошла до инструмента).

`transform_of` считается для каждого поля в каждом плече, включая C: verbatim /
reformatted / fragment / composed / derived / container_embedded / invented /
absent. Гистограмма в C — **мера провокационной силы корпуса**. Прибор, на
котором агент только копирует, ничего не измерил, что бы ни говорил эффект.

**Один человек — несколько подмен.** Сообщение говорит «букин сергей», а запись
CRM из результата инструмента — «Букин Сергей Иванович»; движок чеканит их
порознь, и инициалы, выведенные из второй, — всё равно `derived`. Проверка
знает все подмены одной identity (`alternates`), иначе половина производных
называлась `misderived`.

**Производная сравнивается на уровне, который определяет источник.** Индекс из
города — это зона (три цифры); остальные три модель выдумывает В ОБОИХ плечах.
Сравнение шести цифр дало бы шумовой пол 14% на детерминированном агенте.

## 6. Эталон построен, не найден

Тексты собираются `Writer.put(chunk, key)` со смещениями при сборке;
`validate.prove_no_search` через `sys.setprofile` доказывает, что в кадрах
сценариев и writer не вызывались `str.find/index` и `re.*`. `find_distinct_share`
требует ≥12 случаев, где `text.find(value) != start`: `correction` гарантирует
это — старый адрес стоит раньше нового. Урок v3 («`_canonical_name` искал части
по подстроке, и 162 из 183 sloppy-провалов были ошибкой эталона») здесь не
повторим по построению.

Канон продиктованного идентификатора — цифровой (`+7…`, `dd.mm.yyyy`, «серия
номер»): именно это движок восстанавливает на плече инструмента и именно это
пишет контроль. Имена и адреса держат правило v3 — канон того, что БЫЛО
НАПИСАНО.

## 7. Что нашёл скриптовый агент за $0 (02.09.2026, до живого прогона)

`smoke --engine` — политики copier/decomposer/deriver/validator/sloppy/noisy
через `RealGateway`. Не модель, а труба; но труба нашла:

| дефект | как выглядел | исправление |
|---|---|---|
| телефон возвращался в форме КЛИЕНТА, не агента | модель пишет `+7999…` (E.164 фейка), инструмент получает `8 916 402 11 87` → `phone_not_e164` в 54 из 54 аргументов | `redact._digits_in_form_of`: настоящие цифры в форме агента; телефон — по признаку «+» или разной длине, не по первой цифре (`805-…` СНИЛС становился `405-…`) |
| адрес по ВЛОЖЕННЫМ полям не собирался | `contact.address.street` уезжал фейком с кодом 200 и пустым списком остатков | `_join_addresses_deep` — сборка на каждом уровне объекта |
| город внутри улицы | `split_roles("Москва, ул. Ленина 14")` → street «Москва, ул. Ленина»; в речи «воткинск школьная» | роль `city` в `role_spans`; в сборке — город из ТОКЕНА, когда форма не даёт признака |
| часть адреса не в форме агента | агент пишет `building: "103"`, получает «шестьдесят три» → `house_format` | `morph_places.part_in_form_of`: цифры где агент писал цифры, слово-тип где писал слово-тип |
| фамилия в косвенном падеже не разрешалась | модель копирует «Наумова» из «Наумова Льва Евгеньевича» в `last_name`; индекс держит «наумов» | `residual_of` спрашивает номинатив обоих родов |

На 30 случаях `chain`: PHONE agree 36/90 → 90/90, LOC 93/120 → 117/120.
Оставшиеся расхождения — `derived` (инициалы, транслит) и `validated_refused`
(СНИЛС с невалидной суммой) — классы, которые движок не чинит по построению.

## 8. Статистика

pass^k на случай (τ-bench: C(c,k)/C(n,k)); эффект — парная разность на случай;
95% ДИ — кластерный бутстрап по различным значениям ПД (Field & Welsh 2007);
McNemar exact на дискордантных парах, ПОМЕЧЕН как игнорирующий кластеры; ICC(1)
по случаю и по значению, DEFF = 1+(m̄−1)·ICC (Kish); при нуле расхождений —
односторонний пол Clopper–Pearson (0 на 400 парах сертифицирует ≥99.25%, не
100%); отчёт печатает n для ±2pp по ИЗМЕРЕННОМУ согласию.

## 9. Деньги

Один `SpendLedger` на агента и судью, инвариант `committed + reserved ≤ ceiling`
в каждый момент. Тройка резервирует `cap × 3` до первого токена и записывает
измеренную цену (`ResultMessage.total_cost_usd`, кумулятивный по сессии).
Тройка, которую потолок не пустил, ЗАПИСАНА как `refused`, не выброшена. Порядок
— дороже-первым. Таймаут списывается ПОЛНЫМ капом: прогон был и биллился.

Пилот: `--tier nano --repeats 1 --ceiling 12` измеряет цену тройки; `small`
(120 × K) подгоняется под остаток до $60 (решение владельца 02.09.2026).

## 10. Судья

Детерминированный судья на финальном ответе всех плеч (пол), LLM-судья v3
(`judge.py`) только на ответ плеча I, композиция как в v3 `_judge_answer`:
пол поднимается тем, что модель смогла ДОКАЗАТЬ; невалидная находка — `unjudged`,
считается отдельно.

## 11. Чего v4 сознательно не делает

Не чинит движок по результатам пилота; не запускает мульти-модель
(GPT/Qwen/GigaChat/YandexGPT — после пилота); не переписывает v3 — она остаётся
сравнимой базой; не судит закрытые ответы моделью.
