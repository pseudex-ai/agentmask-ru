# ТЗ: заменяемые коннекторы моделей для AgentPII v5

Статус: реализация и точечные проверки разрешены владельцем 2026-09-26.
Nano и более крупные прогоны требуют отдельного GO. Работа — ветка
`bench/v5-codex`, независимо от v6 и основного рабочего дерева.

## Результат

Существующий v5 запускает любую поддерживаемую им выборку с независимо выбранными
коннекторами агента и судьи. Claude остаётся доступным. Новый агент — DeepSeek Flash
напрямую через его официальный OpenAI-совместимый Responses API. Новый судья —
OpenAI Agents SDK с нашим `Model`, транспорт которого — официальный Codex Python SDK
с ChatGPT-авторизацией. Начальная модель судьи — GPT-5.6 Terra/medium: кандидат на
замену Sonnet 5, но эквивалентность качества доказывается только калибровкой.
Подписка расходует Codex-лимит, а не OpenAI API-баланс.

## Границы и интерфейсы

- Корпус, метрики, правила формы, мок инструментов и три плеча C/I/C2 сохраняются.
- Все три плеча используют один коннектор и одну конфигурацию агента.
- Интерфейс агента выполняет диалог, вызывает только переданные инструменты,
  возвращает ответы, завершение и использование ресурсов. SDK скрыт в коннекторе.
- Интерфейс судьи принимает существующий промпт/JSON-схему и возвращает вердикт.
  Существующие blind guard, pre-gate, проверка цитаты и штамп калибровки сохраняются.
- Между инструментом и моделью остаются restore → call → serialize → mask и
  исходные записи наблюдателя v5. Ошибка транспорта не считается дефектом движка.
- Новая конфигурация записывает роль, SDK/runtime, провайдера, модель, effort,
  происхождение стоимости; ключи в записи не попадают.
- Ни новая модель, ни новый runtime не наследуют доказанную калибровку Sonnet.
- DeepSeek получает только benchmark system, полную историю текущего сценария и
  инструменты этого сценария. `previous_response_id` не используется: его Responses
  API stateless. Встроенных инструментов и агентного runtime между ним и harness нет.
- Судья работает в отдельном `CODEX_HOME`, где запрещён `AGENTS.md`. Рабочая папка —
  пустая временная директория. Environment/permissions/apps/collaboration/skills,
  project docs, shell, MCP, web, subagents, hooks и `request_user_input` отключены.
  `thread_start.instruction_sources` обязан быть пуст; любой tool-call судьи — ошибка.
- Agents SDK обязан передать наш system, user и JSON schema без смыслового изменения;
  собственный `Model` проверяет это до вызова Codex. Tracing Agents SDK отключён.

## Расход и восстановление

- Одна активная оценка судьи на старте; число запросов ограничено явно.
- Резерв USD DeepSeek и лимит запросов подписочного судьи учитываются отдельно.
  Лимит токенов проверяется после ответа: один уже начатый ответ может превысить
  его. Резерв не является жёстким серверным spending cap DeepSeek.
- Стоимость, вычисленная по токенам, помечена оценкой; неизвестная не считается нулём.
- Завершённые результаты сохраняются, report/replay не вызывают модели.
- Исчерпание квоты, таймаут, отказ модели и некорректный JSON видны в результатах.
- Codex resume пока явно отклоняется: нельзя смешать несовместимые записи.
  Новую выборку можно запускать в новом каталоге; report/replay работают офлайн.

## Приёмка

1. Офлайн: общий контракт коннекторов, маршрутизация трёх плеч и судьи, неправильный
   tool/JSON, лимит запросов, ошибки/отмена, отсутствие ключей в диагностике.
2. Регресс: существующие тесты v5 и perfect gateway, неизменный корпус и replay.
3. Точечно: отдельные существующие НЕ-holdout случаи с реальным DeepSeek, вызовом
   инструмента, результатом через шлюз, судьёй Codex и читаемым отчётом.
4. Многотурность и streaming проверяются отдельно; streaming v5 пока сохраняет
   исходную проверку детокенизации на нарезанном ответе, не объявляется сетевым SSE.
5. Проверить запуск по ids и dry-run других выборок; nano не запускать.

Официальные основания: https://github.com/openai/openai-agents-python/blob/main/src/agents/models/interface.py,
https://github.com/openai/codex/blob/main/sdk/python/docs/api-reference.md,
https://github.com/openai/codex/blob/main/codex-rs/config/src/config_toml.rs,
https://api-docs.deepseek.com/guides/responses_api/.
Версии SDK фиксируются; чистый outbound envelope проверяется локальным capture-тестом.

## Запуск и ограничения текущей версии

В отдельном worktree, из `prototype/`, с отдельным окружением и зависимостями
проекта установите `pip install -r bench/agentpii5/requirements-codex.txt`.
Ключ DeepSeek передаётся через `DEEPSEEK_API_KEY`, не аргументом команды.
Codex должен быть авторизован через ChatGPT в ОТДЕЛЬНОМ каталоге, не OpenAI API key:

```bash
export AGENTPII5_CODEX_HOME=/private/path/v5-codex-home
CODEX_HOME="$AGENTPII5_CODEX_HOME" codex login --device-auth
```

В этом каталоге не должно быть `AGENTS.md`; обычный `~/.codex` для benchmark judge
не используется.

Одна точечная проверка (не nano):

```bash
python -m bench.agentpii5.harness --ids validate-000 \
  --agent-connector deepseek --provider deepseek --model deepseek-flash \
  --judge-connector codex --judge-model gpt-5.6-terra --judge-effort medium \
  --agent-turn-limit 20 --judge-request-limit 2 --connector-max-tokens 60000 \
  --ceiling 1 --concurrency 1 --retries 1 --label connector-check \
  --out /tmp/v5-connector-check --runs /tmp/v5-connector-runs.json
```

В грязном тестовом дереве требуется явный `--dirty-ok`. Для планирования любой
выборки используйте `--dry-run` с `--ids`, `--slice` или `--tier`: вызовов нет.
Лимит `agent-turn-limit` — историческое имя: для DeepSeek он ограничивает HTTP
Responses-запросы всех плеч, включая продолжения после tool calls.
Судья работает последовательно и лимитирует все попытки, включая повтор из-за
неверной цитаты. Перед живым запуском harness требует запас до двух запросов
судьи на каждую тройку; для nano из 30 случаев это `--judge-request-limit 60`.
Для большой выборки лимиты выбираются явно перед отдельным GO.

В `<run>.agent.usage.jsonl` и `<run>.judge.usage.jsonl` лежат накопительные
счётчики сессий: суммировать нужно ПОСЛЕДНЮЮ запись каждой session_id, не все строки.
DeepSeek — оценка по пиковому тарифу; подписочная стоимость судьи не выражается
в API USD. Его ноль в legacy cost_usd означает отсутствие API-счёта, не отсутствие
расхода квоты. Смена модели не наследует калибровку: публикационный гейт остаётся
закрытым. CLI калибровки повторов ещё использует Claude; перенос калибровки —
отдельная работа до принятия чисел нового судьи как продуктового доказательства.

Фактическая приёмка новой архитектуры на 2026-09-26:

| сценарий | результат |
|---|---|
| локальный capture, DeepSeek | реальный OpenAI-клиент отправил только benchmark instructions/history/tools; tool loop завершён |
| локальный capture, Codex | `instructionSources=[]`; system/user/schema совпали побайтно; tools пусты |
| реальный judge smoke | Agents SDK → наш `Model` → Codex SDK → Terra; структурированный ответ получен через ChatGPT subscription |
| `validate-000`, DeepSeek + Terra | C/I/C2 завершены; 22 хопа; $0.010553; malformed tool arguments были возвращены модели и исправлены; судья дал счётный вердикт с цитатой |
| `chain-005`, DeepSeek, без судьи | 3/3 плеча завершены; 29 хопов; $0.025764; многоходовый tool-result/streaming путь измерил 2 остаточные подмены и pre-gate правильно остановил судью |
| nano dry-run | 30 случаев, 90 плеч, 381–387 вызовов модели; ориентир $0.16–0.47 и 13–38 минут при concurrency=1; вызовов моделей не было |

Это синтетические случаи существующего корпуса, не записи клиентов и не data-local.
Nano технически готов, но запускается только после отдельного GO владельца; рекомендуемый
первый запуск — `--concurrency 1`, `--agent-turn-limit 600`,
`--judge-request-limit 60`, `--ceiling 5`. Holdout не запускался. Подписку нельзя
считать безлимитным бесплатным судьёй, а Terra нельзя считать откалиброванным судьёй
до отдельной ручной калибровки.
