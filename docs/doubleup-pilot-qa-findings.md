## Дефекты интеграции, найденные тестированием и исправленные

1. **401 «Provider rejected pilot request».** Backend ходил в gateway с ключом-заглушкой
   `pilot-fixture-no-remote-access`, а живой gateway требует per-run `request_key` из
   `model-access.json`. Ключ теперь читается сидом и провайдером из одного места.
2. **LiteLLM недостижим из контейнера.** TLS-хендшейк к `litellm.inf.2up.dev` таймаутит из Docker
   (VPN на хосте не покрывает Docker VM), хотя с хоста — 401 за 0.77 с. Переключено на прямой
   `api.deepseek.com`: TLS 0.3 с, модель та же (`deepseek-v4-flash`).
3. **Сид затирал живой ключ.** `seed.py` перезаписывал провайдера на заглушку после `enable-live`.
   Теперь читает `/run/pilot/model-access.json`.
4. **Мок-инструменты были невидимы.** `integration_map` без записи = `unknown` = скрыт от агента.
   Добавлены как `BUILTIN`.

## Открытые разрывы (нужно решение владельца движка)

1. **В снапшоте движка пилота нет `/policies` и `/mgmt/custom/patterns`** (оба 404).
   Per-agent экран политик существует на фронте и в backend-прокси, но разговаривать ему не с чем,
   пока в стенд не собран движок с политиками (работа лежит в `must-core`, не смёржена).
2. **Одна и та же подмена на один телефон в двух разных разговорах.** `pseudonym_scope` в запросе —
   `conversation`, но подмена не меняется. Похоже на customer-wide scope в движке. Это вопрос ядра,
   не интеграции; записано, не чинилось.
3. **`/reveal` с неизвестным токеном отвечает `{"value": null}` (200).** Не утечка (значения нет),
   но «нет такого токена» и «значения нет» неразличимы. Решение — за владельцем движка.

## Методологические развилки (для владельца)

- **Живой провайдер.** Владелец разрешил его в этом чате; стенд ходит напрямую в `api.deepseek.com`,
  потому что LiteLLM из контейнера недостижим. Если нужен именно LiteLLM — нужен прокси на хосте
  или маршрут VPN внутрь Docker.
- **Выгрузка Langfuse.** Локализована: каталог `deploy/doubleup-pilot/.state/real-sensitive-corpus-export.log`
  (30 кейсов, 21 полный, 16 с контактами в тулах, 13 с контактом пользователя в аргументах) +
  `research/2026-10-24-real-sensitive-dialogues.md` (21 диалог / 183 хода).
- **`builtin`/`none` как фолбэк.** Оставлены по решению владельца: `none` — для отладки, `builtin` —
  только скрытый env-фолбэк, в клиентском UI их нет.
- **`security_level` на старых графах.** Не мигрируется: новые политики живут по `agent_id`, старый
  уровень — мусор прошлой схемы. Граф без привязки работает по политике инстанса.

## Как воспроизвести

```bash
cd deploy/doubleup-pilot
python3 stand.py enable-live          # из ~/.config/2up/deepseek.env
python3 stand.py seed                 # 5 учёток + мок-инструменты
python3 qa_dialogues.py               # 5 параллельных браузерных сессий
python3 qa_api_chain.py               # API-цепочка без браузера
# отчёты: .state/qa/dialogues/index.html
```
