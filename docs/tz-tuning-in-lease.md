# ТЗ: тюнинг в лизе, не в бинаре — закрытие A2 (extract-once-run-forever)

## Проблема (A2, подтверждена красной командой 2026-09-14)

Сейчас авторская настройка («тюнинг» — cue-слова, адресный аппарат, priority-
таблица, look-alike) едет **вкомпилированной в бинарь** как AEAD-блоб
(`pseudex/_tuning_blob.py`), запечатанный **статическим** ключом
`PSEUDEX_TUNING_KEY`, единым для всех лиз сборки. Ключ едет открытым JSON-полем в
КАЖДОЙ лизе (`licensing/pack.py::build_plaintext` → `assets.py::load`).

Атака, воспроизведена за ~1 сек + 4 мс (`research/2026-09-14-security-redteam.md`):
клиент с root дампит память → достаёт статический ключ → расшифровывает
`_tuning_blob.BLOB` из образа **офлайн, навсегда, вне отзыва**. Ротация ключа = 30-мин
Nuitka-пересборка всего парка.

## Почему текущий дизайн строго ХУЖЕ, чем «тюнинг в лизе»

`CLAUDE.md` обосновывает вкомпиляцию так: «leased tuning was readable — a client
with root decrypts their own bundle in one step». Но ключ всё равно едет в лизе,
поэтому лизополучатель читает тюнинг И в текущем дизайне — вкомпиляция НЕ дала
секретности от лизополучателя, а лишь ДОБАВИЛА свойство extract-once-**forever**.
То есть текущий дизайн даёт то же раскрытие лизополучателю ПЛЮС вечную офлайн-копию.

## Решение

Тюнинг едет **в лизе**, как уже едет bulk (имена/улицы). В бинаре — **ничего
ценного**: ни блоба, ни статического ключа. Лиза уже age-запечатана на эфемерный
ключ процесса и nonce-wrap'нута (`bundle.py`), поэтому тюнинг в ней защищён в
канале и на диске (на диск не пишется никогда).

**Что это даёт:**
- Нет вкомпилированного блоба и статического ключа → **офлайн-расшифровки из
  образа не существует**. A2 в форме «навсегда, вне отзыва» закрыта.
- Дамп памяти даёт тюнинг ТЕКУЩЕЙ лизы (остаточная теорема — в RAM работающего
  процесса; неустранимо без железа). Он протухает с лизой; отзыв снова работает.
- Свойство «патч → нет тюнинга» СОХРАНЯЕТСЯ и усиливается: движок, не получивший
  лизу, не имеет тюнинга ВООБЩЕ (нечего расшифровывать, не «блоб под замком»).

**Остаточный риск (называем честно):** лизополучатель с root видит тюнинг своей
активной лизы в RAM. Сужается двумя следующими шагами (отдельно): короткий TTL +
непрерывное продление (окно минуты), водяной знак на клиента (атрибуция утечки).
Аппаратно закрыть (TEE) нельзя — требование «любое железо».

## Что остаётся load-bearing (не сломать)

- **Fail-closed без лизы:** `ASSETS.get()` без загруженного payload → `BundleNotLeased`
  → `/mask` 503. Движок без лизы не детектит.
- **Лиза по-прежнему age-запечатана + подписана + nonce-wrap** — канал/перенос/replay
  закрыты как раньше (эту крипту НЕ трогаем).
- **Паритет source↔compiled (P3)** — обе сборки детектят одинаково.

## Гейты и тесты (пишутся ДО логики)

**`prototype/test_tuning_lease_security.py`** (офлайн, секунды):
1. **Атака A2 больше не проходит:** `from pseudex import _tuning_blob` → ImportError;
   в `pseudex/` нет статического ключа, открывающего тюнинг; из одного образа
   (без лизы) тюнинг не восстановим.
2. **Тюнинг едет в лизе:** `build_plaintext()` декомпрессированный содержит
   priority/lookalike/адресные паттерны/cue-слова.
3. **Load-bearing:** свежий `Assets()` без `load()` → `get()` кидает `BundleNotLeased`;
   после `unload()` — тоже.
4. **Лизованный движок детектит:** `load(build_plaintext())` → детекция работает,
   те же спаны, что и раньше (регрессия).
5. **В `pseudex/` нет потребителя статического tuning-ключа** (механический grep).

**`e2e/pack_gates.py` (на собранном образе, build-time):**
- **P2 усилен:** в образе НЕТ plaintext тюнинга (как было) И НЕТ `_tuning_blob`
  модуля И НЕТ статического tuning-ключа. Позитив-контроль: имя модуля `pseudex.service`
  находится (зонд работает).
- **P11 переосмыслен:** раньше «tuning-ключа нет в метаданных образа»; теперь
  «tuning-ключа не существует как концепции» — в образе нет ни ключа, ни блоба;
  единственный источник тюнинга — лиза.
- **Новый P12 (red-team регрессия):** воспроизвести офлайн-расшифровку A2 против
  образа и утверждать, что она НЕВОЗМОЖНА (нет блоба + ключа). Мутация: если кто-то
  вернёт вкомпилированный блоб — P12 краснеет.

Каждый гейт с позитив-контролем (принцип `audit_gates.py`: гейт, который не может
покраснеть, — не гейт). Мутация-проверка: вернуть старый механизм → гейты красные.

## Проверка

1. Офлайн-тест зелёный, старый механизм (revert) → красный.
2. Полная пересборка обоих образов (Nuitka), `pack_gates.py` P1-P12 зелёные.
3. `e2e/gates.py L1-L22` — лиза/деградация/паритет не сломаны.
4. Повторить атаку A2 на стенде: офлайн-расшифровка из образа падает; дамп памяти
   даёт только тюнинг активной лизы.
5. `/code-review high` + `/security-review` в PR; личная проверка на регрессии.

## Ступень 1 — статус (2026-09-14)

Ядро (тюнинг в лизе → extract-once-forever закрыта) + рычаги сужения:

| Рычаг | Статус | Что реально даёт |
|---|---|---|
| Тюнинг в лизе, пустой бинарь | ✅ ядро | офлайн-расшифровки из образа НЕ существует; дамп даёт тюнинг одной лизы |
| Закалка памяти | ✅ `pseudex/hardening.py`, гейт L23 | `RLIMIT_CORE=0` (крэш не пишет тюнинг на диск), `PR_SET_DUMPABLE=0` (co-tenant/non-root `gcore` отвергнут — доказано: unpriv open → PermissionError), `mlockall` (тюнинг не уходит в swap — VmLck=834МБ на боевом воркере) |
| Водяной знак | ✅ `licensing/watermark.py` | утёкший из RAM тюнинг называет org (атрибуция); секрет только у сервера |
| Детекция отладчика | ✅ `hardening.tracer_pid()` | TracerPid≠0 логируется — подключён gdb/gcore к процессу с тюнингом |
| Короткий TTL | ⚠️ решение владельца | НЕ протухает извлечённые ДАННЫЕ (они статичны, работают standalone вечно). Даёт: скорость отзыва легитимного движка (TTL+grace) и — при ротации бандла — устаревание захваченной ЛИЗЫ. Держать TTL+grace НИЖЕ дрейф-потолка ГАР (сервер уже предупреждает). Не меняю прод-дефолт (24ч/48ч) молча — операционное решение |

**Остаточный риск, названный честно:** root на своём железе читает тюнинг активной
лизы из живой RAM (привилегированный дамп с CAP_SYS_PTRACE — теорема, доказано
позитив-контролем L23). Против этого без аппаратного корня доверия (TEE, требует
железа — вне «любого железа») софт бессилен. Но: «навсегда, офлайн, вне отзыва»
→ «одно окно активной лизы, с именем виновника, без диск-персистенса». Это
максимум надёжности, совместимый с on-prem на любом железе.

**Что ещё можно (не сделано, на будущее):** субтильный водяной знак (пертурбация
данных per-org, который нельзя стереть, не зная какие байты — шум), ускоренная
ротация бандла, отдельный закалённый процесс детекции.
