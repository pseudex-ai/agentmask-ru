# ТЗ: офлайн-лицензия на срок

Купленная на срок лицензия, которая работает **без единого обращения к нам**.
Альтернатива аренде — не замена: оба режима живут в одном движке и в одном
формате лицензии, отличается транспорт.

Документ отменяет решение `decisions.md` от 08.09.2026 («Офлайн-лицензии НЕТ»)
в той части, в какой оно распространялось на будущее, и объясняет, **какой факт
его отменил** (§2). Продуктовое решение о смене модели монетизации принимает
владелец — здесь она предложена и оценена, а не объявлена (§10, §17).

**Правило приёмки то же, что у `tz-license-packaging.md`:** закрывающий gate —
только e2e на реальном контейнере, с настоящим лицензионным сервером и
настоящей сборкой. Юнит-тест с подменённым `httpx` не закрывает ничего.

---

## 0. Что покупает клиент

| | Аренда (сегодня) | Офлайн-лицензия (предлагается) |
|---|---|---|
| Связь с нами | исходящий HTTPS каждые ~8 ч | **нет** |
| Срок | TTL 24 ч, продлевается | **180 или 365 дней**, предоплата |
| Что приходит | бандл, запечатанный на процесс | **тот же бандл**, запечатанный на развёртывание |
| Отзыв | секунды | **невозможен** до конца срока |
| Объём | считаем мы, кванты | **не считаем**: плоский тариф за срок |
| Истечение | 503 через 48 ч grace | 503 по календарю, 14 дней предупреждений |
| Счёт | ежемесячно, по факту | **один счёт вперёд** |

Покупатель офлайна — не «тот, кому дешевле». Это контур, у которого
**исходящий HTTPS в интернет закрыт политикой**, и таких в РФ много: госсектор,
медицина, банки, оборонка, любой заказчик с приказом ФСТЭК на периметре.
Сегодня мы им не продаём вообще ничего — `/v1/lease` для них недостижим, и
`bundle_unavailable` на холодном старте это прямо говорит (гейт L3).

## 1. Как лицензия работает сегодня

Коротко и только то, на что опирается остальное. Полностью —
`docs/tz-license-packaging.md`, `prototype/pseudex/license.py`, `bundle.py`.

```
процесс стартует
  ├─ генерирует X25519-пару В ПАМЯТИ (на диск не пишет никогда)
  ├─ POST /v1/lease {key, instance_id, process_id, pubkey, nonce, usage}
  │     сервер: may_lease(ключ, слоты, бюджет) →
  │             payload = bulk(ГАР, имена) + tuning(cue, регэкспы, приоритеты)
  │             age-печать на pubkey процесса → обёртка ключом из nonce
  │             → sha256 → Ed25519-подпись → ответ
  ├─ verify(подпись) → open_sealed → nonce_unwrap → сверка хеша → ASSETS.load()
  └─ каждые TTL/3 → продление; провал → STALE(grace 48 ч) → EXPIRED(unload)
```

Четыре свойства этой схемы — несущие, и все четыре офлайн сохраняет:

1. **Движок пуст.** Активов на диске нет: нет бандла — детектить нечем.
   Это не булева ветка, которую снимают одним NOP: снимать нечего.
2. **Подпись отвечает «кто сделал», age — «кто может открыть».** Публичный ключ
   Ed25519 вкомпилирован (`_release.LICENSE_PUBKEY`), приватного у клиента нет.
3. **Получатель под подписью.** `recipient` обязателен и сверяется; лиза,
   выписанная не нам, отвергается.
4. **Fail-closed.** Любая ошибка — 503, никогда не «пропустить без маскирования».

Что офлайн ломает: **лестница grace держится на `time.monotonic()` плюс на том,
что рестарт требует свежей лизы.** Офлайн рестарт бесплатен, значит нужен
хранимый high-water mark — первое персистентное состояние лицензии в продукте
(§7).

## 2. Почему прежнее «нет» эту лицензию не запрещает

Запись от 08.09.2026 отвергла конкретный объект:

> «офлайн-лицензия — это вшитая дата в бинарнике, то есть ровно то, что
> отвергнуто в решении про Nuitka выше (не отзывается, не продлевается иначе
> как выкаткой, откат часов помогает)».

Это верно **для объекта**. У «вшитой даты» три свойства, и все три следуют не из
слова «офлайн», а из того, **где лежат активы**:

| Возражение к «вшитой дате» | Почему оно не переносится на лицензию-аренду по файлу |
|---|---|
| проверка — булева, снимается одним NOP | активов в бинаре нет; лицензия **и есть payload**, без неё детектить нечем |
| активы уезжают в образ, пират получает продукт целиком | pack остаётся у нас; клиент получает **один бандл на одно развёртывание** |
| продление = выкатка нового бинарника | продление = **новый файл**, его выдаёт витрина, сборка не нужна |

То есть решение 08.09 было возражением против **локальной проверки как
механизма**. Этот механизм у нас уже заменён арендой активов, и замена
состоялась позже самой записи. Офлайн сегодня — свойство **транспорта**, а
транспорт никогда не был несущим.

Что остаётся верным и что придётся принять вслух, а не спрятать:

- **отзыва нет** — возвращённый или нарушивший договор клиент работает до конца
  срока (§9);
- **часы клиента — его часы** — технически закрывается не до нуля (§7, §8);
- **дрейф бандла перестаёт быть рычагом** — украденный офлайн-бандл живёт весь
  срок, а не трое суток (§9).

Остаток честный: офлайн **слабее аренды по контролю** и **сильнее неё по
охвату**. Продавать его надо там, где контроль и так недостижим, и по цене,
которая это отражает.

## 3. Ядро решения

**Офлайн-лицензия — это та же лиза, на другом транспорте и с другим
получателем.**

```
онлайн:  получатель = X25519-ключ ПРОЦЕССА, живёт в памяти, умирает с процессом
офлайн:  получатель = X25519-ключ РАЗВЁРТЫВАНИЯ, живёт в томе данных, переживает рестарт
```

Меняется ровно это — и следствия расходятся по всей схеме:

| | онлайн | офлайн |
|---|---|---|
| `ttl_seconds` | 86400 | срок лицензии (напр. 15 552 000) |
| `grace_seconds` | 172800 | окно предупреждений (14 дней), не «простой лицензиара» |
| `nonce` | анти-повтор захваченной лизы | не нужен: файл и есть артефакт, «повтор» = запустить снова |
| продление | петля в процессе | новый файл, руками или из кабинета |
| `expires_at` | выводится из `issued_at` + TTL | **абсолютный**, подписанный |
| ёмкость | кванты `/v1/meter` | нет; тариф плоский (§10) |
| отзыв | 402/403 | нет (§9) |

Совпадает всё остальное: `pack.py`, кадрирование payload, `_wm`, canary/Tardos,
`tuning_version`, подпись, `ASSETS.load/unload`, `recipient`, fail-closed.
**Нового криптографического кода нет ни строки** — только новый носитель и новые
правила времени.

## 4. Поток

### 4.1 Покупка и активация (два шага, ~2 минуты)

```
① клиент получает ps_live_… при регистрации (как сегодня)
   docker run -e PSEUDEX_LICENSE_KEY=ps_live_… -e PSEUDEX_LICENSE_MODE=offline
     ├─ файла лицензии нет → воркеры НЕ поднимаются (fail-closed, как L1/L3)
     ├─ но entrypoint держит живым ЛОКАЛЬНЫЙ ИНТЕРФЕЙС (:8081)
     └─ интерфейс показывает: «Лицензия не активирована» + КОД АКТИВАЦИИ

② клиент вставляет код в кабинете → покупает срок → скачивает license.lic
   docker cp license.lic <контейнер>:/data/  (или в том; или SECRET)
   перезапуск → /health = license: active, /mask работает
```

Почему воркеры всё-таки не поднимаются: это ровно сегодняшняя семантика
(«холодный старт grace не имеет»), и она же — то, что делает лицензию несущей.
Почему интерфейс остаётся: он **отдельный процесс** (`PSEUDEX_ROLE=ui`) и уже
спроектирован так, чтобы переживать мёртвый движок и говорить «движок не
отвечает». Экран активации — его прямое расширение, а не новый механизм.

Код активации печатается ещё и в лог и доступен ролью `PSEUDEX_ROLE=activate`
(одноразовая, как `probe`/`preflight`) — для тех, кто ставит без браузера.

### 4.2 Продление

Тот же код активации (ключ развёртывания не меняется → он персистентный), новый
срок. Файл подкладывается, движок подхватывает **без рестарта** (петля проверяет
файл раз в минуту и перезагружает бандл, если `license_id` сменился).

Накопление: новый срок считается **от `expires_at` прежнего файла, если тот ещё
не истёк**, иначе от момента оплаты. Правило считает **наша сторона** — см. §8,
это и есть то, что обнуляет выгоду от перевода часов.

### 4.3 Контур без интернета вообще

Кабинет доступен человеку снаружи; машина — нет. Значит:

- код активации переносится **текстом** (base32, ~300–400 символов: почта, чат
  поддержки, флешка);
- файл лицензии — ~2.7 МБ (2 МБ бандла в base64 + армор). Переносится как файл;
- если и это недоступно — `pseudexctl license export/import` для переноса
  файла, и всё.

## 5. Форматы

### 5.1 Код активации

```jsonc
// base32(json), с армором для переноса
{
  "v": 1,
  "kind": "activation",
  "key_hash": "…",                         // sha256(ps_live_…) — как licensing/store.hash_key

  "deployment": "age1…",                   // X25519-ключ развёртывания, публичный
  "host": "erp-prod-01",                   // для человека, не для проверки
  "engine_version": "1.0.0",
  "requested_at": 1786000000,              // часы клиента, недоверенные
  "usage_since": null                      // см. §10, при продлении — агрегаты
}
```

Код **не подписан и не должен быть**: он ничего не удостоверяет и ни к чему не
даёт доступа. Подписывать его значило бы завести ещё одну проверяемую сущность
на стороне клиента — то есть ровно то, что §2 отвергает.

### 5.2 Файл лицензии

Тот же конверт, что у лизы, — чтобы `verify_lease`/`signing_payload` работали
**без изменений**:

```jsonc
{
  "kind": "offline",
  "license_id": "ol_…",
  "org_id": "acme",
  "key_hash": "…",                  // сверяется с PSEUDEX_LICENSE_KEY
  "recipient": "age1…",             // ключ РАЗВЁРТЫВАНИЯ, под подписью
  "plan": "standard",
  "issued_at": 1786000000,
  "not_before": 1786000000,
  "expires_at": 1801600000,          // абсолютный срок, под подписью
  "term_days": 180,
  "bundle_version": "2026-09-18.1",
  "tuning_version": "…",
  "bundle_sha256": "…",
  "bundle": "base64(age(frame_payload(...)))",
  "signature": "base64(ed25519)"     // над всем, кроме bundle
}
```

Армор `-----BEGIN PSEUDEX LICENSE-----` поверх JSON — чтобы файл переживал почту,
мессенджер и копипаст. Формат разбирается тем же `bundle.py`.

**Почему бандл внутри файла, а не рядом.** Альтернатива — маленький файл плюс
бандл, зашифрованный общим ключом релиза, — разваливает несущее свойство:
один клиент, вынувший ключ релиза (а он у него будет в RAM), расшаривает
*расшифровку* вместе с публично скачанным бандлом, и защита от
перераспространения исчезает целиком. Печать на ключ развёртывания — это то,
что делает файл неработающим на чужой машине.

**`nonce`-обёртка офлайн не применяется.** Её единственная роль — «повтор
захваченной сетевой лизы не расшифруется». Файл не перехватывают, его
устанавливают; ветка, которую она защищала, не существует. Оставить её значило
бы держать в файле ключ рядом с замком.

## 6. К чему привязана лицензия

**К ключу развёртывания, а не к железу.**

`<DATA_DIR>/deployment.key` — X25519-identity, генерируется на первом старте,
живёт в томе данных клиента, переживает рестарт и пересоздание контейнера.

Что это даёт:

- **копия файла на другой машине не работает** — там свой том, свой ключ;
- переустановка контейнера, смена хоста, миграция VM, замена железа — **работают
  без перевыпуска** (том переехал — ключ переехал);
- MAC-адрес, hostname, серийник диска, `machine-id` не участвуют, поэтому
  смена сетевой карты не превращается в тикет в поддержку;
- N воркеров внутри контейнера открывают один и тот же файл своим общим ключом
  (сегодня каждый воркер держит свои 2 МБ бандла — здесь ровно то же).

Что это **не** даёт — и должно быть сказано клиенту прямым текстом:

- **клон тома = клон лицензии.** Кто скопировал весь том, тот скопировал и ключ.
  Это осознанно: том и так содержит карту подмен (реальные значения клиента), и
  «унести том к соседу» — это уже другая проблема, не лицензионная;
- root внутри контейнера видит ключ. Как и весь бандл, что уже принято
  (`tz-license-packaging.md` §3.4).

**Отвергнуто: привязка к железу** (MAC/серийник/`machine-id`). Это ровно тот
механизм, который `decisions.md` 20.08 отверг у PyArmor как более слабый: он
ломается на каждой замене железа и ничего не добавляет к тому, что даёт ключ
развёртывания. Для отдельного «строгого» тарифа его можно добавить вторым
сигналом — но не по умолчанию (§13).

**Число развёртываний.** Тариф офлайна продаётся **на узел**. Много узлов — либо
N кодов активации, либо один файл на несколько получателей (age умеет список
recipient'ов: открыть сможет любой названный, неназванный — нет). Наша сторона
знает, сколько ключей названо: это и есть потолок инстансов, честно посчитанный
**при выдаче**, а не в чужом контуре.

## 7. Часы: три источника и правило `max()`

Офлайн-срок — это интервал по настенным часам, а настенные часы принадлежат
лицензиату. Закрыть это «до нуля» нельзя ни на каком железе, кроме TPM (§13).
Что можно — сделать перевод часов **бесполезным**, а не «запрещённым».

**Правило одно — и оно асимметрично:**

```
mark' = max( mark, mark + (monotonic_now − monotonic_at_mark) )   // время идёт, пока процесс жив
mark' = max( mark', wall_clock )  ТОЛЬКО если wall подтверждён (см. ниже)

effective_now = max( wall_clock, mark', external_lower_bound )
истекла ⟺ effective_now ≥ expires_at
```

**Пока процесс работает, время идёт независимо от настенных часов** — его несёт
`monotonic`, который не зависит от системного времени вовсе. Замороженные часы
на работающем контейнере не дают ничего: `mark` растёт сам.

Отсюда точная формулировка того, что вообще эксплуатируемо: **остановить
контейнер, перевести часы назад, восстановить файл `license.clock` из копии,
запустить** — и так на каждом рестарте. Это уже не «перевёл часы», а осознанная
правка состояния лицензии, и ровно она закрывается договором и правом аудита
(§12).

**Назад — никогда, вперёд — только по подтверждению.** Принимать скачок стенных
часов вперёд сразу нельзя: сдохшая батарейка RTC, показавшая 2030, отравила бы
`mark` навсегда и убила оплаченную лицензию. Поэтому скачок вперёд принимается
только если он **устойчив** (наблюдается на нескольких проверках подряд, а не
один раз) — за это время настоящие часы, ушедшие вперёд по-настоящему (машина
месяц стояла выключенной), подтвердятся, а глюк — нет. Скачок назад не
принимается никогда и ни в каком виде.

**High-water mark** — `<DATA_DIR>/license.clock`, пишется атомарно (tmp+rename),
не чаще раза в 5 минут, HMAC ключом из ключа развёртывания, и **дублируется в
волте**. Расхождение двух копий → берётся большая, пишется ERROR. Это первое
персистентное состояние лицензии в продукте; оно не секрет и не должно им быть —
оно должно быть **неудобным для правки**: две копии + HMAC превращают
«поправил файл» из однострочника в разбор формата на каждом рестарте.

**Внешняя нижняя граница** берётся бесплатно там, где она есть:

| Форма развёртывания | Откуда время |
|---|---|
| `proxy.py` (мы ходим в провайдера) | заголовок `Date` ответа апстрима — TLS уже проверен, хост уже доверенный |
| `service.py` (сайдкар, но сеть есть) | `Date` с нашего же `/v1/attest` (§9), HTTPS |
| сайдкар без сети / air-gap | **недоступно** — остаются только wall + mark |

Важно: внешнее время используется **только как нижняя граница**. Часы, ушедшие
вперёд, никогда не истекают лицензию досрочно — иначе падение NTP-сервера
останавливало бы оплаченный продукт, то есть ровно то, против чего заведён grace.

**Честный остаток:** то, что остаётся, — это не «перевёл часы», а **остановил
контейнер, перевёл часы назад, восстановил `license.clock` из копии и запустил**,
и повторять это на каждом рестарте. Внешнее время (когда оно есть) закрывает и
это; в чистом air-gap оно не закрывается ничем, кроме TPM. Это свойство задачи, а
не дыра в реализации (Keygen называет это «what they say goes»,
`billing-integrity.md` §Промышленный контекст). Закрывается договором, правом
аудита и тем, что **следующие** §8 не дают накопить обман.

## 8. Почему обман часов не окупается на продлении

Единственное место, где у нас честные часы, — **наша сторона**. И продление
через неё проходит всегда, даже у самого закрытого контура (иначе он не купил
бы срок).

Правило на выдаче:

```
new_expires_at = max(issued_now, previous_expires_at) + term
```

- клиент вернул часы на год назад и просит продление «с 2026-01-01» — мы считаем
  от **прежнего `expires_at`**, который лежит у нас в БД, и он ничего не
  выигрывает;
- клиент просит продление за месяц до конца — срок **прибавляется**, а не
  заменяется: ранняя оплата не наказывается;
- клиент не продлевает вообще — он и не платит, вопрос закрыт.

Отсюда точная граница того, что даёт перевод часов: **не больше одного срока и
только внутри одного файла**. Клиент, который платит, от обмана часов не
выигрывает ничего. Клиент, который не платит, выигрывает один срок, и это цена
входа в офлайн — она закладывается в цену (§10).

Если часы отстают (реальный и частый случай: севший CMOS, сбитый NTP в закрытом
контуре), продукт ведёт себя **как оплачено**: `effective_now` упирается в mark и
в подписанный `issued_at`, поэтому лицензия не истекает раньше срока. Ложных
остановок нет — это важнее, чем поймать одного жулика.

## 9. Отзыв, обновления, атрибуция

### 9.1 Отзыв

Отозвать офлайн-лицензию нельзя. Что делается вместо:

1. **Срок — рычаг.** 180 дней — это максимум, который потерян при худшем
   сценарии (возврат платежа, расторжение). Поэтому 6 месяцев, а не «навсегда».
2. **Необязательный check-in.** Если у контура **есть** сеть хоть иногда, движок
   раз в сутки делает `POST /v1/attest {license_id, key_hash}` — 200 байт, ответ
   `{status: active|suspended|revoked, server_time}`. `revoked` → `EXPIRED`
   немедленно. Нет сети → молча продолжаем на срок. Это не «скрытая аренда»:
   адрес можно переопределить и **выключить** (`PSEUDEX_LICENSE_ATTEST=off`), и
   выключенный режим ничего не теряет по сравнению с полным офлайном.
3. **Единица учёта — узел.** Отзыв «одного узла» не нужен: узел — это файл,
   который клиент и так может не устанавливать.

### 9.2 Обновления бандла внутри срока

Офлайн-бандл мёрзнет на весь срок: улицы ГАР ротируются дважды в неделю, а
уличный словарь у офлайн-клиента — сентябрьский. Это **не регрессия**, а
следствие офлайна, и его надо продавать как есть: «обновление словарей — раз в
квартал, файлом, в ваше окно обслуживания».

Механика бесплатная: тот же ключ развёртывания → новый файл с тем же
`expires_at`, но свежим `bundle_version`. Стоит мне одну кнопку в кабинете и
ноль новых механизмов.

### 9.3 Атрибуция — уже есть и работает офлайн

`canary.py`, `fingerprint.py` (Tardos), `watermark.py` — **серверные**, и
`pack.py` вшивает метки в тот же payload, что уезжает в офлайн-файле. Значит
утекший офлайн-бандл, в отличие от «вшитой даты», **называется по имени**: у
каждой организации свои канареечные записи и свой Tardos-код, а `identify()`
находит организацию по маркеру. Набор ненастоящих слов, вшитый в словарь, не
обнаружим без секрета и переживает `lower()`.

Это и есть ответ на «дрейф перестал быть рычагом»: рычаг заменён на
**атрибуцию**. Дрейф делал пиратство гонкой; атрибуция делает его подписанным
актом. Разные механизмы, одна цель — и второй офлайн работает, а первый нет.

## 10. Ёмкость и деньги

**Офлайн продаётся плоским тарифом за срок, без метра.** Это не упрощение
реализации, а следствие: `/v1/meter` офлайн невозможен, а локальный счётчик
клиент правит (это уже честно записано в `billing-integrity.md`: «расход,
посчитанный на машине клиента, неподделываем не бывает»).

Что это меняет в деньгах:

| | аренда | офлайн |
|---|---|---|
| выручка | абонплата + объём | **предоплата за срок** |
| счёт | ежемесячно | **один, вперёд** |
| касса/ККТ | не нужна (безнал, юрлица) | так же |
| возвраты | пропорционально | нет: срок не возвращается |
| риск «тяжёлого» клиента | перерасход | **заложен в цену тарифа** |

Цена офлайна = (абонплата × срок) × коэффициент офлайна, где коэффициент
покрывает: отсутствие метра, отсутствие отзыва, отсутствие дрейфа. Ориентир для
владельца: **1.3–1.6** к аренде за тот же срок; скидка за 12 месяцев — уже
существующий `annual_discount_pct` в `Plan`.

**Телеметрия едет в следующем коде активации.** При продлении контейнер
прикладывает `usage_since` (те же агрегаты `audit.counts()`, без ПД) — не как
обязанность и не как основание счёта, а как:
- наш единственный источник продуктовой аналитики по офлайн-сегменту;
- аргумент в разговоре о цене продления;
- **датированное свидетельство** того, что делал клиент, — по той же логике, что
  `build_measurement()` внутри подписанного отчёта.

Отсутствие поля ничего не блокирует: клиент, который никогда не продлится, его и
не пришлёт.

## 11. Лестница деградации офлайн

```
BOOT ──нет файла──▶ UNACTIVATED   /mask 503, UI показывает код активации
  │
  └──файл есть──▶ ACTIVE ──T-30/T-7/T-1──▶ WARNING (работает)
                    │
                    └──expires_at──▶ EXPIRED  ASSETS.unload(), /mask 503
```

| Состояние | `/mask` | `/unmask`, `/reveal` | UI |
|---|---|---|---|
| `UNACTIVATED` | 503 | 503 (нечем) | код активации + ссылка на кабинет |
| `ACTIVE` | работает | работают | «до 12.03.2027, 176 дней» |
| `WARNING` (<30 дней) | работает | работают | баннер + остаток дней |
| `EXPIRED` | 503 | **работают** | «лицензия истекла, продлите» |

Два решения, оба взяты у аренды и оба несущие:

- **`/unmask` и `/reveal` работают после истечения.** Они читают волт клиента,
  то есть его же данные по его же токенам. Держать их в заложниках вредно при
  продаже, а рычаг не слабеет: без `/mask` fail-closed шлюз не может отправить
  запрос в модель вообще (`tz-license-packaging.md` §2.5).
- **`ASSETS.unload()`, а не флаг.** «Отключить проверку» не должно быть правкой
  одного `if` — данных в памяти просто нет.

Предупреждения идут **в интерфейс** (человек их увидит) и в лог; письма — на
почту администратора из кабинета (витрина знает срок и умеет планировщик).

## 12. Модель угроз: что меняется

| Вектор | Аренда | Офлайн | Чем держится офлайн |
|---|---|---|---|
| Снять проверку лицензии в бинаре | детектить нечем: бандла нет | **так же** | payload приходит только в файле, запечатанном на ключ узла |
| Скопировать лицензию на другую машину | бесполезна (ключ процесса) | бесполезна (ключ узла) | age-печать на `recipient` |
| Скопировать **том** | — | лицензия переезжает | принято: том = карта ПД клиента |
| Опубликовать бандл | протухает ≤ 3 суток | живёт весь срок | **атрибуция**: canary + Tardos + `_wm` называют организацию |
| Откатить часы | не помогает (monotonic + рестарт требует лизы) | не помогает внутри срока | `max(wall, mark, external)`; на продлении — `max` на нашей стороне |
| Air-gap: стоп + откат часов + восстановление `license.clock` | н/п | **продлевается** | договор + право аудита + §8; технически не закрывается ничем, кроме TPM |
| Отозвать ключ | секунды | **невозможно** | срок 180 дней + необязательный `/v1/attest` |
| Занизить объём | учёт по нашей выдаче | **не считается** | плоский тариф: занижать нечего |
| Патч релизного бинарника | окно = TTL | окно = весь срок | `build_measurement()` в отчёте при продлении — датированный факт |
| Наша недоступность | grace 48 ч | **не влияет** | офлайн и есть ответ на этот вектор |

Сводка: офлайн **строго слабее** по отзыву, метру и дрейфу и **строго сильнее**
по независимости от нас. Первое — цена, второе — товар.

## 13. Отвергнутые альтернативы

| Вариант | Почему нет |
|---|---|
| **Вшитая дата в бинарник** | объект решения 08.09: булева проверка, активы в образе, продление = выкатка |
| **Маленький файл + публичный бандл под ключом релиза** | один вынутый ключ релиза расшаривает расшифровку всем: защита от перераспространения исчезает |
| **Файл без привязки к узлу** (подписан, срок есть, ставь куда хочешь) | одна покупка → неограниченное размножение; это и есть «вшитая дата», только в файле |
| **Привязка к железу** (MAC/диск/`machine-id`) | ломается на замене железа и VM-миграции; отвергнута у PyArmor как более слабая (decisions 20.08) |
| **TPM/secure element, монотонный счётчик** | технически честный ответ на часы; требует TPM 2.0 и доступа контейнера к `/dev/tpm*`. Держим как **опциональный строгий тариф**, не как умолчание — та же логика, по которой отвергнут confidential computing |
| **Perpetual fallback** («истёк срок — работай на последнем бандле») | превращает 6-месячную лицензию в вечную. Если продавать — отдельным SKU по цене perpetual, а не как уступку |
| **Просто увеличить grace с 48 ч до 30 суток** | отвечает на «ваш сервер падал неделю», а не на «у нас закрыт исходящий HTTPS». Дёшево и стоит сделать отдельно — но это не офлайн |
| **Локальный прокси лицензий в контуре клиента** | всё ещё требует нас и всё ещё требует сети |
| **Офлайн-счётчик запросов с локальным кэпом** | неисполним (клиент правит), а честного клиента наказывает |
| **Свой формат лицензии** | у нас уже есть age + Ed25519 + кадрирование; новый формат = новая поверхность для ошибок |

## 16. Что этот режим НЕ делает

- **Не отзывает** лицензию до конца срока.
- **Не считает объём** — и не должен: метр офлайн либо правится, либо врёт.
- **Не обновляет словари** без действия человека.
- **Не закрывает** откат часов в air-gap с root'ом — это признано, а не забыто.
- **Не заменяет** аренду: у кого есть сеть, тому аренда дешевле и безопаснее для
  нас. Офлайн — вход в сегмент, который сегодня не покупает ничего.
