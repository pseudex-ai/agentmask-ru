# Инцидент на нашей стороне

## Сколько у тебя времени

**Двое суток и сутки сверху.** Аренда живёт сутки, grace — ещё двое. Клиент,
чей контейнер уже работает, переживёт наш полный простой трое суток и ничего не
заметит. Это не повод не спешить, но повод не паниковать и не чинить наспех.

**Чего grace НЕ покрывает:** холодный старт. Контейнер, который перезапустился
во время нашего простоя, лиз не получит и не поднимется вовсе. Значит первым
делом — поднять сервер лицензий, а не витрину.

## Первый круг, три команды

```bash
docker compose -f deploy/compose.yml ps          # кто нездоров
systemctl status pseudex-agent                   # чем кончилась выкатка
df -h /                                          # место
```

Место — единственный отказ, который останавливает **всех** клиентов сразу:
без него сервер лицензий не пишет аренду.

## Что означает каждая тревога

**«Диск заполнен»** — крит. `docker system df`, старые образы, `deploy/backups`.
Агент сам чистит образы старше недели, но бэкапы копятся 30 дней по замыслу.

**«Бэкап старше 25 часов»** — крит, и не про сегодня. База лицензий
единственная, чего не пересобрать из кода: потеряешь — встанут все развёртывания
в поле, и никакой код этого не вернёт.

**«Сервисы нездоровы»** — крит. Логи **не пересылаются в канал**: там ПД
клиентов. Смотреть на машине.

**«Лицензионный сервер не отвечает»** — крит, но время есть, см. выше.

**«Не продлевают аренду больше суток»** — **warn, и это не наша поломка**.
Ломается у клиента. Единственный пункт, который стоит превращать в письмо
клиенту **до** того, как он позвонит.

**«Сертификат истекает»** — warn. Caddy продлевает сам; если счётчик не растёт,
продление молча не работает.

**«Снаружи не отвечает» (из GitHub Actions), а сторож молчит** — это машина или
сеть, а не сервис. Сторож молчит, потому что он умер вместе с ней.

## Выкатка сломала прод

Агент откатывается сам и присылает «Откат на vX выполнен». Если он этого не
сделал:

```bash
echo "PSEUDEX_PIN=v<прежняя>" >> deploy/.env    # заморозить, выключить автовыкатку
cd deploy && git checkout v<прежняя> && VERSION=<прежняя> docker compose up -d
```

`PSEUDEX_PIN` нужен именно затем, чтобы разбираться, не воюя с агентом, который
раз в минуту возвращает «правильную» версию.

## «Подпись не сошлась» — не снимай проверку

Агент отказался выкатывать и **ничего не остановил**: работает прежняя версия.
Варианта три: это не наш образ, скомпрометирован реестр, или
`COSIGN_IDENTITY_REGEXP` сужен под другой репозиторий. Разберись, откуда взялся
образ. Реестр не доверенная сторона — подпись существует ровно затем.

## Восстановление

```bash
# витрина
docker compose exec -T postgres pg_restore -U pseudex -d pseudex --clean \
  < deploy/backups/storefront-<stamp>.dump

# лицензии — тот отказ, ради которого всё это существует
docker compose stop license
docker cp deploy/backups/license-<stamp>.db pseudex-license-1:/data/license.db
docker compose start license
```

Потом проверить, что живой клиентский ключ продлевается: `/admin/list` показывает
организации, а не пустой список.

Учения идут сами раз в неделю и проверяют не «файл читается», а **непустые
таблицы**: оборванный дамп читается прекрасно, разворачивается в пустоту и
проверку свежести проходит.

## Чего у нас нет и не должно быть

**Обратного канала к клиенту.** Связь односторонняя: его контейнер звонит нам.
Это не удобство, а то, что делает нас необработчиком — у нас физически нет
способа дотянуться до его данных. Если инцидент требует «зайти к клиенту» —
значит диагноз неверный.

**Его тома в наших бэкапах.** `pseudex-data` — его контур и его данные.
Инструкция по копии выдана ему в шаге 7 онбординга.
