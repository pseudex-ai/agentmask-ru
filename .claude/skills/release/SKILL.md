# Выкатка версии

Одна команда, дальше без человека:

```bash
git tag v1.0.1 && git push --tags
```

Всё остальное в этом файле — про то, что должно быть верно **до** неё, и что
делать, когда что-то пошло не так.

## До тега: две вещи вшиваются в образ и меняются только пересборкой

**Ключ подписи.** Проверочный ключ компилируется внутрь бинарника Nuitka.
Другой ключ = полная пересборка и другой дайджест. Он должен быть окончательным
до первой публикации.

**Адрес сервера лицензий.** Клиенты внесут его в белые списки. Смена = ручная
переконфигурация всех развёрнутых контейнеров в поле.

Ни то ни другое не «настройка» — это одноразовые решения. Проверь `deploy/.env`
и `PSEUDEX_LICENSE_URL` витрины прежде, чем ставить тег.

## Что делает CI (`release.yml`)

Порядок обратный обычному, и это намеренно:

1. тесты движка и витрины;
2. **гейты против настоящих контейнеров** — P1–P8 и L1–L20 на скомпилированном
   образе;
3. только после зелёных гейтов — публикация и подпись **трёх** образов:
   клиентского, лицензионного и витрины.

**Подписывается дайджест, не тег.** Тег изменяем, подпись над ним ничего не
говорит о байтах, которые скачает клиент. «Подписано» здесь означает
«доказано», а не «собралось».

Наши два образа собираются **в CI, а не на хосте**. Сборка на боевой машине
означала бы, что ничто нигде не доказывает: крутится то, что прошло гейты.

## Что делает хост (`deploy/agent.sh`, таймер systemd, раз в минуту)

1. новый тег `v*`?
2. **`cosign verify` каждого образа — ДО того, как что-либо остановлено.**
   Не сошлась подпись → не выкатываем и кричим. Реестр не доверенная сторона;
   подпись существует ровно затем, чтобы его таковым не считать;
3. `compose pull` + `up -d`;
4. **ждёт здоровья и откатывается сам**, если сервисы не поднялись.

Пункт 4 — разница между «автономно» и «автоматически». Автоматическое умеет
только ломать быстрее.

Источник правды — тег в git, из него же берётся `compose.yml`: описание стенда
и версии образов переезжают одним движением и не могут разъехаться.

## Когда что-то пошло не так

**Заморозить.** `PSEUDEX_PIN=v1.0.0` в `deploy/.env` закрепляет версию и
выключает автовыкатку. Нужно ровно тогда, когда надо подумать, не воюя с
агентом, который упорно возвращает «правильную» версию.

**Посмотреть, чем кончилась последняя выкатка:**

```bash
systemctl status pseudex-agent
journalctl -u pseudex-agent -n 50
```

**Агент молчит.** Проверь по порядку: таймер включён (`systemctl list-timers`),
тег запушен (`git ls-remote --tags`), `.env` читается юнитом.

**Подпись не сошлась.** Не снимай проверку. Это либо не наш образ, либо реестр,
либо `COSIGN_IDENTITY_REGEXP` сужен под другой репозиторий. Разберись, откуда
взялся образ.

## Проверить глазами клиента

Он проверяет так, и мы должны уметь это повторить:

```bash
cosign verify cr.yandex/pseudex/pseudex:1.0.1 \
  --certificate-identity-regexp '.*' --certificate-oidc-issuer-regexp '.*'
```

## Локально прогнать то же, что CI

```bash
cd prototype
python3 e2e/pack_gates.py                                  # P1-P8, собирает оба образа
PSEUDEX_SIGNING_KEY=<ключ> python3 e2e/gates.py --image pseudex:compiled --skip-build
```

Ключ передаётся, чтобы не пересобирать Nuitka заново: он вкомпилирован в
бинарник, и свежий ключ форсирует полную пересборку.

## Чего НЕ делать

- **Не выкатывать по пушу в ветку.** У нас релиз по тегу с гейтами; «выкатилось
  само» в продукте, где отказ останавливает чужих агентов, — не то место для
  экономии двух минут.
- **Не собирать образы на хосте.** Это было и убрано: сборка там отличается от
  сборки в CI по десятку скучных причин, и разница всплывает как
  невоспроизводимый баг.
- **Не подписывать до гейтов.** Подпись — утверждение о доказанности.
