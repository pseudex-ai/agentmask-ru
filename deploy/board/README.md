# Доска команды — локальный стенд

Наша сборка Vikunja за дверью Authelia, на скрытом пути. Здесь можно посмотреть,
как это выглядит и работает, ничего не трогая в проде.

```bash
cd deploy/board
./up.sh                      # генерирует секреты, собирает фронтенд, поднимает
```

Открыть: **https://board.lvh.me:8443/ops-7f3a/**
Логины: `igor`, `gosha`, `ops` · пароль: `pseudex` (меняется `BOARD_PASSWORD=... ./up.sh`)

`lvh.me` — публичный домен, который резолвится в `127.0.0.1`. Он нужен, чтобы
браузер и контейнеры видели провайдера идентичности по одному адресу: без этого
OIDC требует правки `/etc/hosts` и TLS. На проде вместо него — настоящий поддомен.

## Что здесь смотреть

1. **Скрытый путь.** Откройте https://board.lvh.me:8443/ — ответ 404, а не форма
   входа. Посторонний не узнаёт, что здесь что-то есть; так же спрятана админка
   витрины (`PSEUDEX_ADMIN_PATH`).
2. **Дверь.** https://board.lvh.me:8443/ops-7f3a/ перекидывает на портал Authelia.
   Пароль → и только потом что-либо отдаётся.
3. **SSO.** Внутри доски нет своего входа: `VIKUNJA_AUTH_LOCAL_ENABLED=false`, и
   пользователь приходит от Authelia по OIDC. Учётка одна на все инструменты.
4. **Бренд.** Логотип, палитра, шрифты (Inter + JetBrains Mono) и имя продукта —
   наши, из `storefront/static` и `brand/logo`, без чужих CDN.

## Как устроено

```
браузер ──► Caddy :8080 ──┬─ forward_auth ──► Authelia :9091  (кто ты)
                          ├─ /ops-7f3a/api/*  ──► Vikunja :3456 (Go, SQLite)
                          └─ /ops-7f3a/*      ──► nginx: наша сборка фронтенда
```

| файл | что |
|---|---|
| `docker-compose.yml` | четыре сервиса: caddy, authelia, vikunja, frontend |
| `caddy/Caddyfile` | скрытый префикс, `forward_auth`, 404 на всё остальное |
| `authelia/configuration.yml` | ШАБЛОН: дверь, SSO, OIDC-провайдер, секреты — плейсхолдерами |
| `authelia/users.yml` | создаётся `up.sh` (argon2id), в гит не едет |
| `Dockerfile.frontend` | апстрим Vikunja + наш патч → статика |
| `patches/pseudex-brand.patch` | тема, шрифты, логотип, имя — весь бренд одним diff |
| `assets/icons/` | наши favicon и иконки |

## Бренд

Единственное место, где меняется внешний вид — `patches/pseudex-brand.patch`.
Палитра и метрики в нём — те же токены, что у сайта и локального интерфейса
(`storefront/static/site.css`): фон `#17171a`, панели `#1c1c20`, границы
`#2b2b31`, акцент `#b3a0ea`, прямые углы, моноширинный интерфейс.

Правится так:

```bash
# 1. клонировать апстрим на закреплённом коммите
# 2. править frontend/src/styles/pseudex-brand.scss
# 3. пересобрать и перегенерировать патч
cd board && ./up.sh
```

Патч применяется `git apply`: обновление апстрима, изменившее те же строки,
ломает сборку громко, а не тихо возвращает чужой вид.

## Что на проде будет иначе

| стенд | прод |
|---|---|
| `https://board.lvh.me:8443` | `https://board.pseudex.ru` + сертификат Caddy |
| `policy: one_factor` | `two_factor` — TOTP у каждого, как в Django-админке |
| пароль общий, `pseudex` | у каждого свой; заводится в `authelia/users.yml` |
| `lvh.me` | реальный домен, без правки `/etc/hosts` |
| SQLite в томе | тот же SQLite + файл в `deploy/backup.sh` |

## Про 2FA, который уже есть в Django

Он остаётся на месте и не конфликтует. `django-otp` защищает кабинет клиента и
админку витрины — это контур, который смотрит в интернет. Authelia берёт на себя
наши внутренние инструменты: доску, Grafana, всё следующее. Свести оба в один
слой значило бы строить IdP внутри публичного приложения; разнести — это то, что
здесь и сделано.

## Telegram

Опционально и отдельным шагом: у Vikunja есть [вебхуки](https://vikunja.io/help/webhooks/)
на создание, закрытие и назначение задачи. Приёмник вебхука → наш бот → сообщение
в командный чат. Инфраструктура ботов у нас уже есть (`deploy/notify.sh`, боты
ops и поддержки), так что это ~50 строк, а не новый сервис.
