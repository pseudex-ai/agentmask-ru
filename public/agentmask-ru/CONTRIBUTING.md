# Как добавить случай

**Единица вклада — один файл** `cases/<семья>/<id>.json`. Не набор, не семья: файл.
Так устроены бенчмарки, у которых есть контрибьюторы (lm-eval-harness — 460, MTEB — 344),
и так НЕ устроены те, у которых их полтора десятка.

## Что проверит CI

`agentmask gates` прогонится на изменённых случаях и потребует:

1. схему (`schema/case.schema.json`) и офсеты: `content[start:end]` обязан равняться `value`;
2. хотя бы один негатив — значение, похожее на персональные данные и таковым не являющееся;
3. `canary`, `license`, `created_at`, `source` — на месте;
4. `expected_call.name` есть среди `tools`, а каждый его `pii_params` кем-то из `pii` питается;
5. **passthrough проходит случай**: маскировщик, который ничего не меняет, обязан доставить
   каноническое значение. Если не доставляет — неверен случай;
6. **наивный regex оставляет след** — или случай несёт `hard.why` с объяснением, почему
   не может (строчное имя без подсказки, буква-двойник внутри цифр).

## Правила эталона

- **Эталон — каноническая форма того, ЧТО НАПИСАНО.** Сообщение без отчества не требует
  отчества обратно.
- **Офсеты считаются при сборке**, а не поиском по готовой строке: поиск найдёт первое
  вхождение, и сообщение с двумя одинаковыми телефонами получит неверный спан.
- **Ярус имени обязателен** (`common` / `tail` / `diminutive` / `foreign`) и не выдумывается:
  он определяется тем, из какого пула взято имя.
- **Никаких настоящих людей.** Значения — из пулов `pools/`; телефоны — из резервных
  кодов DEF.

## Очки и соавторство

| вклад | очки |
|---|---|
| новый случай | 1 |
| первый случай в новой страте (регистр × тип × семья инструментов) | +2 |
| ревью чужого PR | 1 |
| найденный и починенный дефект скорера | 2–10 |
| прогон системы с полными наблюдениями | 1 |

Очки пишутся в `points/<номер PR>.jsonl` (по файлу на PR — так они не конфликтуют при
слиянии). Порог соавторства в статье — **8 очков**. Ревью оплачивается наравне с вкладом:
в MMTEB у держателя первого места больше половины очков — за ревью, и именно это не дало
очереди PR встать.

Список контрибьюторов в README обновляется из реестра и ПЕРЕЖИВАЕТ статью: бенчмарк, где
после публикации нечего заработать, умирает — так закончился BIG-bench.

## Прогон своей системы — ЛОКАЛЬНО, число публикуете вы, не репозиторий

```sh
agentmask run --adapter openai_proxy --name моя-система \
    --base-url http://localhost:8080/v1 --upstream-bind 0.0.0.0:8099 \
    --out results/ --submitted-by "кто прислал" --notes "версия, конфигурация, образ"
agentmask leaderboard          # таблица собирается у вас на машине
```

`results/` и `leaderboard.md` — в `.gitignore` и в PR не принимаются: измерение
чужого продукта публикует тот, кто его сделал, в своём тексте с методологией, а
не репозиторий как «официальный рейтинг» (у некоторых это ещё и против условий
использования). Вклад сюда — это СЛУЧАИ (данные), не числа. Прогон карается
воспроизводимостью: пообъектные наблюдения в файле дают пересчитать строки
любой арифметикой — но у себя.
