# AgentMask-RU

**Ломает ли шлюз маскирования персональных данных работу LLM-агента с инструментами?**

Бенчмарк и харнесс для ЛЮБОГО маскировщика. Русский язык, 272 случая, 680 значений
персональных данных, 624 негатива. Код — Apache-2.0, корпус — CC BY 4.0.

```sh
pip install agentmask-ru
agentmask run --adapter placeholder_regex          # эталон «регулярки за вечер»
agentmask run --adapter openai_proxy --name мой-шлюз \
    --base-url http://localhost:8080/v1 --upstream-bind 0.0.0.0:8099
```

## Зачем

Маскировать текст умеют многие. Но агент ВЫЗЫВАЕТ ИНСТРУМЕНТЫ, а инструменту нужно
настоящее значение: `create_order(phone="+7 907 …")` не найдёт заказ по подстановке.
Значит шлюз обязан вернуть настоящее значение в аргумент — и не сломать при этом
ничего остального. Ни один существующий бенчмарк этого не измеряет:

| что есть | чего не хватает |
|---|---|
| NER-корпуса (NEREL, WikiANN-ru) | новостная проза, инструментов нет; разметка отвечает «сущность ли это», а не «чьи это данные» |
| корпуса маскирования ПД (ai4privacy, hivetrace/pii-bench) | нет вызовов инструментов; лицензия ai4privacy — только академическая |
| бенчмарки вызова инструментов (BFCL, τ-bench, GorillaHard в MERA) | нужная форма, но без персональных данных |

Пересечение — русские разговорные персональные данные, проходящие через схемы
инструментов, которые их потребляют — не покрыто ничем.

## Восемь строк, которые не складываются

| строка | что значит |
|---|---|
| `скрыто` (leak) | значение изменено до того, как его увидела модель |
| `скрыто целиком` (coverage) | ни один КУСОК настоящего значения не дожил до модели |
| `тип` (typed) | тип определён верно — только если маскировщик отдаёт спаны |
| `круг из скрытых` (round_trip) | инструмент получил настоящее значение (из тех, что были скрыты) |
| `круг из всех` (end_to_end) | то же по всем значениям — «агент не сломан» |
| `не тронуто лишнего` (overmask) | номер заказа, трек, сумма, дата документа, голый город не тронуты |
| `одна подстановка` (consistency) | второе упоминание человека получило ту же подстановку |
| `подстановка не плавает` (stability) | подстановка не менялась между запросами |

Рядом со строками печатаются два счётчика. **`не атрибутируется`** — значения, где
две соседние подстановки слились в один блок и выравнивание не может сказать, какая
из них чья; такие значения НЕ считаются ни в круг, ни против него. Прибор, который не
может атрибутировать, не должен оценивать. **`вернулось починенным`** — расхождения
круга, где инструмент получил значение исправленным, а не потерянным.

**Общего балла нет, и это решение, а не недоработка.** Шлюз, который маскирует всё,
выигрывает первую строку и проигрывает две последние. Что покупать — решает читатель.

У каждого числа — точный интервал Клоппера–Пирсона. Безошибочная строка печатает,
что она СЕРТИФИЦИРУЕТ: ноль ошибок на 272 случаях — это ≥98.9%, а не «100%».

## Как это работает без модели

Харнесс поднимает фальшивого провайдера. Маскирующий прокси шлёт ему замаскированные
сообщения — ровно то, что увидела бы модель. Скриптовая «модель» выравнивает их с
оригиналом, копирует увиденное в вызов инструмента (дословно: настоящая модель иногда
перепишет значение, и прощать это значило бы прятать поломку), прокси восстанавливает
аргументы, харнесс читает, что получил бы инструмент. Ноль рублей за прогон, полная
воспроизводимость.

Библиотека вместо прокси вызывается напрямую тем же интерфейсом.
`tests/test_proxy_path.py` доказывает, что оба пути дают одинаковые строки.

## Корпус

Шесть семей (`create_order`, `check_status`, `verify_identity`, `refund`, `send_sms`,
`second_mention`), три регистра (`clean` — как в форме, `chat` — строчными без
разделителей, `sloppy` — одна описка), четыре яруса имён.

**Пулы независимы от любого газетира.** Имена, улицы и города — снимки Wikidata (CC0),
NEN (CC BY 4.0), mimesis и Faker (MIT). Каждое имя несёт ярус: `common` (частотные,
которые есть у всех), `tail` (редкие, только в Wikidata), `diminutive` (Саша, Таня),
`foreign` (Нгуен, Йылдыз). **Заголовочная цифра по именам — хвост, а не среднее:**
корпус из частотных имён не может провалить ни один словарь.

**Телефоны не принадлежат никому.** Резервные коды DEF (907, 935, 943–948, 972–976,
Приказ Минцифры № 75 ред. 17.06.2025) не выданы ни одному оператору, но libphonenumber
считает их валидными мобильными: детектор их видит, абонента нет. СНИЛС, ИНН и карты —
с настоящими контрольными суммами (детекторы их проверяют, и правильно делают);
вероятность совпадения с реальным значением ~1e-9…1e-11 на значение.

**Эталон — каноническая форма ТОГО, ЧТО НАПИСАНО.** Сообщение без отчества не требует
отчества обратно; телефон, набранный как «89071234567», должен вернуться этими цифрами.
Шлюз, который «чинит» описку клиента, изменил данные клиента — и здесь это видно.

## Проверки, чтобы бенчмарк мог провалиться

Корпус можно построить так, что он не провалит никого: правило отбора использует
сигналы самого детектора, пулы берутся из его же словаря, скорер возвращает истину над
пустым списком. Каждое из этого с кем-нибудь случалось, и ни одно не видно в цифрах.
`agentmask gates` — механические проверки против этого класса:

- **G6** — passthrough обязан дать «скрыто 0» и «круг из всех 100%». Если значение не
  переживает маскировщик, который ничего не меняет, неверен СЛУЧАЙ, а не маскировщик.
- **G7** — наивный regex обязан оставить след в каждом случае, который не объясняет,
  почему не может. Поле `hard` выводится из того, ЧТО НАПИСАЛ ШАБЛОН (есть ли заглавная
  буква в имени, целы ли цифры), а не из прогона детектора по корпусу: второе сделало бы
  корпус зеркалом этого детектора.
- **G8** — страты наполнены: доля имён вне частотного яруса, доля имён без подсказки,
  размер каждого регистра и семьи.
- **G10** — в `src/` нет импортов из закрытого движка авторов.
- **G11** — опубликованные результаты посчитаны на текущем корпусе.

`tests/test_gates.py` ломает каждое свойство нарочно и требует, чтобы проверка покраснела.

## Как добавить случай

Единица вклада — ОДИН файл `cases/<семья>/<id>.json`. CI проверит схему, офсеты,
негативы и прогонит два эталонных маскировщика. Подробности — `CONTRIBUTING.md`.

## Что показал первый прогон

Семь систем на одном корпусе. Числа — в `leaderboard.md`, здесь то, что за ними стоит.

**LiteLLM с guardrail `presidio` возвращает в инструмент 0 значений из 327.** Не
«мало», а ноль. Перекрывающиеся находки склеиваются в испорченный плейсхолдер —
`8 935 7476622` уходит к модели как `8 935 <DATE_TIME_6>VER_LICENSE_6>`,
`89747851063` как `<US_BANK_NUMBER_7>LICENSE_7>` — и такой плейсхолдер не находится
в карте восстановления, поэтому он же и приходит в аргумент вызова. Проверено на
`ghcr.io/berriai/litellm:main-stable` с `output_parse_pii: true` и `default_on: true`,
воспроизводится одним запросом. Заодно видно, что часть телефона («8 935 ») остаётся
открытой.

**LLM Guard по-русски не работает вовсе.** `Anonymize` принимает только `en` и `zh`;
`ru` поднимает `LLMGuardValidationError`. Его 42.6% — это английский конвейер на
русском тексте, и читать их как «плохо ищет по-русски» неверно: продукт этот язык
не заявляет.

**Presidio со стандартными распознавателями маскирует лишнее.** 28% негативов
тронуто — худший показатель в таблице: «привет» становится PERSON, город и номер
заказа тоже. Телефон в российском формате он при этом не находит: распознаватель
рассчитан на другие страны.

**Cloud.ru — противоположный профиль.** Находит меньше всех (43.7%), но всё, что
нашёл, возвращает безупречно (100%) и не трогает ничего лишнего (100%). Плейсхолдер
нельзя восстановить неправильно — и нельзя просклонять, поэтому имена он почти не
видит (12%).

## Раскрытие: бенчмарк написан вендором

AgentMask-RU спроектирован и поддерживается командой, которая продаёт **Pseudex** —
шлюз, измеряемый этим же бенчмарком. Поэтому:

- Правило отбора случаев вычислимо БЕЗ какого-либо маскировщика и зафиксировано до
  прогонов. Пулы значений НЕ пересекаются с нашими рабочими словарями по построению
  (см. `pools/build_pools.py`), а манифест нашего прогона печатает, сколько имён корпуса
  всё-таки лежит в нашем газетире — 29 из 206 личных имён и 111 из 168 фамилий.
- Наш прогон помечен `vendor-submitted` и содержит полные пообъектные наблюдения:
  любой может пересчитать наши строки своей арифметикой.
- Ни один наш прогон не отзывается. Худшие числа остаются в истории.
- Наш движок нельзя воспроизвести из этого репозитория (он лицензируемый и без лицензии
  не детектирует). Пробный ключ и образ — по запросу; до тех пор наша строка читается
  как заявление вендора, а не как независимый замер, и мы так её и подписываем.

**Что бенчмарк нашёл у нас самих в первом прогоне.** 80 расхождений круга из 461.
53 из них — значение вернулось ПОЧИНЕННЫМ, а не потерянным: гомоглиф в цифрах
свёрнут («8 972 58О2333» → «8 972 5802333»), улица написана по реестру («блоная» →
«Блочная»), имя приведено к именительному падежу («филатову мию» → «Мия Филатова»).
Это осознанная политика, и здесь она выглядит промахом, потому что эталон — то, что
написано. Остальное — настоящие дефекты, и они заведены: первое слово составного
названия улицы («Николая Заболоцкого») остаётся вне спана, иностранное имя вернулось
огрызком, женская фамилия вернулась в мужской форме.

**Счётчик «вернулось починенным» — нижняя оценка.** Он ловит свёрнутые look-alike,
вставленное родовое слово и переформатированные цифры; он НЕ ловит изменение падежа и
исправление опечатки в буквах, потому что для этого нужна морфология, а бенчмарк,
которому нужна морфология одного из участников, перестаёт быть нейтральным.

## Чего бенчмарк НЕ измеряет (версия 0.1)

Стриминг; персональные данные, приходящие ОБРАТНО из инструмента; память агента между
диалогами; восстановление подстановки, которую модель просклоняла, транслитерировала
или сократила до инициалов; эквивалентность по TOST (нужен прогон с живой моделью).
Всё это — заявленные пробелы, а не молчание.
