# Б21 не флейк теста: остаточный дефект обратного пути (дательный падеж)

## Что происходит

Тест `test_names_morphology.py::test_b21_pinned` падает в CI примерно раз в
двадцать запусков и **блокирует тег платформенного релиза**: job `tag` ставит тег
только на зелёные проверки merge-коммита, а падает движковый джоб. Два релиза
подряд (0.3.26 и 0.3.27) тег не поставился с первого раза, и оба раза помогал
перезапуск.

Это не флейк. Воспроизведено локально и измерено:

```
провалов: 9 из 200   (случайная жеребьёвка фамилии, как в тесте)
провалов: 5 из 200   (повторный прогон)
провалов: 0 из 200   (жеребьёвка сделана детерминированной)
```

## Как выглядит провал

```
исходное:   Курьер выехал к Анне Черных
в модель:   Курьер выехал к Мещеряковой Софии      ← подмена собрана фамилией вперёд
обратно:    Курьер выехал к Черных Анны            ← должно быть «к Анне Черных»
```

Токены раскрываются все — наружу уходит персональных данных не больше, чем
должно. Ломается **форма**: обратный путь читает падеж по первому слову подмены,
а первым стоит фамилия. У «Черных» падеж не выражен вовсе, поэтому приоритет
pymorphy3 разрешает неоднозначность не в ту сторону — и в аргумент вызова
уезжает «Анна Черных» вместо «Анне Черных». Это ровно тот дефект, который
описан в докстринге как исправленный («the customer's own case wins the tie»):
исправление держится, пока подмена собрана в порядке оригинала, и не держится,
когда жеребьёвка собрала её иначе.

## Чем это плохо, а чем нет

- **Не утечка.** Настоящие значения не появляются там, где их не должно быть.
- **Дефект качества у клиента.** В CRM или в вызове инструмента фамилия с
  отчеством-порядком и падеж приезжают неверными. Для доставки и записи это
  видимая ошибка, и она попадает в карточку клиента.
- **Он блокирует релизы.** Триггер — жеребьёвка, поэтому красный приходит
  случайно и всегда не вовремя.

## Воспроизводитель

```python
import secrets, testkit
from pseudex.detect_all import Detector
from pseudex.redact import mask_text, unmask_text
from pseudex.vault import Vault

testkit.load_dev_bundle()
det, real = Detector(), secrets.choice

def forcing(*wanted):
    def choice(seq):
        for w in wanted:
            if w in seq:
                return w
        return real(seq)          # ← вот здесь и живёт случайность
    return choice

fails = 0
for _ in range(200):
    secrets.choice = forcing("Панова", "София")   # то же, что делает тест
    v = Vault(":memory:", "b21")
    orig = "Курьер выехал к Анне Черных"
    masked = mask_text(orig, v, det.detect(orig))
    if unmask_text(masked, v) != orig:
        fails += 1
print(fails, "из 200")
```

Тест форсирует только два значения из пула; когда жеребьёвка уходит на
`real_choice(seq)`, она с некоторой вероятностью собирает подмену фамилией
вперёд — и тогда виден этот дефект. Форсирование всего пула даёт 0 провалов, то
есть красный гасится, а дефект остаётся: **это лечение симптома, а не причины.**

## Что с этим делать

1. **Починить причину в движке** — обратный путь должен брать падеж из
   собственного разбора исходной фразы, а не из порядка частей подмены. Тогда
   случайная жеребьёвка в тесте становится естественным сторожем дефекта, а не
   источником красного. Это правка движка, значит отдельный релиз движка и
   полная измерительная батарея перед ним.
2. **Не «убирать» тест.** Он поймал настоящий дефект; убрать его — значит
   оставить дефект без сторожа и продолжать ловить красное случайно.
3. Пока причина не починена, релизы платформы продолжат изредка упираться в
   перезапуск проверок. Это не повод менять правило «тег только на зелёное»:
   правило работает, красный настоящий.
