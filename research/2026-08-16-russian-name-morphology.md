# Морфология русских ФИО: чем склонять и где всё ломается

**Дата:** 2026-08-16 · **Повод:** фейковые ФИО были грамматически рассогласованы,
модель их «чинила», и починенный токен переставал находиться в волте — в
инструмент клиента уходил несуществующий человек. Три персоны-клиента наткнулись
на это независимо.

**Проверено:** Python 3.12.12, pymorphy3 2.0.6 + pymorphy3-dicts-ru 2.4.417150,
petrovich 2.0.1, natasha 1.6.0 — в venv проекта, а не по документации.

---

## Ответ

**Ядро — pymorphy3, и только он.** petrovich как единственный движок брать
нельзя: два подтверждённых бага порта, данные в PyPI отстали от upstream,
последний релиз 2020 года. natasha склонять не умеет вовсе — `normalize()` это
лемматизация, обратной операции нет.

**Главное правило: никогда не `parse(w)[0]`.** Первый разбор имени у pymorphy3
регулярно оказывается не той частью речи.

## 2. Где ломается склонение

### pymorphy3, наивный `parse(w)[0].inflect(...)`

| вход | что даёт первый разбор | результат |
|---|---|---|
| Черных | `ADJF` «чёрный» | **чёрных** — прилагательное, и ё подставлена |
| Седых | `ADJF` «седой» | седых — совпало случайно |
| Салтыков | `NOUN` мн.ч. род.п. | **салтыков** — не склоняется |
| Любовь | `NOUN` нарицательное | **любви** вместо «Любови» |
| Иванова | `Surn masc gent` | женский именительный прочитан как мужской родительный |
| Мамин-Сибиряк | — | **мамин-сибиряка** — склонена только вторая часть |

`[A]` Все воспроизведены. **«Черных» имеет верный разбор `Surn` с `Fixd`, но он
не первый** — фильтрация по `Surn/Name/Patr` его находит.

`[A]` **`Fixd` — рабочий программный признак несклоняемости.** Дюма, Гюго,
Живаго, Шевченко, Пикадилли, а также ЖЕНСКИЕ Ким/Ковальчук/Мороз/Черных — все
несут `Fixd`. Иванов — не несёт.

`[A]` **Женская фамилия на согласный, у которой нет женского разбора** (Цой,
Кисель), при фолбэке на мужской даёт «цоя», «киселя». Отсутствие женского
разбора само по себе является ответом: не склонять.

### petrovich — два бага порта

`[A]` **Модификатор `"."` не останавливает поиск правила.** В `__find_rules`
стоит `continue` там, где Ruby берёт первое совпавшее правило. Следствие:
`Черных` с явным мужским родом → **Черныха**.

`[A]` **Androgynous-правила недостижимы при явно указанном роде.** Указание
правильного рода делает результат хуже: `Никита MALE → Никита` (без рода →
Никиты). То же для Лука, Фома, Савва, Данила.

## 3. Определение рода

Единственный опубликованный алгоритм с исходником — Ruby petrovich
(`Gender.detect` + `gender.json`). Порядок приоритетов там жёсткий: `[A]`

1. **Отчество — абсолютный приоритет**, выход немедленно. Суффиксы: жен. `на`,
   `кызы/гызы/кизи`; муж. `ич`, `оглы/улы/уулу`.
2. При конфликте выигрывает не-androgynous.
3. **Если оба определились и противоречат — возвращается «не определён»**, а не
   «вероятнейший».
4. Длиннейший суффикс выигрывает.

`[A]` pymorphy3 даёт то же для русских отчеств дешевле: `Ивановна → Patr femn`
со score 1.00. **Но тюркские не покрывает**: `оглы` размечается как `Name`,
`кызы` не распознаётся вовсе — их надо брать суффиксным списком.

Списки исключений в `gender.json`: ~150 мужских имён на `-а/-я`, ~230 женских на
согласный, плюс явно androgynous (Саша, Женя, Ким).

**Опубликованных оценок точности нет ни у кого** — ни pymorphy3, ни petrovich,
ни DaData цифр не публикуют. Проверено отсутствие.

## 4. Улицы

**Готовых решений в Python-экосистеме нет.** natasha `AddrExtractor` только
парсит; DaData склоняет ФИО, но не адреса.

`[A]` Даже для *извлечения* наташе понадобился хардкод: в `grammars/addr.py`
лежит `EXCEPTION = {'арбат', 'варварка', ...}` с авторским комментарием про
«улицы, которые ни в какую не хотят парситься».

Эмпирика по согласованию прилагательного с родовым словом:

```
улица Тверская          → улицы Тверской          ✓
Ленинский проспект      → Ленинского проспекта    ✓
площадь Революции       → площади Революции       ✓  (родительный заморожен)
шоссе Энтузиастов       → шоссе Энтузиастов       ✓  (шоссе несклоняемое)
улица Ленина            → улицы Лениной           ✗  КАТАСТРОФА
Большая Никитская улица → Большей Никитской ✗ (лексема «большой» даёт компаратив)
```

**Правило, которое обязано быть жёстче тегов:** если часть названия стоит в
родительном падеже (Ленина, Победы, Энтузиастов) — она заморожена и не
склоняется никогда. Без него «улица Ленина» превращается в «улицы Лениной».

## 5. Практики генерации фейковых ФИО

`[A]` **Faker `ru_RU`**: `fake.name()` род сохраняет (форматы собраны из
компонентов одного рода), но `fake.first_name()` / `fake.last_name()` берут из
объединённых кортежей и род **не** держат — их смешивание даёт «Мария Иванов».
Частотность не моделируется. Склонения нет вовсе.

`[A]` **Presidio**: оператор `replace` подставляет константу; ни консистентности
«одна сущность → один суррогат», ни сохранения рода из коробки.

`[A]` **[Surrogate Substitution Preserves PHI Detectability](https://arxiv.org/abs/2608.03172)**
(2026) — прямо про нашу задачу. Формулировка дословно: *«Structure-preserving
de-identification replaces PHI with realistic same-type surrogates — "Anna S."
becomes "Maria S.", not [NAME] — so that clinical text stays fluent and
downstream tools keep working. But this only helps if the substitution does not
itself corrupt the signal those tools rely on.»* 11 детекторов, 7 языков, 57k
парных спанов; recall на маскированных спанах 76,1% → 74,9%, эквивалентность
через TOST. Русский в абстракте не заявлен.

`[D]` Публикаций именно про **грамматическую рассогласованность** суррогатов как
причину деградации downstream я не нашёл. Наш случай — эмпирическое наблюдение
трёх прогонов, а не подтверждённый литературой эффект. Это честная граница.

## Открытые вопросы

- **CC BY-SA 3.0 на словаре pymorphy3-dicts-ru** — закрыть с юристом до релиза.
- **Склонение адресов не сделано.** Фейковый LOC генерируется в одной форме;
  правило заморозки родительного из раздела 4 нужно будет применить, когда
  дойдём до дефекта №2 в `known-issues`.
- **Точность нечем измерить**: публичного размеченного набора русских ФИО со
  склонениями нет. Свой набор в `test_names_morphology.py` — 17 случаев рода и
  14 склонения — это регрессионная защита, а не оценка точности.
