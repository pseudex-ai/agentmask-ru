# Deep Dive — Как открытый бенчмарк живёт и не врёт: механика для публичного AgentPII-RU

> Date: 2026-09-20 · Mode: breadth fan-out (B1 мировые бенчмарки, B2 русские бенчмарки и сообщество, B3 честность и статистика, B4 источники данных / хостинг / лицензии; синтез и проверка — ведущим) · Контекст: владелец открывает НОВЫЙ бенчмарк «ломает ли шлюз маскирования агента» с харнессом для любого маскировщика; приватные v3/v4 не публикуются (их пулы лежат в лизованных словарях — `research/2026-09-07-benchmark-critics.md`).

## 1. Вопрос и рамка

- **Настоящий вопрос:** какие механики заставляют посторонних людей ДОБАВЛЯТЬ кейсы в чужой бенчмарк и ГОНЯТЬ на нём свои системы, при этом не давая бенчмарку стать «прибором, который не может провалиться» — и какие из этих механик работают именно в России.
- **Полный ответ обязан установить:** (1) единицу вклада и стимул, с числами контрибьюторов; (2) что убило умершие бенчмарки; (3) как русские бенчмарки получали внешний вклад — и получали ли; (4) минимальный набор честности (контаминация, негативы, статистика, конфликт интересов) с первичными источниками; (5) из чего строить корпус, чтобы он был независим от НАШИХ словарей, и где его хостить так, чтобы он открывался из России; (6) кого из вендоров можно измерять по их ToS.
- **Гипотезы на входе:** (H1) лидерборд + PR-кейсы + HF = достаточно; (H2) русское сообщество вносит вклад PR-ами, как западное; (H3) CC BY 4.0 на данные, Apache-2.0 на код — очевидный выбор; (H4) нужны «независимые источники» имён.

## 2. Ответ (BLUF)

**Контрибьюторов даёт не звёздность, а ЕДИНИЦА ВКЛАДА: один файл со схемой, проверяемый CI, с записанной наградой.** lm-eval-harness 460 контрибьюторов / 1 537 PR, MTEB 344 / 2 951, BIG-bench 231 / 681 — против τ²-bench 15, AgentDojo 18, LiveCodeBench 16, где вклад = целый домен [A]. Эталон — MMTEB: реестр очков по-PR (JSONL, названный номером PR), соавторство от ≥10 очков, ревью оплачивается наравне с вкладом (у лидера 326 из 597 очков за ревью), реестр ревьюеров в одном закреплённом issue и **автоматический гейт «может ли этот кейс провалиться»** — два референсных решения гоняются на каждом присланном кейсе, флаг при near-random / near-perfect / equal [A/B]. BIG-bench умер (архив 17.04.2026) на одноразовом соавторстве: после статьи зарабатывать стало нечего [A]. **H2 ложна:** в России внешний вклад в бенчмарк сработал ровно один раз — MERA, и только после формального «call for datasets» с письменными критериями приёма (≥300 вопросов, baseline ≤0.8, синтетика с указанием генератора, README RU+EN, лицензия в метаданных) → ≥10 внешних аккаунтов и 12 приватных тестов в MERA Text 2.0 (01.09.2026) [A]; `hivetrace/pii-bench` за 8 месяцев — 0 внешних PR, 0 issues, дефект чек-сумм авторы чинили сами через 7 месяцев [A]. Русский tool-calling тест уже есть — GorillaHard внутри MERA (1169 вопросов, без исполнения, без ПДн) [A]; русского бенчмарка «ПДн × вызовы инструментов» нет ни одного (поиск по HF API — 0). **Честность:** только 16.0% из 445 бенчмарков используют статистические тесты (Bean et al., NeurIPS 2025) [A]; OpenAI в феврале 2026 сама отозвала SWE-bench Verified (59.4% из 138 проверенных задач сломаны) — сильнейший прецедент доверия к vendor-authored бенчмарку [B]; TOST-эквивалентности в LLM-evals нет ни у кого — цепочка Schuirmann 1987 → Lakens 2017 → клинические non-inferiority [A]. **H4 уточнена:** независимость — свойство ПРОЦЕССА ВЫБОРКИ, а не пула (частые имена лежат во всех словарях); наши 225k имён — публичный BSD-3 `russiannames` (проверено: `bench/build_name_dicts.py`), так что бенчмарк обязан печатать долю значений вне словарей и считать страты отдельно. **Хостинг:** GitHub из РФ деградирует с мая 2026 (OONI до 16% аномалий, 130+ заблокированных страниц; РКН отрицает), HF не заблокирован; MERA = GitHub + HF + свой сайт-лидерборд — этот же паттерн плюс зеркало на GitVerse/.ru.

## 3. Инсайты (проход 0.01%)

1. **Ревью должно оплачиваться наравне с вкладом, иначе очередь PR встанет.** MMTEB закрыл сотни PR за пятинедельное окно только потому, что 2 очка за ревью = 2 очка за датасет; у лидера очков больше половины — за ревью. Бенчмарк одной компании без этого правила превращается в бэклог мейнтейнера — ровно то, что случилось с pii-bench. `[A]` MMTEB points.md, статья 2502.13595.
2. **Гейт «может ли кейс провалиться» — механическая форма нашего ручного урока про `not any([])`.** MMTEB гоняет два референсных решения на каждый кейс; для бенчмарка маскировщиков это no-op-маскер и Presidio: кейс отклоняется, если оба равны, если нет негативов, или если ground truth выводим из сигналов самого детектора. `[B]` MMTEB; `[A]` наш `e2e/audit_gates.py` как вторая половина.
3. **«Pool ⊂ vocabulary» имеет имя в литературе — test–train overlap (Lewis et al. 2021), а отбор с моделью в петле — AFLite.** Это позволяет описать наш дефект v4 языком статьи, а не признания, и обязывает печатать долю значений внутри словаря каждого измеряемого маскера. `[A]`
4. **Правило отбора кейсов должно быть вычислимо БЕЗ системы под тестом — и записано на карточке.** «Любая цифра или числительное» вместо «слово-тип улицы» — наш урок bench/voice, у него есть прецедент (HLE §3.1 декларирует, где модель была в петле). Это самая дешёвая и самая редко исполняемая гарантия. `[A]` Bean et al. §3.1/3.8; HLE.
5. **В России вклад приходит не через PR, а через ТРИ КАНАЛА, у каждого своя валюта:** MERA-задача (авторы попадают в национальный бенчмарк, который обязаны прогонять все модельные команды), shared task на «Диалоге» (академики приходят за публикацией — NEREL вырос через RuNNE/BioNNE без единого PR в репо), ODS-секция (практики). PR-ы — четвёртый и самый слабый. Отсюда приватная половина в MERA, публичная — у нас. `[A]`
6. **Телефоны для синтетики есть где взять законно:** резервные коды DEF **907, 935, 943–948, 972–976** по действующей редакции плана нумерации (Приказ Минцифры от 31.01.2022 № 75, ред. 17.06.2025, таблица 8) не назначены никому, а libphonenumber 9.0.36 принимает их как валидные мобильные — детекторы не откажут, абонента нет. (Список ветки B4 включал 949/959/990 — они назначены в текущей редакции; исправлено по первоисточнику.) `[A]` PDF на 25.rkn.gov.ru; проверка libphonenumber — в этой сессии.
7. **Skyflow нельзя измерять публично:** ToS §2.5(f) (15.07.2026) запрещает «publicly disseminate information regarding the performance of the Skyflow Services» — классическая DeWitt-оговорка. Вендор либо сабмитит сам с подписанным манифестом, либо стоит в таблице как «отказался/ToS» с цитатой. `[A]`

5. Результаты пересчитываемы третьей стороной из артефактов: SWE-bench `submit verify`, τ² — траектории + `standard|custom` + `modified_prompts`, MTEB отменил самоотчёт через model-card «as we want to ensure that we can match the results with the model implementation» [A]. Papers with Code — единственный без правила артефактов — закрыт 07.2025.
6. Надёжность, не точка: pass^k при k≥4 (τ²: «we strongly prefer results with at least 4 trials per domain») [A/B].
7. Версия НАБОРА отдельно от кода, bump при любом изменении, changelog по кейсам (lm-eval `version`, AgentDojo) [A].
8. Негативы — категория первого класса со своей строкой (BFCL 882 irrelevance items; AgentDojo utility vs security) [A].
9. `created_at` на каждом кейсе, `--since` в скорере; каденс НЕ обещать (LiveCodeBench остановился через ~16 месяцев) [A].
10. Canary GUID в каждом файле (BIG-bench) — GPT-4/Claude его воспроизводят, значит это детектор, не щит [A/B].
11. Статус «Flagged» с ссылкой на обсуждение вместо тихого удаления (Open LLM Leaderboard) [A].
12. Лейн «запрос на оценку» с SLA как ВТОРОЙ путь (MTEB «within 7 working days») [A].

Что убило: одноразовое соавторство (BIG-bench); хост платит за чужие прогоны (Open LLM Leaderboard, retired 03.2025 — «hill climb irrelevant directions»); платформа вместо датасета (Dynabench); самоотчёт без артефактов (PwC); приватный лейн без раскрытия (Arena — 27 вариантов Meta, один опубликован); фиксированный набор без обновления и hold-out (насыщение за 1–2 года; SWE-bench потребовал 93 аннотаторов OpenAI, чтобы выбросить 68.3%); каденс, обещанный маленькой командой; ограничительная лицензия данных (ai4privacy); «вклад = целый домен» (τ², AgentDojo) [A].

### B3. Честность: чек-лист карточки, три статистических инструмента, текст раскрытия

Первичные якоря [A]: Bean et al. NeurIPS 2025 — 445 бенчмарков, 16.0% используют статистические тесты, 53.4% обосновывают валидность, чек-лист из 8 рекомендаций; BetterBench NeurIPS 2024 — 14 из 24 не сообщают значимость, 17 из 24 без скрипта воспроизведения; Miller 2024 (Anthropic) — кластерные SE до 3× наивных, парные разности, n≈969 для δ=3 pp; Bowyer ICML 2025 — CLT ломается при n<100, Wilson/CP; Dietterich 1998 — McNemar; Card 2020 — MDE; Lewis 2021 — test–train overlap; Bras 2020 — AFLite; TAB 2022 — entity-level recall + информационно-взвешенная precision, термин «unnecessary masking»; i2b2 2014 — entity vs token; XSTest/OR-Bench — контрастные наборы; Leaderboard Illusion — 27 приватных вариантов, правило «без отзыва результатов». [B]: OpenAI Feb 2026 — «we have stopped reporting SWE-bench Verified scores, and we recommend that other model developers do so too».

**Чек-лист карточки (18 пунктов, сокращённо; полный с цитатами — сырой отчёт B3 §2):** 1 явление определено ДО кейсов, с негативным определением («голый город — не ПДн, 152-ФЗ ст. 3») · 2 цепочка валидности явление→задача→источник→правило отбора→метрика→утверждение · 3 правило отбора вычислимо без системы под тестом и записано · 4 доля значений внутри словаря вендора измерена, страты считаются отдельно (наши «0 из 2172 внутри / 8 из 272 вне» — число, которое надо печатать) · 5 аудит утечки решения в подсказку (cue-слова генератора ≠ cue-список детектора) · 6 контрастный (негативный) набор заявленного размера в том же харнессе · 7 две строки полноты: type-aware strict как заголовок, type-blind отдельно как «leak-only» · 8 покрытие третьей строкой · 9 precision на уровне сущностей по негативам · 10 неопределённость на каждом числе (n, кластеры, SE; Wilson/CP при n<сотен) · 11 сравнения парные с McNemar (b, c) · 12 MDE рядом с каждым сравнением · 13 «эффекта нет» — только TOST с предрегистрированной δ · 14 ноль ошибок несёт точный биномиальный пол (99.4% → 498 безошибочных) · 15 pass^k, K и температура зафиксированы · 16 статус контаминации, hold-out, даты создания · 17 версия и правила пересчёта, старые результаты несравнимы · 18 происхождение и деньги на карточке (кто построил, кто платит, сколько внутренних вариантов прогнано, без отзыва своих результатов, критерии снятия, Croissant).

**Три инструмента:** (1) парные кластерные SE (Miller eq. 7–8; `statsmodels` OLS разности на константу с `cov_type="cluster"`), McNemar exact для бинарных, Wilson при n<100; (2) **TOST** с δ на карточке ДО данных — `statsmodels.stats.weightstats.ttost_paired`, `binom_tost`; эквивалент: 90% ДИ разности внутри (−δ, +δ); ROPE как байесовская форма; (3) Clopper-Pearson нижняя граница `beta.ppf(0.05, x, n−x+1)`, при нуле ошибок 0.05^{1/n}, требуемое n = ⌈ln 0.05 / ln p⌉ → 99.0%: 299, 99.4%: 498, 99.9%: 2 995; **никогда не бутстрапить долю** — перцентильный бутстрап по одинаковым исходам даёт нулевую ширину.

**Текст раскрытия для vendor-authored бенчмарка** (каждая фраза с прецедентом — Datasheets «who funded», Leaderboard Illusion «disclose the total number of private variants … prohibit score retraction», HLE/Epoch hold-out у третьей стороны, tau2 v1.0.1 «результаты несравнимы между версиями», OpenAI «мы прекращаем отчитываться, когда прибор перестал измерять»): «Бенчмарк спроектирован и поддерживается <вендор>, который продаёт <продукт>, измеряемый этим бенчмарком. Финансировал только <вендор>. Кейсы писали/ревьюили N сотрудников и M внешних ревьюеров без коммерческой связи (K% кейсов). Правило отбора — <правило>, вычислимо без маскировщика и зафиксировано до прогона <продукта>. X% значений лежат в словарях <вендора>; результаты внутри/вне печатаются отдельно. До релиза прогнано V внутренних версий, ни одна не отозвана, все перечислены. Hold-out из H кейсов, ответов которых команда не видела, скорит <третья сторона>».

- **Независимые пулы (измерено 20.09.2026):** имена — mimesis ru (MIT: 203 м + 480 ж), MentalTech NEN (CC BY 4.0: 1 551 с уменьшительными), Wikidata CC0 (2 007 кириллических given names по SPARQL); фамилии — mimesis (3 230 гендерных форм), Wikidata (11 119), Faker (338); отчества — mimesis (278) или по правилу; улицы — mimesis (2 744), Wikidata (16 337), Faker (297); города — mimesis (1 120), Wikidata (151 546). **Независимость — свойство выборки:** карточка печатает долю имён вне любого коммерческого газетира, который бенчмарк хочет уметь ронять (хвост Wikidata, уменьшительные NEN).
- **Регистры и фразировка:** MASSIVE ru-RU (CC BY 4.0, 16 521 реплика, «free of personal or sensitive data»), SOVA RuDevices (CC BY 4.0, ~85k расшифровок), RuSpellGold (Apache-2.0, статистика опечаток), pii-bench (Apache-2.0) — только как внешний набор сравнения, не сливать. **Открытого русского корпуса поддержки с лицензией на редистрибуцию не существует** (HF: 0) — регистр синтезируется шаблонами + LLM и валидируется по статистике MASSIVE/RuDevices. Не брать: NEREL (без лицензии), open_stt (CC BY-NC), Golos (кастомный PDF), ai4privacy (academic-only), `ru_sharegpt_cleaned` (без лицензии).
- **Структурные идентификаторы:** телефоны — резервные DEF (инсайт 6); СНИЛС/ИНН/карта — алгоритмически, checksum-VALID (бенчмарк тестирует checksum-gated детекторы) с заявленной вероятностью коллизии ~1e-9–1e-11 на карточке; паспорт — серия регион+год, номер случайный. Фильтр публичных персон для имён (MASSIVE содержит реальных людей).
- **Хостинг:** GitHub (харнесс, кейсы как plain files ≤ десятков МБ, чтобы `raw.githubusercontent.com` работал без LFS) + HF-датасет (те же файлы; `HF_ENDPOINT=https://hf-mirror.com` как обход CDN) + зеркало GitVerse (СберТех, серверы в РФ, on-prem с 05.2026) + статическая копия в Yandex Object Storage; лидерборд — статический JSON на GitHub Pages И на .ru-домене (паттерн MERA «свой сайт»); отдельный репо `results` под CC0 (mteb/results). Не зависеть от HF Spaces / GitHub Actions как единственной точки.
- **Лицензии:** данные CC BY 4.0 (ai4privacy — контрпример; CC BY-SA отпугнёт коммерческих маскеров от публикации прогонов); код Apache-2.0 (patent grant; pii-bench/BIG-bench/LiveBench) — ИЛИ MIT, если хотим совместимости с MERA один-в-один; результаты CC0; вклад через DCO (Signed-off-by), не CLA; `THIRD-PARTY-NOTICES.md` с MIT-уведомлениями и CC BY-атрибуциями; строки атрибуции на карточке (mimesis, Faker, Wikidata CC0, MentalTech CC BY 4.0, MASSIVE CC BY 4.0, RuDevices CC BY 4.0, RuSpellGold Apache-2.0, «телефоны из резервных кодов DEF Приказа № 75, не принадлежат ни одному абоненту»).
- **Контаминация:** canary GUID (детектор, не щит); генератор публичный / seed приватный с предрегистрированным хэшем seed; страта вне словаря; «свежий seed по запросу» (наш `make_addr_real.py <seed>` — уже прецедент); GSM1k-style приватная реплика.
- **ToS вендоров:** Skyflow §2.5(f) — запрет публикации performance [A]; Just AI Jay CoPilot — без запрета на бенчмарк, но Jay Guard только по договору (условия неизвестны) [A/D]; Cloud.ru оферта — основной текст чист, Приложения 3 и 8 не прочитаны [A/D]; KodikRouter — ToS нет (404) [D]; Presidio/LLM Guard/Cloud.ru OSS — свободно [A].

## 5. Критический анализ

- **Steelman «просто открыть репо и ждать PR»:** у pasteguard 754★ за 8 месяцев без всякого бенчмарка — интерес к теме есть. Но звёзды ≠ вклад: у τ² 2 070★ и 15 контрибьюторов; у Cloud.ru OSS 176★ и 6 содержательных внешних issues при полном корпоративном PR (C4). Интерес конвертируется в кейсы только через единицу вклада + награду.
- **Сильнейший контраргумент против MMTEB-модели для нас:** MMTEB — это 100+ соавторов ради статьи в топ-венью; у бенчмарка одной компании нет такой валюты. Ответ B2: в России валюты три (MERA-задача, shared task на Диалоге, ODS), и статья на Dialogue/arXiv — обязательная ножка, без неё бенчмарк не цитируют и в MERA не берут.
- **Несущее допущение:** что маскировщики захотят быть измеренными. Cloud.ru уже сделал сравнительную таблицу и F1 на pii-bench в README — они хотят; Skyflow запрещает ToS; Jay Guard — по договору. Бенчмарк должен быть полезен и без вендоров — как инструмент для ИНТЕГРАТОРА («ломает ли мой стек агента»), и первые числа — OSS (Presidio, LLM Guard, LiteLLM-hook, Cloud.ru OSS) + мы.
- **Противоречия:** B1 рекомендует MIT/Apache для кода и CC BY 4.0 для данных; B2 — Apache-2.0 на всё (совместимость с pii-bench/MERA). Не усредняю: данные — CC BY 4.0 (атрибуция нужна из-за Wikidata/MASSIVE-строк), код — Apache-2.0; MERA (MIT) принимает Apache-задачи. B4 включил 949/959/990 в резерв DEF — исправлено по действующей редакции (первоисточник прочитан).
- **Стимулы:** мы — vendor-authored; каждое число, которое мы напечатаем про себя, будет читаться как реклама. Ответ — п. 18 чек-листа и текст раскрытия, hold-out у третьей стороны (кандидаты: HiveTrace как конкурент, MERA как нейтральный, Dialogue Evaluation как академия), и правило «без отзыва своих результатов».
- **Заработанный консенсус vs повторяемое:** «единица вклада = файл» — заработано (три бенчмарка с сотнями контрибьюторов против трёх с полутора десятками); «HF-хостинг даёт охват» — заработано (ai4privacy 77k, Saiga 5.46M загрузок при 56★ — C4); «русское сообщество вносит PR-ами» — опровергнуто; «TOST — стандарт» — нет прецедента в LLM-evals, мы будем первыми, и это надо сказать в design doc, а не подать как норму.
