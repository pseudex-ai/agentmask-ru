# Аудит формы на каждом hop: заключение

Дата: 2026-09-27. Это заключение первоначального расследования в указанном объёме, до реализации исправлений. Последующая реализация и измерения — [PROGRESS](PROGRESS.md); текущий согласуемый объём — [матрица до 450](../../docs/plan-hop-form-before-450.md). Ветка `research/hop-format-audit`, база `9c5acbb13e02ae3b230a31411bef2877ecc23ef3`. Основной checkout и исходные прогоны не изменены.

## 1. Вердикт

1. **Компаратор формы не признан сломанным.** Все 10 384 сохранённых verdict повторно вычислены: расхождений 0. Это проверка воспроизводимости, не независимое доказательство полноты правил. Тесты метрик, наблюдателя, формы, report-selftest и medium perfect-gateway зелёные.
2. **Прежняя таблица «450» некорректно складывала попытки.** В A было 321 наблюдение I, но только 314 завершённых троек. Семь незавершённых попыток попали в сумму вместе с последующими перепрогонами. Правильный состав: A314+B9+C124+D3 = 450 уникальных `(case_id, repeat)`, без пересечений.
3. **17,78% нельзя называть вероятностью успешного восстановления движком.** Метрика использовала объявленные OUT-хопы, включая `absent` при отсутствии вызова в объявленном ходе. Агент вправе уточнять, менять число ходов и вызывать инструмент раньше/позже. Нужно измерять фактические переходы и отдельно поведенческий эффект C₀↔C₁ против I↔C₀.
4. **Ошибки движка реальны**, но их масштаб ещё нельзя вывести из смешанного знаменателя. Цифровой телефон возвращается словами; ответ и tool args выбирают разные формы; адрес собирается из подставной улицы и настоящего дома; tool result наследует не свою форму. Два класса PHONE воспроизведены без LLM через production core.
5. **Высокий `leak` не доказывает безопасность всего payload.** Неполное покрытие спана и неразмеченное эхо ошибки инструмента — отдельные источники открытых фрагментов. «Всего одна утечка» и «vault точно ни при чём» — преждевременные выводы.

## 2. Что именно проверено

Полный механический пересчёт: 450 завершённых троек. DeepSeek Flash: четыре независимых задания по шесть контрастных кейсов, **24 выбранных досье**, не ручной аудит всех 450. Исследователи читали буквальные поля сообщений/вызовов/результатов; главный ревьюер перепроверил ключевые утверждения по трассам и коду. В длинных кейсах не каждый вызов был прочитан вручную. Выборка намеренно диагностическая, не случайная для оценки распространённости причин.

Первичные отчёты с оговорками ревьюера:

- [PHONE и числовые формы](numbers.md).

- [Независимый скептик: наблюдатель и знаменатели](skeptic.md).

## 3. Исторический estimator на правильных 450

Это исправление состава выборки, **не исправление привязки к ходам**. Следующие числа сохраняют определения старых метрик и не становятся автоматически метриками качества engine-only.

| Метрика | Числитель / знаменатель | Результат |
|---|---:|---:|
| `leak` | 3750 / 3751 | 99,97% |
| `coverage` | 3691 / 3751 | 98,40% |
| `residual` | 7549 / 8349 | 90,42% |
| `end_to_end` | 301 / 1736 | 17,34% |
| `form_hIN` | 3184 / 3750 | 84,91% |
| `form_hOUT` | 5153 / 7470 | 68,98% |
| `chain_value` | 9 / 197 | 4,57% |
| `chain_form` | 11 / 197 | 5,58% |
| `consistency` | 1267 / 1295 | 97,84% |
| `memory_consistency` | 549 / 549 | 100% |
| `multi_all_out` | 0 / 330 | 0% |
| `overmask` | 450 / 450 | 100% |
| `out_absent` | 1498 / 2692 | 55,65% |

Важные определения:

- `leak` не равен «полное отсутствие ПД в отправленном сообщении»: частичная замена может пройти эту строку. Полноту защищённого спана показывает `coverage`; непроверенные поля payload сюда не входят.
- `form_hOUT` допускает `observed` и `unmasked`, но исключает `residual`. Следовательно, это условная проверка формы, а не совместный успех формы/идентичности/восстановления.
- `multi_all_out` считает группы по **ходам** с несколькими требуемыми OUT, не долю целиком исправных диалогов. Подпись «1 корректный сценарий из 337» была неверной.
- `overmask` относится к размеченным негативам, не ко всему естественному тексту.
- Высокая согласованность подмен не исключает ошибок vault, связи частей или восстановления.

### Четыре источника формы

| Фактическая категория наблюдателя | Числитель / знаменатель | Форма |
|---|---:|---:|
| IN/user | 1176 / 1505 | 78,14% |
| OUT/tool_arg | 3923 / 5305 | 73,95% |
| IN/tool | 1579 / 1741 | 90,70% |
| OUT/answer | 1129 / 2024 | 55,78% |

Последняя строка — **все наблюдаемые answer-хопы**, а не доказанный срез ответов после tool result. Для такого среза нужна причинная привязка к результату. Значения формы не доказывают правильность содержимого.

### Разложение вместо преждевременного обвинения

В 1736 объявленных tool-arg хопах: `absent=1348`, `observed=342`, `unmasked=37`, `residual=9`. Среди 388 не-absent старый value-предикат проходит в 301 случае: 77,58%. **Это дополнительная диагностика, не новый headline**: она тоже зависит от старой привязки и не охватывает все фактические вызовы.

В 744 absent-хопах инструмент с таким именем вызван где-то ещё. Это не значит, что 744 ошибки доказанно ложные: совпадение имени инструмента недостаточно для установления той же сущности, действия и версии данных. В трассах I всего 3978 фактических вызовов.

Для OUT/tool_arg отдельно видны 415 residual-хопов, исключённых из form. Дополнительный совместный диагностический знаменатель 5305+415=5720 даёт 3923/5720, но **не заменяет определение form без отдельного решения**. Из 197 объявленных цепочек 166 имеют absent target. Их низкий результат нельзя целиком приписать reverse engine.

## 4. Принятые доказательства и отвергнутые обвинения

| Свидетельство | Решение ревьюера |
|---|---|
| A `long_order-014`: fake цифрами → реальный телефон словами → mock отказывает `phone_not_e164` | Реальная потеря агентной формы; класс воспроизведён локально. Это отказ инструмента, не fail-closed защита gateway |
| Изолированная проба письменного телефона: agent `+7…`, tool `+7…`, answer `8 (…)` | Реальное расхождение двух OUT-путей; сохранён воспроизводитель |
| C `tool_chain-017`: Барбарисовая остаётся, дом/квартира восстановлены | Подтверждённый смешанный адрес; локализация точной виновной функции ещё нужна |
| C `prompt_rule-026`: реальная Комиссарова, fake Мятная остаётся в адресе | Подтверждённый residual. Гипотеза «общая улица настоящего и fake» отвергнута |
| B `memory_anaphora-045`: громова марина → Мухин Степан → Громов Марин | Повреждение подтверждено. Разделение ошибки mint/рода/обратной морфологии пока не доказано |
| A `long_order-058`: user `8 …`, result `+7…`, маска result в прежней форме | Реальная ошибка формы текущего IN/tool, не противоречие корпуса |
| A `long_support-013`: error payload повторяет фрагмент реального словесного телефона без маски | Подтверждённый незакрытый чувствительный фрагмент; не утверждаем, что раскрыт весь номер |
| «Produced/reference перепутаны в form» | Отвергнуто: сравнение формы, не равенство fake и real; ориентация соответствует контракту |
| «Идентичные строки получают разные verdict» | Представленный пример смешивал разные хопы; replay 10384 не выявил расхождений |
| «Удаление цифры исправляет fuzzy digit lookup» | Отвергнуто: исследованный lookup использует точные digit/digits10 сигнатуры |
| `chain-009`: «ответ содержит старое fake имя» | Отвергнуто: процитированный восстановленный ответ содержит реальное Владислав Юрьевич |
| «Канонизировать все телефоны в E.164» | Не соответствует цели: форму диктует текущий отправитель, не удобство шлюза |

Замечания к отчётам: у `skeptic.md` исходно ошибочная общая подпись `source A`; источник каждого кейса указан в его досье (например, `prompt_rule-026` — C). В `names.md` пара телефона в вводном примере переписана неточно; авторский вывод по ней не используется. В `chains.md` §6 смешаны две пары префиксов, поэтому этот абзац не принят как самостоятельное доказательство. Нельзя на основании отчётного процента автоматически объявлять причиной morphology, vault или detector: нужны точные строки и минимальная проба.

## 5. Проверки и ограничения независимости

- Replay формы: 10384 checked, 0 mismatches — [результат](evidence/verdict-replay.json).
- `report --selftest`: 29 broken metrics refused, 6 mutants caught.
- `test_metrics`: 20 именованных проверок; `test_observe`: 33; `test_form`: 72 пары и 41 extractor — PASS.
- `test_perfect --tier medium`: 300 кейсов, 25 bounded lines, 6 wrong gateways — [PASS](evidence/perfect-medium.log).
- Две проверки production core, in-memory vault, без модели: [артефакт](evidence/core-probes.json).

Perfect gateway следует объявленной траектории; его зелёный результат **не доказывает** корректность наблюдения за свободным живым агентом. Повторный вызов того же компаратора тоже не независимый oracle.

При попытке paired rescoring обнаружен `BundleNotLeased`: inherited v3 `_street_repaired` импортирует engine `pseudex.address.register_spelling`. Исторический диагностический пересчёт выполнен с явно загруженным dev bundle. Для будущего сравнения engine-версий этот oracle нужно отделить/зафиксировать, иначе исправляемый код может сдвигать собственную оценку. Это замечание к inherited paired taxonomy, не утверждение о зависимости v5 form-компаратора.

[Paired counts](evidence/paired-controls.json) показывают IC и CC отдельно, но без пересчёта доверительных интервалов/TOST; они не доказывают статистическую эквивалентность или её отсутствие. Между A–D менялись ограничения генерации: это завершённая ремонтная когорта, не один однородно настроенный новый эксперимент.

## 6. Воспроизводимость и стоимость

[audit.json](evidence/audit.json) хранит состав A–D, run ids, исходные пути, SHA256 исходных JSON/JSONL/TSV, числители и знаменатели. [code-fingerprints.txt](evidence/code-fingerprints.txt) фиксирует главные файлы измерителя и движка: исходный checkout содержит прежние незакоммиченные изменения, одного SHA коммита недостаточно. [diagnostics.json](evidence/diagnostics.json) — статусы; [case-index.json](evidence/case-index.json) — 450 строк механического индекса. Поле `manual_review` этого машинного индекса не является журналом выполненной ручной проверки; её объём задаёт [samples.json](evidence/samples.json) и четыре отчёта.

В `evidence/cases/` сохранены буквальные синтетические досье и C/C2-контроли. Два дополнительных диагностических экспорта не увеличивают заявленный объём ручного исследования. Полные raw runs остаются по исходным локальным путям; сохранение этих выдержек **не является полной резервной копией прогонов**.

`evidence/reproducers/` — архив одноразовых диагностических скриптов, не новый production-модуль. В них закреплены исходные абсолютные пути и вывод в temporary directory; перед повтором надо проверить доступность источников и хеши. Не запускать на месте существующего вывода, если нужно сохранить предыдущий артефакт. Mint случайный, поэтому новые fake-строки могут отличаться, хотя проверяемый класс ошибки тот же.

Четыре Flash-сессии завершены (`idle`), дочерних агентов нет. Оценка MCP accounting после корректирующих проверок: **$0,40519 суммарно**. Это расчёт по зафиксированному usage/прайсу, не списание из биллинга провайдера. Снимки — в `evidence/accounting/`. Новых платных генераций benchmark не запускали.
