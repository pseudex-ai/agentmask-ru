## Acceptance clauses

- **C03** — nested objects/arrays, several values in one list, numeric/string scalars, quotes/escape,
  split chunks, several stream choices. Result must be: valid JSON and types; the chunked result
  equals the buffered result; chunks do not mix; real strings are not re-restored; a partial failure
  of one value does not substitute another value's.
- **C06** — vault persistence, tenant/conversation scope, mask cache, isolation, latency, memory, DB
  growth; both entry points and the real endpoint contracts. Result: no new leak / mixing /
  false-mask, no proxy↔sidecar drift, no full vault scan for a token; the resource threshold is
  **agreed before measurement**; existing guarantees are preserved.

### What each C03 clause is held by

- **Nested JSON / string / number / escaped-quote — buffered == chunked.** `unmask_arguments` walks
  every string leaf (`redact.unmask_arguments` → `walk` → `_unmask` per leaf), leaves keys and
  non-string scalars untouched, and re-serialises with `ensure_ascii=False`, so the real
  `ООО "Заря"` is escaped by construction. The same tokens restored through the prose streaming leg
  (`unmask_stream_chunk` with carry + flush) produced byte-identical output to `unmask_text`
  (`prose chunked == buffered: PASS`). Number `3` and string-number `"42"` were untouched.
- **Tool args never through `/unmask_chunk`.** The flat path does restore the leaves but injects the
  real `"Заря"` unescaped, yielding invalid JSON (`'{"company": "ООО "Заря""}'`). This is the pinned
  reason `/unmask_arguments` exists; the probe confirms the tempting simplification is still wrong.
- **One carry per `choice.index`.** The proxy's `_stream_content` keys `StreamDetokenizer` per
  `choice.index` (`detok.setdefault(index, …)`); the sidecar `/unmask_chunk` is stateless and hands
  the carry back per call (caller owns one carry per choice). The probe interleaved two choices with a
  boundary INSIDE each token and both restored their own value; the **negative** (one shared
  `StreamDetokenizer` for both choices) splices choice 0's tail onto choice 1's head — proof the
  per-index carry is load-bearing, not decoration.
- **Partial failure does not substitute another value.** A field holding a known fake + one added
  digit stayed exactly that fake and is named in `residual_tokens`; the sibling field resolved to its
  OWN value; a plain number field was untouched. No cross-field pull.

## 3. C06 — code surface (all hold)

- **Tenant isolation.** org B unmasking org A's phone token returns the token unchanged (no
  resolution) and discloses no cross-org value; `detokenize` is keyed by `customer=? AND token=?`.
  Note (by design): `residual_tokens` names only *substitutes this org minted* that still stand, so a
  foreign-org token is not reported as a residual — the isolation guarantee is that it does **not**
  resolve, and the probe asserts exactly that.
- **Conversation scope.** `Vault.for_conversation` returns a shallow-copied view (scope never written
  onto the shared org vault); `content_key` carries `(org, conversation, content)`. `test_product.py`
  pins «isolated in the cache, shared in the vault».
- **Vault persistence.** `vault_test.py` (exit 0) reopens a file-backed vault and detokenises; the
  probe re-confirmed a fresh file DB across two `Vault` objects.
- **Cache.** `MaskCache` is bounded LRU, org+conversation keyed, stores masked output only; audit
  recorded on miss only (`test_perf_masking` audit de-dup: 5 resends → NAME/PHONE/LOC each 1).
- **Proxy↔sidecar parity.** The CLAUDE.md "`_mask_messages` duplicated on purpose and drifted" note is
  now **stale**: there is no `_mask_messages` in either entry point — both call the shared
  `envelope.mask_messages`/`mask_tools` (proxy with `skip_template=False`, sidecar with the body's
  `skip_system`). The masking semantics live in one place, which removes the drift the row worries
  about. The two surfaces still differ by design only in auth/scope wiring, not in masking behaviour.
- **No full vault scan for a token.** `unmask_text` resolves by SHAPE (`Vault.TOKEN_RE`) in batched
  indexed lookups, cost ∝ answer length, not vault size; the `/unmask*` legs are value-rate-limited
  and audit counts-only (`_detok_rate_ok` / `_audit_detok`). No probe found a scan.

## 4. C06 — resource threshold: measurement exists, threshold NOT pre-agreed

The measurement battery is present:

- **Latency p50/p95/p99** — `pseudex/profiling.py` records per-stage percentiles (`p50_ms/p95_ms/p99_ms`,
  bounded ring buffer) exposed at `GET /profile` (both entry points) under `PSEUDEX_PROFILE=1`;
  `profile_latency.py` prints mean/p50/p95 offline; `test_perf_masking.py` asserts `/health` p99 < 200 ms
  (event-loop responsiveness only, not a general latency budget).
- **Memory** — `pseudex/operator.py` reads per-process `VmRSS` (exposed via the operator surface);
  `preflight` computes worker count against the cgroup memory budget (`PSEUDEX_WORKER_MB`,
  `PSEUDEX_MEMORY_LIMIT_MB`), pinned by `test_preflight.py`.

**No numeric pre-agreed threshold is recorded.** `docs/plan-hop-form-before-450.md:133` requires

просмотра результата», and the C06 row itself demands «порог ресурсов согласован до измерения» — but
no number (ms or MB) for p50/p95/p99 or memory appears in the sprint matrix, the execution contract,
or `research/hop-format-audit/PROGRESS.md`. `PROGRESS.md:692-697` records a local diagnostic
(tool p50/p95/p99 0.101/0.132/0.198 ms before, answer 0.066/0.075/0.080 ms before) and explicitly
labels it «**not** a production latency gate». **This is an owner decision for G4 (fix a threshold
