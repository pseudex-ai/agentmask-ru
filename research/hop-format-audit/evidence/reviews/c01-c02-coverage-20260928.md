## 3. How the "applicable boundaries" map to the files

- **C01's actual scope is 7 types, not 9.** `test_other_hop_forms.py` covers EMAIL, DOB, SNILS,
  INN, CARD, PASSPORT, PLATE. NAME and LOC are deliberately outside it (they are the E03/E04/E05
  rows with their own files `test_name_subject_form.py` / `test_location_hop_form.py`); the
  module docstring "every type but PHONE" overstates that.
- **NEGATIVE exists only as generic CONTROL** (4 checks): "quantities are not identifiers",
  "numbers in a sentence stay", non-PII JSON/prose neighbours. There is **no per-type negative**
  — e.g. no check that a checksum-failing 11-digit SNILS look-alike, a non-Luhn 16-digit run, or
  a lower-case prose word `от` (which `ru_pii._PLATE_DENY_LOWER` exists to keep) stays unmasked.
- **CROSS-TYPE (межтиповые) has zero examples.** None of the 82 checks exercises two competing
  owners. The engine's cross-type form hazard — a SNILS beginning with `8` must not be spliced by
  the PHONE prefix rule (`redact._digits_in_form_of`) — is real and is pinned in
  `test_phone_hop_form.py` (`regression_controls`, "SNILS took the phone prefix rule"), but not in
  this file.
- **fake checksum** is preserved only *by construction* (the `in-identity`/`_card_lengths` checks
  assert digit preservation, which implies checksum preservation), never by a `validate_*`
  assertion. The pinned fakes `085-387-569 19`, `001234567887`, `0123 4567 8901 2347` are all
  **checksum-VALID** (verified against `ru_pii.validate_*`), so the "checksum-INVALID token"
  invariant in `vault.py` is not exercised at all.

## 4. Reproduced gaps (throwaway probes through the real mask/unmask path)

All probes ran through `mask_text` / `unmask_arguments` / `unmask_text` with the real dev bundle,
a real `Detector`, and an ephemeral `Vault` — the production seam, not a stub.

### G1 (REAL DEFECT — C02): malformed `+8` / `++` PHONE becomes a real/fake hybrid

```
mint +79795553322 for real +79162148803, then unmask_arguments of the agent's written form:

  "+89795553322"   -> "+89162148803"     residual=[]
  "++79795553322"  -> "++79162148803"    residual=[]
  "++7 979 555 33 22" -> "++7 916 214 88 03"
```

The real ten digits (`9162148803`) are spliced under the agent's **malformed** country-code sign
(`+8` / `++`), producing a number a dialer/validator refuses. This is exactly the hybrid the
acceptance forbids — "unknown forms remain explicit uncertainty (never a real/fake hybrid)" —
and the same `+8` failure `redact._digits_in_form_of`'s own comment describes ("the customer's
«8» under the agent's «+» … `+8 916…`"). The mask **output** side is pinned
(`test_phone_hop_form.py` asserts `"++" not in result`, `"+8" not in first`), but the
agent→tool **restore** side of these malformed forms is asserted nowhere and is wrong.

### G2 (coverage gap, engine correct — C01): cross-type SNILS-vs-PHONE is handled but not in C01

```
tokenize real "112-233-445 22" as SNILS (fake "805-387-569 27"):
  tool  "80538756927"    -> "11223344522"     (SNILS, not phone-spliced)
  prose "805-387-569 27" -> "112-233-445 22"
```

Engine is correct (a leading-`8` SNILS is not treated as a phone); the assertion lives in
`test_phone_hop_form.py`, not `test_other_hop_forms.py`.

### G3 (coverage gap, engine partial — C02): zero-width Unicode is untested and breaks spoken detection

`normalize` canonicalizes `_ZW_RE` (ZWSP/ZWJ/ZWNJ/BOM) and `_DASH_RE`/`_SPACE_RE`, but **no test
file pins zero-width**. A ZWSP inserted inside a dictated numeral word splits the word, the
numeral run breaks, and `Detector.detect` returns **no spans** for a spoken phone — the number
reaches the model in the clear:

```
"телефон восемь девятьсот два[ZWSP]дцать шесть пятьсот сорок семь восемьдесят два тридцать восемь"
    -> detect() == []   (no PHONE span; the run broke at the zero-width space)
```

### G4 (coverage gap — C02): spoken EMAIL and spoken PLATE are untested

`spoken.email_from_words`, `spoken.detect_spoken_email`, `spoken.plate_from_words`,
`spoken.detect_spoken_plate` are part of the C02 code surface (and wired into `detect_all`) but
have **no test in either C02 file and no test anywhere**. The functions work
(`email_from_words("ситникова собака мэйл точка ру") == "sitnikova@mail.ru"`,
`plate_from_words("а двести шестьдесят три о ка регион шестьдесят шесть") == "А263ОК66"`), but
the round-trip form behaviour is unpinned.

## 5. Terminal verdict

### C01 — REJECT

`test_other_hop_forms.py` is green (82/82) and covers POSITIVE + AMBIGUOUS + real-content
restoration for all seven in-scope types, but the acceptance clause "каждому типу — положительные,
отрицательные, межтиповые и неоднозначные примеры" is not met:

- **CROSS-TYPE: 0 examples** (missing for all 7 types). Missing named examples:
  SNILS-vs-PHONE (leading `8`); INN-10/12-vs-CARD-vs-PHONE (length overlap); CARD-vs-INN
  (12..19 digits); PASSPORT-vs-INN-10/PHONE (10 digits); DOB-vs-order-date; PLATE-vs-prose
  `от` (the `_PLATE_DENY_LOWER` case); EMAIL-vs-LOC/NAME local part.
- **NEGATIVE: generic only** (4 CONTROL checks). Missing per-type negatives: a checksum-failing
  11-digit SNILS look-alike stays; a non-Luhn 16-digit run stays; a lower-case plate-denied word
  stays.
- **fake checksum** never asserted; pinned fakes are checksum-valid, so the "checksum-INVALID"
  invariant is not exercised.

No engine defect was found behind the C01 gaps (G2 shows the one cross-type form hazard is
already handled and pinned elsewhere); the rejection is coverage, not behaviour.

### C02 — REJECT

`test_spoken_date_form.py` (7/7) + `test_spoken_identifier_form.py` (114/114) are green and cover
spoken↔written, noise (`эээ`), digit regroup/leading-zeros/case, and one explicit-uncertainty
case (internal hesitation → numeric fallback). But:

- **REAL DEFECT (G1):** malformed `+8` / `++` PHONE on the agent→tool restore leg yields a
  real/fake hybrid (`+89795553322 → +89162148803`, `++79795553322 → ++79162148803`) instead of
  explicit uncertainty. These inputs are "assigned here" and are neither tested nor correct.
- **homoglyph** transformations not pinned in C02 (live in `test_phone_hop_form.py` +
  `test_atomic_form_adversarial.py`).
- **Unicode** (zero-width/soft-hyphen/dash) not pinned anywhere; G3 shows zero-width breaks
  spoken detection to an unmasked leak.
- **spoken EMAIL and spoken PLATE** untested (G4).
