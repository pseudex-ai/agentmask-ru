## Корень

**Адрес в движке — одна СТРОКА, а не набор ролей.** Роли города/улицы/дома/квартиры посчитаны (`morph_places.split_roles`) и даже используются, но **не участвуют ни в чеканке, ни в возврате, ни в ключе**: ключом служит `address_key` — свёртка всей строки (город + основы улицы + **все** цифры, `morph_places.py:665-681`), а родовое слово (`street_type`) вообще не роль, а **позиция**: восстановитель берёт тип из НАЧАЛА написанной агентом строки (`_leading_generic`), и если агент написал «Барбарисовый бульвар» (название первым — а именно так и пишется минтимая подмена), типа нет ни у подмены, ни у настоящей улицы.

Три следствия одного корня, и они объясняют все три формулировки класса:

1. **Тип теряется, потому что он «позиция», а не «роль».** `_street_like` выкидывает из настоящей улицы **все** родовые слова и возвращает тип только если он стоял первым у агента (`morph_places.py:1683-1686`). Обе ноги (IN: подмена в форму клиента, OUT: настоящее в форму агента) идут через эту функцию, поэтому теряется симметрично: клиенту показывают «Барбарисовый» вместо «Барбарисовый бульвар», инструменту отдают «Светлый» вместо «Светлый переулок» — то есть в Казани «переулок Пушкина» и «улица Пушкина» становятся неразличимы для CRM.
2. **Одна улица → N подмен, потому что ключ несёт ДОМ.** `address_key` по построению различает `9`, `9а`, `11` (доккомментарий сам это декларирует: «House 42 flat 118 and house 118 flat 42 are different addresses»). Правило-лекарство есть — `_same_street_in_conversation` («одна настоящая улица в диалоге — одна подменная»), но оно (а) пропускает ровно ту строку, чей ключ совпал (`vault.py:3874`), а ключ совпадает именно у пары «9/9а», потому что `street_house_key` **срезает литеру** (`morph_places.py:838-839`), и (б) сдаётся, если для одной основы уже стоят две разные подменные улицы (`vault.py:3882`) — то есть одна осечка отравляет улицу до конца разговора (g06: 4 подмены).
3. **Два дома → одна подмена, потому что ключ теряет литеру.** `address_key` выкидывает слова из `_PREPOSITIONS` (`morph_places.py:573-574`), а `_PREPOSITIONS` (`morph_places.py:488-490`) содержит «в», «с», «к», «о» — то есть ровно те буквы, которыми пишут литеру дома. `canonicalize('толстого 34 в') == 'толстой 34' == canonicalize('толстого 34')` — дальше уже **никакое** сравнение не может отличить 34в от 34: проверенный факт, `'толстого 34 в'` + `'г Краснодар, ул Толстого, д 34'` получают один подменный адрес целиком.

Плюс четвёртая грань, которая делает дефект **невидимым**: частично восстановленный адрес — это не «отказ», а тихая смесь. Ключ целой подмены не равен ключу упоминания, из которого выпала часть (`match_signature` склеивает ВСЕ цифры: `полевой|сортавала|1730` против `полевой|сортавала|17`), поэтому включается фрагментный путь, а он требует, чтобы **каждая** часть написанной фразы нашлась в `token_parts` — где настоящего города нет по построению (`vault.py:2933-2941`). Написанная фраза с городом не резолвится целиком, резолвится окно покороче — улица; дом остаётся подменой, а `residual` молчит, потому что дом в 2 цифры не предлагается ни одним вопросом сигнала.

## Механизм (файл+строки)

### Б-1. Тип улицы: `_leading_generic` вместо роли

Ветка: `redact._unmask` (`redact.py:793`) → `redact._restore_inflected_candidates` (`redact.py:1808`) → `redact._in_case_of` (`redact.py:2192`, LOC-ветки `2225` и `2239`) → `morph_places.in_form_of` (`morph_places.py:1689`) → цикл ролей (`morph_places.py:1725-1734`, строка `1732-1734`: `role == "street"` → `_street_like`) → `morph_places._street_like` (`morph_places.py:1660`) → `morph_places._leading_generic` (`morph_places.py:1647-1657`).

Решающие строки — `morph_places.py:1683-1686`:

```
named = [w for w in words if not is_generic_word(w)]     # тип ВЫБРОШЕН из записи
real_name = " ".join(named) if named else street
agent_marker = _leading_generic(model)                   # тип только С НАЧАЛА строки агента
result = f"{agent_marker} {real_name}" if agent_marker else real_name
```

Проверено прямым вызовом: `_street_like('Светлый переулок', 'Барбарисовый бульвар') == 'Светлый'`; `_street_like('Светлый переулок', 'бульвар Барбарисовый') == 'бульвар Светлый'`; `_leading_generic('Барбарисовый бульвар') == ''`.

**Та же функция работает на ноге МАСКИРОВАНИЯ** — `redact._token_for_text` (`redact.py:321`: `shown = morph_places.in_form_of(agreed, span.value)`), поэтому модель и видит подмену без типа (`г Торжок, Барбарисовый, д 3, кв 12` вместо `…Барбарисовый бульвар…`). Это не два дефекта, а один: тип улицы не имеет роли, а позиция «название первым» — обычная для подмены (`_fake_place`, `vault.py:1309-1319`: для `проспект`/`бульвар` голова собирается как `<название> <тип>`).

**Почему это не «подгон под кейс»:** правило уже сформулировано в доккомментарии `_street_like` («тип улицы — содержимое: клиент либо написал „улица", либо нет»), но реализована только одна половина — «если АГЕНТ написал тип в начале». Рядом, на той же роли `street`, живёт **противоположная** реализация: `morph_places.part_in_form_of` (`morph_places.py:1514`, ветка `1529-1539`) возвращает часть записи **как есть**, то есть тип записи сохраняет. Два потребителя одной роли расходятся правилом.

**Роль `street_type` отсутствует в модели полей.** `morph_places.FIELD_ROLES` (`morph_places.py:1457-1465`) знает `street/house/flat/entrance/floor/city` и не знает типа; `field_role` (`morph_places.py:1469-1475`) режет имя по `_` и ищет слово целиком, поэтому:
* `field_role('street_type') == ('street','street')` — лист ТИПА спрашивается как лист УЛИЦЫ (в пробе он получил всю настоящую улицу `светлый переулок`, тогда как `street` получил `светлый` — одна и та же улица уехала в инструмент дважды);
* `field_role('address.street') == ('','')` — точечный путь (`courier_book.address.street`, g02) не роль вовсе, лист не попадает в соединение адреса (`redact.py:2600-2602`) и восстанавливается одиночным текстовым проходом, то есть через `_street_like`.

### Б-2. Одна улица → N подмен: ключ несёт дом, а правило-лекарство пропускает совпавший ключ

* Идентичность: `vault.canonicalize` LOC-ветка (`vault.py:276-282`) → `morph_places.address_key` (`morph_places.py:540-681`), город + основы + все цифры (`665-681`). «9» и «9а» — **разные** строки `tokens`.
* Лекарство: `Vault._same_street_in_conversation` (`vault.py:3836-3882`) возвращает подменную голову, найденную среди `place_parts` по основе улицы, и передаётся в `_fake_place(original, head)` (`vault.py:1263`, `1299-1319`) — тогда меняются только числа.
* Провал: `vault.py:3874` — `if stored == part or not _street_stems_match(...): continue`. Для «9а» `street_house_key == 'депутатский 9'` (`morph_places.py:838-839` срезает приклеенную литеру) и **равен** сохранённому ключу дома 9, поэтому кандидат пропускается; единственный путь, который умеет равный ключ, — `_same_place_written_differently` (`vault.py:3884`) — требует ТОГО ЖЕ дома (`_same_house`, `vault.py:951-954`, `3914-3915`) и отказывает. Затем `vault.py:3882`: `next(iter(heads)) if len(heads) == 1 else ""`.
* Каскад: после второй подменной улицы на ту же основу `len(heads) != 1` навсегда, и все следующие дома этой улицы получают **новую** улицу.

Проверено на движке (публичный путь): дома `9, 9а, 11` → три разные подменные улицы; контроль без литеры (`9, 11`) → одна улица, разные номера.

### Б-3. Два дома → одна подмена: литера дома теряется в ключе идентичности

`morph_places.address_key:573-574`:

```
stripped = " ".join(word for word in phrase.strip().split()
                    if word.strip(",.").casefold() not in _PREPOSITIONS)
```

`_PREPOSITIONS` (`morph_places.py:488-490`) = `{на, в, во, по, с, со, у, до, от, из, за, к, ко, о, об, при, около}`. «в», «с», «к», «о» — и предлоги, и буквы литеры. Проверено:

```
canonicalize('толстого 34 в') == 'толстой 34'      # литера съедена как предлог
canonicalize('толстого 34в') == 'толстой 34в'      # приклеенная выжила
street_house_key(...)  в обоих случаях == 'толстой 34'
```

Приклеенная форма в ключе выживает, но `street_house_key` срезает и её (`838-839`) — а этот «терпимый» ключ используется как **кандидатный** ещё в трёх местах (`_same_place_written_differently` `3905`, `_linked_place` `3998`, `_extends_linked_place` `4047`). Решение о связывании принимается по `_house_identity` (`vault.py:957-974`, литера сохранена) — машинерия верная, но на отдельно написанной литере она уже получила испорченный канон.

Итог по g06 P4/`search_rank-008`: короткое упоминание `толстого 34 в` (канон `толстой 34`) вырастает в полное `г Краснодар, ул Толстого, д 34` через `_extends_linked_place` (`vault.py:4026-4070`) — **одна подмена на два разных дома**, и агент, выбрав строку, совпавшую с адресом заказчика, отправил курьера на 34 вместо 34в. Проверено: `A → 'ивовая 80'`, `B → 'г Краснодар, ул Ивовая, д 80'`.

### Б-4. Частичное восстановление: фрагмент требует настоящий город и молчит о доме

* Точный ключ: `vault.place_key` (`vault.py:635-648`) → `morph_places.match_signature` (`morph_places.py:1049-1065`) = `"|".join(sorted(stems)) + "|" + "".join(digits)`. Упоминание без части по построению имеет **другой** ключ (проверено: `полевой|сортавала|1730` против `полевой|сортавала|17`) — точного попадания нет.
* Фрагментный путь: `redact.py:1933-1934` (`_residual_owner(...) or _place_fragment(...)`) → `Vault.place_owner` (`vault.py:3142-3184`) → `_place_fragment_owners` (`vault.py:3186-3202`) — пересечение по **всем** частям.
* Настоящий город в `token_parts` не индексируется намеренно (`vault.py:2933-2941`: «The settlement is REAL, so it is not a piece of the fake»). Поэтому любая написанная фраза, где город остался, обнуляет ответ. Проверено:

```
tokens.token = 'Сортавала, улица Родниковая 25, кв. 202'
place_owner('улица Родниковая')            -> 'Сортавала, улица Родниковая 25, кв. 202'
place_owner('Сортавала, улица Родниковая') -> None
```

* Следствие: целое окно не резолвится, резолвится окно без города и без числа — только улица. `in_form_of` вписывает настоящую улицу в окно, остальное остаётся как написано: `сортавала, улица лавандовая, 52` → `сортавала, улица вольная, 52`. **Стоит убрать город — та же фраза резолвится целиком** (`улица лавандовая, 52` → `улица вольная, 75`). Это чистая ошибка механизма, а не выбор: город записи заведомо наш, а фрагмент требует его как «часть подмены».
* Молчание сигнала: `surviving_substitutes` (`redact.py:2885`) берёт кандидатов по вопросам — `asked.address_parts` (ключ поля/подсказка), `_NUM_RUN` (`redact.py:23`, требует 7+ знаков) и `_still_a_whole_value` (`redact.py:3217`, порог 3 цифры). Дом `17`/`52` не предлагается ни одним, поэтому остаётся в инструменте без строки в `residual_tokens` — ровно то, что g08 назвал «дом 22 остался подстановкой, `residual {}`».

## Подход как грамотно

Массовое правило: **адрес — НАБОР РОЛЕЙ; форма принадлежит тому, кто написал, содержание — записи клиента; ключ тождества и ключ связывания — разные ключи.** Семь правок, каждая общего характера (ни одна не упоминает кейс):

1. **`split_roles`/`role_spans` получают роль `street_type`.** Одна читалка (она уже объявлена единственной) отдаёт `street` = название, `street_type` = родовое слово + его позиция, `street_phrase` = фраза для тех, кому нужна фраза. `FIELD_ROLES` (`morph_places.py:1457-1465`) получает `street_type`/`type`, а `field_role` (`1469-1475`) читает имя токенами (по `_`, `.`, camelCase) — тогда `street_type`, `streetType`, `address.street`, `address.street_type` находят свою роль. Почему: без роли «тип» любой потребитель обязан угадывать его по позиции, а позиция — оформление.
2. **Один рендерер части «улица»** — `street_in_form_of(record_part, agent_part, role)`: наличие и слово типа берутся из ЗАПИСИ (клиент написал тип или нет), маркер (ул./улица/пр-т), его позиция (до/после названия), падеж и регистр — от писавшего. `_leading_generic` (`morph_places.py:1647`) заменяется чтением по роли, ветка «тип только с начала» в `_street_like` (`1683-1686`) исчезает, `part_in_form_of` (`1529-1539`) и `in_form_of` (`1732-1734`) ходят в один рендерер. Почему: сейчас две функции одной роли реализуют противоположные правила, и от выбора пути зависит, доживёт ли «переулок» до CRM. Это ровно та симметрия IN/OUT, которую класс А требует для PHONE/даты — здесь она нужна на уровне ЧАСТИ.
3. **Два ключа с разными именами и разными обязанностями.** `place_identity(...)` — город, основа улицы, родовое слово, дом с литерой, квартира (всё, что различает два места); `place_link_key(...)` — то, чем два написания ОДНОГО места встречаются (город + основа улицы + числа, без типа и без литеры). Инвариант: ключ тождества **никогда** не используется как кандидатный, ключ связывания **никогда** — как тождество; решение о связывании всегда берётся на тождестве (`_house_identity` — уже так). Почему: сегодня один `address_key` служит обоим, и обе ошибки класса — «одна улица, N подмен» и «два дома, одна подмена» — растут из подмены вопроса.
4. **Литера дома — часть тождества в обеих записях.** `34в` и `34 в` — один дом; `_PREPOSITIONS` выкидывается только там, где предлог синтаксически возможен (перед городом/улицей), и **никогда** после числа. Почему: буква после числа — литера по построению, а «в/с/к/о» — предлоги и буквы одновременно; сейчас ключ молча сливает разные дома.
5. **Правило переиспользования головы перестаёт пропускать совпавший ключ** (`vault.py:3874`): равный терпимый ключ — это «та же улица», и различать надо СОСЕДНИЕ дома тождеством, а не пропуском; отказ `len(heads) != 1` (`3882`) обязан быть не приговором улице, а решением по каждому дому (переиспользовать голову может любой дом той же основы, если подменная улица для основы ровно одна; две — уже отказ, как сейчас). Почему: одна осечка сейчас отравляет всю улицу разговора.
6. **`place_owner` спрашивает только те части, которые МОГУТ опознать подмену.** Город записи не индексируется как часть подмены by design (`vault.py:2933-2941`) — значит пересечение не имеет права его требовать: либо город исключается из вопроса, либо индексируется отдельным признаком «настоящее совпало». Почему: один настоящий город в написанной фразе сейчас обнуляет весь ответ, и адрес распадается на «улица настоящая + дом подменный».
7. **Остаток называется, и называется числом.** Кандидатом в `surviving_substitutes` обязан становиться числовой компонент адресного прогона, который восстановление пыталось и не смогло отобразить (короткое число тоже: дом `17`), а листья схемы складываются ДО свободного окна — лист, чья роль объявлена именем поля, восстанавливается соединением (`_join_address_fields`/`place_owner_of_whole`), а не одиночным `_unmask`, иначе починенный лист выпадает из `fragments` (`redact.py:2602`) и соединение его больше не видит. Почему: смесь «настоящая улица + подмена-дом» сегодня уезжает в инструмент с кодом 200 и пустым журналом — это порча данных, а не отказ.

**Заодно для прибора (класс Е/Ж, но здесь же):** сравнение LOC — по ролям (набор ролей + значения, `street_type` отдельным признаком), иначе потеря родового слова читается как потеря значения и «настоящий промах» смешивается с «тип не перенесён».

## Риски

* **Пере-ключевание персистентного волта.** `tokens` живёт через рестарты; смена `address_key` делает уже отчеканенные строки недостижимыми по новому ключу (подмена есть, владельца нет). Нужен шаг миграции или решение «старые ключи живут до конца беседы»; `test_schema.py` + `schema_lock.json` держат контракт номера схемы.
* **Раскол одного места на два.** Родовое слово в тождестве (развилка ниже) означает, что «Светлый переулок 12» и «Светлый 12» — две строки и две подмены: это ровно тот класс, который лечим. Связывание обязано закрыть это правилом (п. 3/5), иначе правка сделает хуже.
* **Слияние двух мест в одно.** Обратная сторона: вернуть тип связыванию — и «переулок Пушкина» с «улица Пушкина» получат одну подмену, то есть курьера отправят не туда. Это и есть цена развилки, и она должна быть решена владельцем, а не кодом.
* **Маскировочная нога двигает то, что видит модель.** `_street_like` вызывается и на IN (`redact.py:321`), поэтому правка меняет показываемую подмену; замер — тем же замороженным скорером и внешними корпусами, не своим набором.
* **Сигнал остатков пойдёт вверх (ложные тревоги).** Доккомментарий `surviving_substitutes` (`redact.py:2894-2901`) документирует 10 ложных из 21 на прошлой попытке «спрашивать по форме». Расширять кандидатов можно только по вопросу, который называл сам текст (роль поля/адресный прогон), и мерить `residual` на контрольных парах.
* **`_PREPOSITIONS` общий.** Сужение списка двигает не только ключ: им пользуются `address_key`, `_has_city`, разбор города. Правку надо делать локально (правило «после числа»), а не правкой списка.
* **Гварды спринта.** `test_overmasking` 99.5%, `wiki/check` 0, холдаут не тронут; `pseudex/` не импортирует `licensing/` и `sqlite3`; ошибка маскирования — 5xx, не проброс.

## Методологическая развилка

Считать ли родовое слово частью **тождества** адреса — то есть «переулок Пушкина» и «улица Пушкина» это два разных места, которым положены две разные подмены (а одно место, написанное с типом и без него, связывается отдельным правилом), — или тип это оформление, одна подмена на место, и тогда «переулок Пушкина» и «улица Пушкина» получают одну подмену и различить их в CRM уже нечем?
