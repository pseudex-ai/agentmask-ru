# SPRINT-BRIEF: Качество и стабильность для продакшена

Binding-контракт следующего спринта. Читать буквально, подчиняться, не пере-планировать.

## Цель (одна, передаётся всем агентам)

Максимум качества и стабильности pseudex для **продакшена на любых кейсах и для любых агентов**. Лечить болезни **массово** — правилом/механизмом движка, а не костылём под конкретный кейс. После спринта мы должны быть максимально уверены в продакшен-пригодности, спокойно допиливать фичи и катить релиз.

## Источники истины (binding)

- `research/hop-format-audit/DIAGNOSIS.md` — 7 системных классов А–Ж, ранжирование, рефрейм.
- `research/hop-format-audit/agents/gNN-*.md` — per-семейство разборы «глазами» (кейсы-свидетели).
- `research/hop-format-audit/agents/00-case-metrics.json` — per-case метрики.
- Не пере-исследовать, не пере-скопить, не пере-планировать. Классы и свидетели берутся оттуда.

## Рефрейм (читать перед всем)

Headline `end_to_end 41% / chain 36% / multi_all_out 12%` не измеряют движок: в знаменателе сидят `absent` (агент не написал) и `unmasked` (движок осознанно не маскировал — город, часть адреса). Реальное восстановление движка ≈90–96%. Поэтому класс **Е (прибор) идёт ПЕРВЫМ** — он развязывает знаменатели, иначе правки движка не измеримы.

## Классы (А–Ж) и зачем каждому спайк

Спайк нужен потому, что DIAGNOSIS даёт симптом + гипотезу, а для «как грамотно» нужен ТОЧНЫЙ механизм (файл+строка) и корректный подход. Спайк = воспроизвести симптом RED-тестом → проследить механизм → спроектировать массовое правило → выявить методологическую развилку (если есть) → вопрос владельцу.

- **Е — прибор/корпус смешивает причины.** Разделить `absent`/`unmasked`/настоящий промах в знаменателе; недостижимые обязательные хопы → optional; синонимы листьев; нотационно-устойчивое сравнение. Спайк: где в `observe.py`/`metrics.py`/`contracts.py` считаются статусы и знаменатели.
- **А — нотация не симметрична.** Подмена не наследует нотацию источника (диктовка↔письменная, регистр/разделители PLATE, латиница↔кириллица), восстановление не рендерит в нотации агента. Механизм есть для PHONE/даты/SNILS — надо обобщить. Спайк: карта `date_form.render_like`/`_phone_in_form_of`/`spoken`/`agent_form` и чего нет для PLATE/LOC/латиницы.
- **Б — адрес не компонуется.** street_type теряется; ключ адреса по всей строке (одна улица → N подмен, два дома → одна подмена); частичное восстановление (дом остаётся фейком). Спайк: `morph_places.address_key`/`street_house_key`/`split_roles` + путь восстановления в `redact.py`/`vault.py`.
- **В — собственная подмена перечеканивается.** Ответ модели передетектируется → «три личности». Спайк: где чеканится повторно (own-substitute/own-rendering в `envelope.py`), как сделать идемпотентным.
- **Д — тихое усечение цифр.** Подмена «00…», модель снимает нули → инструмент получает 10 из 12 настоящих цифр, residual пуст. Спайк: `vault.resolve_digit_signatures` + невозможные префиксы.
- **Г — утечки.** Латиница наполовину, голое слово после предлога, `passport.*` вложенный, коллизия частей, телефон-СНИЛС. Спайк: по каждому вектору отдельно (или один с подчастями).
- **Ж — сравнение не нотационно-устойчиво.** Прибор наказывает за разделители/порядок/скрипт. Спайк: `metrics.value_matches`/`part_matches`/`script` признак.

## Фазы и гейты

**Фаза 0 — СПАЙКИ (параллельно, 7 flash-субагентов, по одному на класс).**
Каждый: читает DIAGNOSIS + свои агент-артефакты + код; пишет RED-тест (self-contained, без модели/сети), воспроизводящий симптом; прослеживает механизм (файл+строка); пишет `research/hop-format-audit/SPIKE-<КЛАСС>.md`: корень, подход «как грамотно» (массовое правило), RED-тест, затронутые модули, риски, методологическую развилку (если есть) как вопрос владельцу.
**ГЕЙТ 0:** RED-тест реально воспроизводит симптом; `SPIKE-*.md` заполнен; развилки сформулированы.

**Фаза 1 — МЕТОДОЛОГИЧЕСКИЕ ОТВЕТЫ (последовательно, владелец).**
Каждую развилку из спайков — через ask_user_questions; ответ владельца → `research/hop-format-audit/DECISIONS-SPRINT.md`.
**ГЕЙТ 1:** каждая развилка закрыта решением владельца (нет открытых).

**Фаза 2 — РЕАЛИЗАЦИЯ (Е ПЕРВЫМ, затем А,Б,В,Д,Г,Ж параллельно; flash-субагенты).**
Е развязывает измерение. Каждый класс — массовое правило, TDD RED→GREEN, атомарный коммит на класс, тип честный (`deploy/lint_engine_commits.sh`).
**ГЕЙТ 2:** RED→GREEN; полный батл зелёный; гарды `test_overmasking 99.5%` + `wiki/check 0`; холдаут не тронут; детекция — по дисциплине detect-change (замер ДО/ПОСЛЕ, позитивы+негативы).

**Фаза 3 — ВЕРИФИКАЦИЯ (последовательно).**
Полный батл + офлайн parity-свип (834 → 0) + перепрогон кейсов-свидетелей + сравнение метрик до/после (по написанным листьям, не headline).
**ГЕЙТ 3:** всё зелёное; parity 0; метрики round-trip по observed∪unmasked выросли; отчёт о до/после.

## Правила (hard invariants)

1. Холдаут (359) НЕ трогать. Неотпрогоненные (628) не обязательны.
2. МАССОВО: правило/механизм, не подгон под кейс. Свидетель = подтверждение правила, не цель.
3. `pseudex/` не импортирует `licensing/` и `sqlite3`.
4. Fail-closed: ошибка маскирования → 5xx, никогда проброс в открытую.
5. Замороженный скорер `agentpii3/score.py` — трогать только если владелец явно решил.
6. Каждая правка детекции — по detect-change (воспроизвести → замерить ДО → менять узко → позитивы+негативы → замерить ПОСЛЕ; просел — откатить).
7. Никакого overclaim: гейт красный → HALT и честный отчёт, не поднимать статус, не выдавать непроверенное за результат.

## Формат работы

- Субагенты — **flash** (deepseek-flash). Параллельно где независимы, последовательно где есть зависимость (Е → остальное; фазы 0→1→2→3).
- Каждый субагент сам читает DIAGNOSIS.md + свои артефакты + SPIKE-*.md + код (не переспрашивает, не ждёт копирования).
- Артефакты субагента обязательны и проверяемы: SPIKE-*.md, RED-тест, коммит с цитатой теста.
