## Механизм каждого класса

### A. Предохранитель `place_key` отбивает БЕЗУПРЕЧНОЕ зеркало (1 случай, 4 %)

`prototype/pseudex/redact.py:250-253`:

```python
agreed = _agree_settlement(token, span.value)
shown = morph_places.in_form_of(agreed, span.value)
if shown and place_key(shown) == place_key(agreed):
    return shown
return agreed
```

`place_key` (`prototype/pseudex/vault.py:536` → `morph_places.match_signature`,
`morph_places.py:936`) — это отсортированные ЛЕММЫ всех слов плюс все цифры,
с выброшенными родовыми словами (`_GENERIC_STEMS`, `morph_places.py:989`) и
структурными маркерами (`_SIGNATURE_NOISE`, `morph_places.py:1015`). В списке
шума есть «ул», «наб», «б-р», «д», «кв» — и **нет «г»**. Поэтому:

```
place_key('г. Ачинск, б-р Озёрный, д. 78, кв. 105') = 'ачинск|г|озёрный|р|78105'
place_key('Ачинск, б-р Озёрный 78, кв. 105')        = 'ачинск|озёрный|р|78105'
```

Зеркало у `create_order-clean-009` было ИДЕАЛЬНЫМ — в нём нет ни одного
настоящего слова клиента, только фейк и его же маркеры, — но ключи разошлись на
лишней основе `г`, и модели показали канон «Ачинск, б-р Вишнёвый 30, кв. 31»
вместо «г. Ачинск, б-р Вишнёвый, д. 30, кв. 31». Переписчику нечего было
чинить, он скопировал, обратно вернулась сырая строка клиента, а бенчмарк ждал
переписанную.

**Свойство, ради которого предохранитель стоит, — «ни одно настоящее слово не
уцелело в показанном»**; `place_key` был его прокси, и прокси врёт в обе
стороны: тут он отбил безопасное, а маркер «г.» он же и породил.

### B. Замороженный родительный улицы прочитан как косвенный падеж (8 случаев, 32 %)

`prototype/pseudex/redact.py:226`:

```python
case = morph_places.detect_case(span.value)
if case is None or case == "nomn":
    ...зеркало формы клиента...
return morph_places.inflect_place(token, case)
```

То есть **зеркало формы вообще не пробуется**, когда `detect_case` сказал
«косвенный». А `detect_case` (`morph_places.py:293`) решает по родовому слову, и
у маркерless-улицы родового слова НЕТ — тогда он падает в голосование по всем
словам (`morph_places.py:329-337`), где название улицы вида «Чернышевского»,
«Заболоцкого», «Комиссаров», «Терегулова» голосует за родительный/винительный.
Но для улицы, названной по человеку, родительный — это её КАНОНИЧЕСКАЯ форма, а
не падеж предложения:

```python
morph_places.detect_case("заболоцкого 81 кв 51")    # 'gent'
morph_places.detect_case("чернышевского 29 кв 52")  # 'gent'
morph_places.detect_case("комиссаров 56 кв 28")     # 'accs'
morph_places.detect_case("Тверской 7")              # 'gent'  ← а вот это ПРАВДА косвенный
```

Та же ловушка в файле уже описана дважды и оба раза закрыта частично:
`morph_places.py:299-305` («сокращённый маркер — это запись, а не предложение» →
`nomn`) и `morph_places.py:325-326` (у родового слова «nomn» бьёт «accs»). Ни
одно из двух правил не достаёт до фразы БЕЗ маркера и БЕЗ родового слова — то
есть до чатового регистра, который и есть основной трафик.

Результат для клиента: показывается «улицы Вязовой 59, кв. 127» — причёсанный
канон в родительном. Переписчику нечего нормализовать, он копирует, и
`_restore_verbatim_spans` отдаёт сырую строку клиента «глазов чернышевского 29
кв 52», тогда как агент без нас написал бы «Глазов Чернышевского 29 кв. 52».
Класс проявляется целиком как несовпадение ФОРМЫ.

### C. Свёрнутый гомоглиф возвращается «починенным» (10 случаев, 40 %)

Самый большой класс, и он не про улицы вовсе. Клиент пишет «ваcи алексеева» с
латинской `c`, «меpецкова» с латинской `p`, «задунaйская» с латинской `a`.
Детектор читает НОРМАЛИЗОВАННЫЙ текст (Layer 0), волт хранит свёрнутое значение,
и когда агент ПЕРЕПИСАЛ показанное (а rewriter переписывает всегда), путь
`_restore_verbatim_spans` не срабатывает — форма пересобирается из содержимого
волта, то есть из свёрнутой строки. В инструмент уходит «улица Васи Алексеева
д. 36 кв. 179» вместо «улица Ваcи Алексеева д. 36 кв. 179».

Бенчмарк считает это `normalised=True` и печатает отдельной строкой
`round_trip_repaired` (95.1 %) — ровно затем, чтобы это не смешивали с потерей.
`docs/known-issues.md:1257` («Что НЕ чинится») называет нормализацию гомоглифа
политикой. Но вторая половина Б24 («Дословно — значит дословно») уже установила
обратный принцип и механизм под него — `Vault.shown_forms` помнит на диалог
БУКВАЛЬНЫЙ срез исходного текста (`redact.py:78-85`). Сегодня этот буквальный
срез читает только путь дословной копии; путь пересборки формы его не видит.

### D. Нумерованная улица разобрана как дом (2 случая, 8 %)

`morph_places.role_spans` (`morph_places.py:1136`) берёт домом ПЕРВОЕ число,
которое не забрал ни один маркер (`morph_places.py:1163-1172`). Порядковый
префикс названия — такое же число:

```python
morph_places.split_roles("г. Балашов, ул. 3-я Победиловская, д. 77, кв. 113")
# {'city': 'Балашов', 'street': 'ул', 'house': '3', 'flat': '113'}
morph_places.split_roles("г. Киров, пр-д 4-й Вешняковский, д. 38, кв. 77")
# {'city': 'Киров', 'street': 'пр-', 'house': '4', 'flat': '77'}
```

Отсюда две разных поломки от одной причины.

*Плечо чеканки:* `in_form_of` (`morph_places.py:1533`) режет строку клиента по
этим же ролям и вставляет части фейка внутрь, поэтому получается

```
in_form_of('Киров, улица Родниковая 8, кв. 105',
           'г. Киров, пр-д 4-й Вешняковский, д. 38, кв. 77')
→ 'г. Киров, родниковаяд 8-й Вешняковский, д. 38, кв. 105'
```

— настоящий «Вешняковский» и настоящий дом «38» остались бы стоять. Тут
предохранитель `place_key` срабатывает ПРАВИЛЬНО и показывает канон; это
единственная его настоящая работа во всём корпусе, и именно она описана в
коммит-сообщении `915a365`. Цена — переписчику нечего нормализовать (см. класс B).

*Плечо инструмента:* схема `decompose` просит `street`/`house`/`flat` по
отдельности, и `decompose-clean-010` получил `{"street": "ул. Ул", "house": "3",
"flat": "113"}` — то есть мусор в CRM, а не просто иную форму.

### E. Улица без дома перехватывает поле чужого диалога (≈1.7 случая, 7 %)

Это класс, которого в заметке нет, и он единственный здесь — **раскрытие данных
одного диалога в инструменте другого**, а не расхождение формы. Механизм —
прямое следствие Б16.

`create_order-clean-010` пишет «наб. Ольгина пруда, 119, кв. 234», детектор
берёт «наб. Ольгина» (второе слово названия и дом — снаружи), и волт чеканит
**вырожденный токен без единой цифры**: подмена «наб. Каштановая», ключ
`каштановый|`. Другой диалог того же заказчика получает на свой адрес фейк с тем
же названием улицы, агент кладёт в поле `street` строку «Каштановая», а
`Vault._lookup_typed` (`prototype/pseudex/vault.py:3589-3607`) ищет по
`name_key` **без области разговора** — и отдаёт настоящую улицу первого диалога.

```
$ python3 $CLAUDE_JOB_DIR/tmp/compound-street/repro3.py
A spans  : [('LOC', 'наб. Ольгина')]
A fake   : наб. Каштановая
COLLISION conv-B36
  B masked : … адрес каштановая 55 кв 25 …
  agent street field : Каштановая
  unmask_text(for_tool) : Ольгина          ← настоящая улица ДРУГОГО диалога
  verbatim/tokens/reformatted: []           ← решил _restore_inflected_spans
  place_key(field): каштановый|
  row: ('наб. Каштановая', 'набережная ольгин', 'каштановый|', 'conv-A')
```

`minted_in` у строки ЕСТЬ (`conv-A`), но `_lookup_typed` его не спрашивает.
Для полного адреса это сознательно («один адрес — одна подмена, навсегда»,
`CLAUDE.md`, «Conversation scope»); для ключа без цифр — это ровно тот класс,
который Б23 закрыл для имён (`wiki/INVARIANTS.md#conversation-scope`, «A PIECE
OF A SUBSTITUTE RESOLVES ONLY IN A DIALOGUE THAT WAS SHOWN THE WHOLE»).
В бенчмарке это 1–3 случая за прогон (`decompose-chat-024`, `-027`,
`decompose-sloppy-031`) и главный источник разброса базового числа.

### F. Б16 как причина round_trip (2 случая, 8 %)

Остальные одиннадцать из тринадцати частично покрытых адресов **круг проходят**:
потерянное слово агент видит сырым и переписывает его так же, как переписал бы
без нас, а маскированный хвост возвращается в его форме. Ломаются два:

* `decompose-chat-018` «улица 5-й армии д62 кв149» — спан РАЗОРВАН на «улица 5»
  и «д62 кв149», и в поле `street` уезжает `"улица 5-й Армии улица д62 кв149"`:
  наше «улица» приклеено к сырому хвосту клиента.
* `create_order-sloppy-051` «литвина-седого 39 кв 62» — дефисное составное имя,
  спан берёт только «седого 39 кв 62».

## Что из этого детекция, что чеканка, что восстановление

* **Детекция** — только F (и, косвенно, E: вырожденный токен рождается из
  укороченного спана). Ни один другой класс детекцию не трогает: во всех
  остальных спан правильный, а ломается ФОРМА или АДРЕСАЦИЯ.
* **Чеканка (что показали модели)** — A, B и плечо «показать» у D. Проверяется
  тем, что подмена, показанная в форме клиента, переписывается агентом и
  возвращается его формой; доказательство — колонка `shown` в
  `classify.py` и деление веток в `probe.py`.
* **Восстановление** — C (откуда берётся содержимое), E (в какой области искать
  владельца), плечо «по полям» у D.

## План: шесть шагов, каждый отгружается отдельно

Замеры ниже — rewriter, ADDRESS round_trip, среднее по прогонам; в скобках
разброс и число прогонов. Все патчи — монкипатчи из
`$CLAUDE_JOB_DIR/tmp/compound-street/patches.py`, продового кода не написано.

### Шаг 1 — предохранитель по СЛОВАМ, а не по `place_key`

**Что меняется.** `redact._token_for_text` (`redact.py:250-253`): условие
принятия зеркала — «каждое буквенное слово и каждая цифровая группа показанной
строки принадлежит ФЕЙКУ либо является структурным маркером» вместо равенства
`place_key`. Список маркеров локальный для этой проверки — трогать
`morph_places._SIGNATURE_NOISE` НЕЛЬЗЯ: это индекс волта, и уже отчеканенные
строки хранят старые ключи.

**Инвариант.** `wiki/INVARIANTS.md#swap` («CONTENT FROM THE VAULT, FORM FROM THE
AGENT»); формулируется точнее — «мы никогда не отдаём настоящую часть ради формы».
**Пины сегодня:** `test_hard_cases.py::test_addresses` (`test_hard_cases.py:384`
«every address round-trips back intact»), `test_argument_form.py::_forms_follow`.

### Шаг 2 — замороженный родительный улицы не считается косвенным падежом

**Что меняется.** Общий читатель падежа для УЛИЧНОЙ фразы: если в спане нет
родового слова и нет сокращённого маркера, косвенный падеж принимается только
когда в названии есть **прилагательное женского рода** — единственная форма,
которая согласуется с опущенной «улицей» («улица Тверская» → «на Тверской 7»).
Иначе падежа нет, и работает зеркало. Применяется в ДВУХ местах и только в них —
`redact._token_for_text` (`redact.py:226`) и прозаическое плечо
`redact._in_case_of` (`redact.py:1442`).

**Почему не глобально в `detect_case`.** Измерено: глобальная правка ломает
`test_product.py:1125` — `_agree_settlement` зовёт `morph_places.city_case` →
`detect_case("Валдае")`, и настоящий город перестаёт склоняться: «Живу на
Валдай, улица Еловая 9». Город читается прежним читателем.

**Инвариант.** `wiki/INVARIANTS.md#swap` и `#address`.
**Пины сегодня:** `test_hard_cases.py:386` — `check("no address substitute sits
in the nominative inside an oblique slot", …)`. Это тот тест, который ловит
наивную версию: «зеркалить всегда» даёт «Встретимся на **Сиреневая** 5» и
«Заберите с **Ивовая** 25» — красный, воспроизведён.
**Новый негативный тест:** пара утверждений в `test_hard_cases` — «адрес
чернышевского 29 кв 52» показывается строчным зеркалом без «улицы», а
«Встретимся на Тверской 7» по-прежнему показывается склонённым.
**Риск:** маркерless-улица с МУЖСКИМ прилагательным в косвенном («на
Вешняковском 12») теперь пойдёт зеркалом и даст несогласованную прозу. В нашем
корпусе таких нет; увидит тот же `test_hard_cases` и персона-прогон.

**Замер:** 78.8 % (74.7…81.4, n=5), **+7.7 пп**. Потолок класса (зеркалить
всегда) — 79.6 %, то есть точечное правило забирает класс почти целиком.

**Шаг 2 НЕЛЬЗЯ отгружать без 2b и 2c** — он вскрывает два латентных дефекта,
которые сегодня прикрыты тем, что подмена показывается причёсанной:

* **2b. `_PLACE_RUN` цепляется за «ул» ВНУТРИ слова.** `LOC_TOKEN_PATTERN`,
  ветка сокращений (`prototype/pseudex/vault.py:1484`,
  `rf"|(?i:{abbrs})\.?\s{name}"`), не имеет левой границы слова:

  ```python
  redact._PLACE_RUN.findall("Барнаул Ивовая 55 кв. 132")   # ['ул Ивовая 55 кв. 132']  ← со смещения 5
  redact._PLACE_RUN.findall("Барнаул, Ивовая 55 кв. 132")  # []
  ```

  Сегодня подмена чеканится с запятой после города, поэтому не стреляет; после
  шага 2 клиент пишет без запятой — и `create_order-sloppy-057` возвращается
  **«Барнаонватаняна 50 кв. 86»**. Правка — негативный lookbehind на буквы
  перед сокращением. Это отдельный дефект, он стоит починки сам по себе.
* **2c. Строчная подмена, приклеенная дефисом, не предлагается окном.**
  `_LOWER_WORD` (`prototype/pseudex/redact.py:962`) —
  `(?<![А-ЯЁа-яё-])[а-яё]{2,}(?![А-ЯЁа-яё-])`, дефис в классе исключения
  намеренно (иначе разорвалась бы дефисная фамилия). После шага 2
  `create_order-sloppy-051` показывается как «литвина-осиновая 86 кв 227», агент
  пишет «Литвина-осиновая 86 кв. 227», и **фейк уезжает в инструмент**:

  ```
  _PLACE_RUN / _PLACE_RUN_ANY_CASE на 'Литвина-осиновая 86 кв. 227' → []
  _LOWER_WORD → ['кв']
  ```

  На базе тот же случай возвращал НАСТОЯЩЕЕ значение (в чужой форме). То есть
  шаг 2 без 2c **меняет расхождение формы на фейк в инструменте** — это хуже,
  а не лучше. Правка — то же, что сделал `0e877b3` для двух склеенных подмен:
  дефис предлагает обе половины окнами. Новый негативный тест обязателен.

  туда не проброшен. +10.6 пп — арифметика по разнице `delivered`/`owed`, а не
  прогон.
* **Цена шага 6 на нужном объёме.** 2 691 предложение NEREL prose и 16 521
  реплика MASSIVE — это порядок 1/1000, а бюджет ошибки 12 спанов на 19 456.
  `bench/eval_overmasking_volume.py` не гонялся: корпус пуст.
* **Частота класса E в реальном трафике.** В бенчмарке он рождается из Б16 и
  тянется розыгрышем подмены; как часто заказчик диктует улицу БЕЗ дома в
  проде — неизвестно. Дефект при этом воспроизводится детерминированно
  (`repro3.py`) и не требует Б16: любое упоминание улицы без номера чеканит
  вырожденный ключ.
* **Регистр маркера у `create_order-clean-004`** — не разделено, сколько там
  нашего (`agent_form.cased_like` пословно по строке, где число слов у реальной
  и фейковой роли разное) и сколько артефакта `rewrite_address`.
