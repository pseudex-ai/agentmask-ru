# AgentPII-RU v5 — как им пользоваться

Приватный бенчмарк «шлюз не ломает агента»: три плеча (контроль, контроль′,
шлюз) над теми же задачами, форма значения на каждом хопе, судья по виду
клиента. Никогда не публикуется — ни корпус, ни числа, ни этот каталог.

Что меряется и почему именно так — `docs/tz-agentpii5.md`, `contracts.py`
(нормативный файл) и `RULINGS.md`. Здесь — только как это запускать.

**Одна дверь ко всем командам:**

```bash
cd prototype && source .venv/bin/activate
python3 -m bench.agentpii5 --help            # список команд, по строке на каждую
python3 -m bench.agentpii5 <команда> --help  # аргументы одной команды
```

Модули запускаются и напрямую (`python3 -m bench.agentpii5.compare …`) — дверь
не прячет их, а перечисляет.

**Деньги тратят две команды — `run` и `calibration export --repeats K`.** Все
остальные (`dry-run`, `report`, `compare`, `microscope`, `trend`, `repro`,
`runs`, `quarantine`, `build`, `provider`) читают файлы: ни модели, ни сети, ни
ключа. Что нужно `run`, сказано в рецепте 2; сколько стоят повторы судьи — в
рецепте 6.

## 1. Добавить случаи

Новое семейство — файл в `scenarios5/` и строка в плане. Харнесс не правится.

```bash
# 1) scenarios5/<семейство>.py с build(seed, count) -> list[CaseV5]
# 2) строка (<модуль>, <сколько>) в PLAN_A или PLAN_B (scenarios5/plan_*.py)
python3 -m bench.agentpii5 build --check     # ничего не пишет: проверяет и печатает
python3 -m bench.agentpii5 build             # пишет corpus.v5.json, corpus.json, ladder.json
```

`--check` доказывает четыре вещи: корпус проходит свои правила, ни один
генератор не искал значение в уже собранной строке, НАСТОЯЩИЙ мок рендерит
каждый объявленный хоп, и печатает план, ярусы и мусор корпуса (дубли id —
отказ; мёртвый груз и дубли по составу — счёт с перечислением).

Состав ярусов при этом не двигается: лестница остаётся прежней, обновляется
только штамп (R-57). После первого ЖИВОГО прогона по holdout состав holdout не
перерисовывается вообще — `ladder.json` несёт `holdout_touched_at` и
`holdout_touched_by`, и `--regenerate-ladder` становится отказом.

## 2. Сделать прогон

Сначала — сколько это будет стоить. Оценка строится по РЕАЛЬНЫМ прошлым
прогонам из `runs.json` и называет, на чём она основана:

```bash
python3 -m bench.agentpii5 dry-run --tier medium
```

Потом сам прогон. Из всего, что здесь перечислено, ключ Anthropic
(`ANTHROPIC_API_KEY`, либо `ANTHROPIC_AUTH_TOKEN`) и чистое рабочее дерево
нужны только ему. `--baseline` необязателен, но без него в отчёте не будет
колонки сравнения с v4. `--label` обязательна для всего, что дороже `nano`:

```bash
export ANTHROPIC_API_KEY=…            # значение ваше; в файлы прогона оно не попадает
python3 -m bench.agentpii5 run --tier medium --repeats 1 --ceiling 12 \
    --label "после правки адресов" --note "перепроверить large" \
    --baseline bench/runs/<дата>/v4-live-<ярус>
```

**Ярус — миниатюра корпуса, а не первые N случаев.** Каждый отладочный ярус
повторяет доли пула «корпус минус holdout» по регистру, по поведению и по
v4-семье сразу, с полом в один случай на значение; ярусы вложены по построению
(это префиксы одного стратифицированного порядка). До 23.09.2026 это было не
так — `nano` был 30/30 `voice_raw`, `medium` 300/300, — и приёмка прибора,
которая идёт на `medium`, четырёх регистров из пяти не видела. Состав каждого
яруса печатает `python3 -m bench.agentpii5 build --check`.

**Срез вместо яруса — когда нужен один регистр, одна вертикаль или один тип
ПД.** Оси: `register`, `behaviour`, `vertical`, `pii_type`; несколько значений
одной оси через `|`, разные оси складываются по И:

```bash
python3 -m bench.agentpii5 dry-run --slice register=chat --slice-size 120
python3 -m bench.agentpii5 run --slice vertical=clinic --label "клиника после правки ДР"
python3 -m bench.agentpii5 run --slice register=voice_raw|voice_itn,behaviour=rag --slice-size 40 \
    --label "голос в RAG"
```

Срез **детерминирован** (тот же срез — тот же список случаев, и это видно по
`selection_sha256` в реестре), **холдаута не касается никогда** и записывается в реестр как
`slice:register=chat` с `selection_kind: "slice"`. **Сравнивать срез с ярусом
нельзя**: у них разные множества и разные доли, и разница между их числами —
это разница выборок, а не движка.

**Холдаут читается ровно одним способом — `--tier holdout`, — и это теперь
ОТКАЗ, а не обещание этого абзаца.** `--ids`, назвавший холдаутный случай,
отказан ДО оценки (раньше он проходил молча и настоящий прогон за $0.45 ставил
`holdout_touched_at` навсегда); лестница без яруса `holdout` отказана тоже —
раньше срез по ней печатал «холдаут исключён» над выборкой, в которую холдаут
попадал целиком.

Прогон **откажется начаться**, если: нет метки выше `nano`; в метке ключ или
значение из корпуса; рабочее дерево грязное (снимается `--dirty-ok`, и это
записано в `meta.json` и в реестре); корпус не тот, который знает лестница
(**не снимается ничем** — ярус назвал бы случаи из другого корпуса); объявлен
чужой провайдер или `--gateway` (см. «Чего сегодня нет»).

Прогон **не упадёт**, если провайдер оборвал связь: случай повторяется с
отступом, исчерпав попытки — помечается `terminated: transport`, исключается
из знаменателей и считается отдельной строкой. Остановится он на двух вещах:
исчерпан потолок и сработал стоп-кран по цене (средняя цена случая выше
ожидаемой вдвое — защита от зациклившегося агента).

Отчёт по уже готовому каталогу, без модели и без трат:

```bash
# все четыре файла отчёта разом (текст, гейт, машинный JSON, публичная подстрока):
python3 -m bench.agentpii5 run --report <каталог> --baseline <каталог v4>
# только текстовый отчёт и гейт — зато без движка:
python3 -m bench.agentpii5 report <каталог> <каталог v4>
# пишет report.json и public.json, печатает публичную подстроку:
python3 -m bench.agentpii5 report --public <каталог> <каталог v4>
python3 -m bench.agentpii5 runs list                     # все прогоны строками
python3 -m bench.agentpii5 trend --tier medium           # по датам, и где регресс
```

Если менялся **наблюдатель** (`observe.py`), пересобранный отчёт покажет старые
наблюдения на новых метриках — а разница прочитается как движение движка.
Тогда нужен пересчёт ПЛЕЧЕЙ, и он тоже бесплатен: хопы считаются заново из
записей прогона, ни одного вызова модели.

```bash
python3 -m bench.agentpii5 run --replay <каталог> --baseline <каталог v4>
```

## 3. Сравнить два прогона

Любой с любым — не только «v5 против v4» и не только «до/после»:

```bash
python3 -m bench.agentpii5 compare <A> <B> --cases
```

`--cases` даёт таблицу «случай × строка», отсортированную по величине
ухудшения: кто именно ушёл в красное. Разница по каждой строке идёт с
доверительным интервалом (тот же кластерный бутстрап, что в TOST, с полом
1/n), и «различие не отличимо от нуля при таком n» печатается словами.
`--reps` — тяга бутстрапа, она в шапке, чтобы два сравнения не оказались
сделаны с разным разрешением. Прогоны с разными дайджестами корпуса
сравниваются только с `--across-corpora`, по пересечению id, и это написано в
шапке.

## 4. Повторить чужой прогон

```bash
python3 -m bench.agentpii5 runs show <id|начало id>
python3 -m bench.agentpii5 repro <id|начало id>
```

`repro` печатает ОДНУ команду: корпус и его дайджест, ярус, сиды, модели с их
id, версия движка, имена (не значения) переменных окружения. Чего сегодня нет —
сказано отдельной строкой, с тем, чем это заменить. Состояние дерева читается
как его записал прогон: чистое — «числа привязаны к этому коммиту», грязное или
незаписанное — строкой в «что изменилось».

## 5. Посмотреть один случай

```bash
python3 -m bench.agentpii5 microscope <case id> --run <A>
python3 -m bench.agentpii5 microscope <case id> --run <A> --run <B>   # две ленты и различия
python3 -m bench.agentpii5 microscope <case id> --run <A> --repeat 2
```

Лента: что показали модели (маскированные сообщения и результаты
инструментов), что она написала (аргументы и ответ), что вернулось
(восстановление), какие хопы объявлены и как их прочитал наблюдатель, вердикт
судьи с цитатой. Только файлы прогона — ни модели, ни сети, ни трат.

УТЕЧКОЙ лента называет ровно то, что считает утечкой `metrics.coverage`:
значение, которого не покрыла НИ ОДНА замена. Замена шире объявленного значения
(нашли весь адрес, в корпусе объявлена улица) — это защита, и лента помечает её
«гейтвей заменил шире»; замена, задевшая значение краем, — «УТЕЧКА
(частичная)».

Рядом: `quarantine <A> <B> <C>` (или `--runs-file runs.json`) называет случаи,
которые в трёх прогонах подряд ведут себя нестабильно у ВСЕХ плеч при
одинаковых условиях. Это дефект случая, а не движка; пометить его в корпусе —
решение человека, команда ничего не меняет.

## 6. Откалибровать судью (без этого отчёт — НЕПОЛНЫЙ)

Пока судья не откалиброван, каждый отчёт печатает «НЕ ОТКАЛИБРОВАН» в шапке и
метку НЕПОЛНЫЙ, а ось ответа читать нельзя: неизвестно, совпадают ли вердикты
модели с человеческими. Калибровка — процедура из ТРЁХ команд, и вторая из них
— ваша разметка.

```bash
# 1) слепой лист разметки + K−1 повторов судьи (ЕДИНСТВЕННЫЙ шаг, который
#    тратит деньги: 50 ответов × 2 = 100 вызовов судьи)
python3 -m bench.agentpii5.calibration export \
    --run bench/runs/<дата>/v5-live-<ярус> \
    --out /tmp/calib-sheet.jsonl \
    --repeats 3 --ceiling 2.00

# 2) РАЗМЕТКА: в каждой строке листа проставить "human_label"
#    одной из: "верно" · "частично" · "неверно" · "выдумал"

# 3) метки + вердикты прогона -> штамп в <run>.judge.jsonl
python3 -m bench.agentpii5.calibration import \
    --sheet /tmp/calib-sheet.jsonl \
    --run bench/runs/<дата>/v5-live-<ярус> \
    --out bench/agentpii5/calibration/<судья>.<промпт12>.jsonl
```

`<промпт12>` печатает первая команда («промпт d39ef7aa94bd»); имя файла целиком
собирает `calibration.calibration_path`. Значений из корпуса в нём нет: ответ,
диалог и оракул живут только в листе разметки и на импорте отбрасываются.

Третья команда печатает «откалиброван» или «НЕ ОТКАЛИБРОВАН» и возвращает 1 во
втором случае. После неё `report` (рецепт 2) перестаёт быть неполным ПО СУДЬЕ —
дыры по метрикам и по хопам он считает отдельно и называет своими словами.

**Сколько стоит первая команда.** Ровно 100 вызовов судьи
(`CALIBRATION.repeat_sample` × (`repeats` − 1)). Цену одного вердикта ваш
прогон уже записал — `judge_cost_usd` в `<run>.triples.jsonl`; умножьте на 100
и возьмите `--ceiling` с запасом. Потолок — верхняя граница, команда
останавливается сама и пишет, на чём; ниже `QUERY_CAP_USD` = $0.20 он не
имеет смысла, столько резервируется под один запрос.

**Сколько размечать и сколько это стоит по времени.** Лист — ровно 300 ответов
(`contracts.CALIBRATION.sample_size`), выборка стратифицирована по «тип ПД ×
семья × регистр», 20% из яруса holdout. На ответ уходит 20–40 секунд: прочитать
вопрос клиента, ленту диалога, ожидаемые значения (`oracle_literals`) и сам
ответ, выбрать одну метку из четырёх. Итого **2–3,5 часа**, и лист можно
размечать в несколько заходов — строки независимы, порядок не важен.

**Чего делать не надо.**

- Имя судьи и ярус holdout задавать не надо: первое берётся из
  `<run>.meta.json` прогона, второе — из `ladder.json`, и обе строки печатает
  сама команда. Флаги `--judge-model` и `--holdout` остались для редкого
  случая, когда калибруют не ту модель, которая судила; забытый флаг раньше
  стоил трёхсот размеченных вручную строк, по которым `stamp` печатал n=0.
- Не заполняйте `judge_label`: лист СЛЕПОЙ, метка судьи пристыковывается на
  импорте. Строку с непустым `judge_label` `import` отказывается читать —
  человек, увидевший вердикт судьи, не второй независимый разметчик, и κ
  мерила бы якорение.
- Не размечайте два прогона одним листом: штамп считается только по строкам
  СВОЕЙ модели и СВОЕГО промпта (`prompt_sha256`), правка промпта судьи
  обесценивает калибровку механически.

**Пороги** (`contracts.CALIBRATION`, спека §8.5): 300 размеченных, сырое
согласие ≥ 0.85, κ ≥ 0.70 на всей выборке и на каждом типе с ≥ 20 примерами,
расхождение K=3 повторов ≤ 10%. Не сошлось — отчёт остаётся неполным и говорит,
какой именно порог не взят.

Весь путь прогоняется офлайн на скриптованном судье
(`test_calibration.test_the_whole_loop_runs_offline`): выборка, лист, разметка,
повторы, стыковка, штамп и вопрос отчёта «судья откалиброван?» — тот же код,
единственное, что подменено, — модель.

## Файлы прогона

Каталог по умолчанию — `bench/runs/<дата>/v5-live-<ярус>`; `<run>` — id прогона.
Нормативный список — `contracts.RUN_FILES`.

| файл | что в нём |
|---|---|
| `corpus.json` | снимок корпуса в форме v4 — по нему читают все читатели v4 |
| `corpus.v5.json` | снимок корпуса v5: хопы, формы, инструменты. Отчёт replay'ится по нему, а не по дереву |
| `<run>.arms.jsonl` | по записи на плечо, форма v4 без изменений |
| `<run>.arms.v5.jsonl` | плечо I целиком: ходы агента, подмены, что он прочитал |
| `<run>.triples.jsonl` | статус, цена и вердикт на тройку; `excluded` — в том числе снятые обрывом |
| `<run>.hops.jsonl` | по наблюдению на хоп: то, что посчитали метрики формы |
| `<run>.judge.jsonl` | строка 0 — штамп калибровки, дальше вердикты судьи |
| `<run>.spend.tsv` | журнал трат (агент и судья), формат v4 |
| `<run>.meta.json` | чем был прогон: модели, ярус, потолок, метка и заметка, дерево и происхождение, провайдер с ценами, шлюз |
| `<run>.report.txt` | отчёт для человека: цена, блок v4, линии v5, срезы, судья, отказы гейта |
| `<run>.gate.json` | по метрике: печатается ли она и почему — доказательство, что отчёту было позволено печатать |
| `<run>.report.json` | тот же отчёт как ДАННЫЕ, одна версионированная схема. На нём строятся тренд и статьи |
| `<run>.public.json` | подстрока предыдущего, которую можно показать наружу. Список полей явный; ни одного значения из корпуса |

Реестр прогонов — `bench/agentpii5/runs.json`: строка на прогон, дописывается
и при завершении, и при прерывании, задним числом не меняется.

## Чего сегодня нет

Названо здесь, чтобы это не выяснялось командой, которая молча сделала не то.

- **Плечо шлюза по HTTP.** `--gateway http://host:port` объявлен и ОТКАЗЫВАЕТ:
  клиентский путь написан (`provider.HttpGateway`, `probe_gateway`), но плечо
  всё ещё строит шлюз в этом же процессе, и прогон записал бы свои числа на
  счёт чужого контейнера (ТЗ §4.2).
- **Чужой провайдер.** Плечи зовут модель через `claude_agent_sdk`
  (Anthropic). `--provider openrouter|local` отказывает по той же причине:
  запись назвала бы модель, которая не отвечала. Цены и id моделей при этом
  пишутся в `meta.json` всегда (`provider.PRICES`).
- **Кеш ответов модели ПОД ДРУГОЙ ПРОМПТ.** `provider.AnswerCache` написан и
  ждёт случая, когда пересчитать надо промпт (судья с другой рубрикой).
  Пересчёт ПЛЕЧЕЙ новым наблюдателем уже есть и денег не стоит — это
  `run --replay <каталог>` (см. «Сделать прогон» выше): хопы
  считаются заново из записей прогона, ни одного вызова модели.
- **Оценка по ценам, а не по прошлым прогонам.** `dry-run` без единого
  прошлого прогона той же пары моделей честно говорит «основание: только
  резерв»; `provider.estimate_usd` умеет считать по токенам, и они пока не
  соединены.

## Проверки

Тестов нет пакетного раннера; каждый — скрипт с `main()`.

```bash
for t in test_contracts test_records test_form test_tools test_mock test_schema \
         test_observe test_metrics test_fixtures test_report test_report_gate \
         test_generator_a test_revise test_build test_generator_b test_judge \
         test_calibration test_harness test_harness_stream test_cli \
         test_runinfo test_compare test_microscope test_trend test_repro \
         test_provider test_reportjson test_quarantine test_perfect; do
  python3 -m bench.agentpii5.$t || echo "КРАСНО: $t"
done
python3 -m bench.agentpii5.report --selftest      # мутанты метрик: фикстуры обязаны их ловить
python3 -m bench.agentpii5.test_perfect --tier max  # приёмка на ПОЛНОМ корпусе, ~2 мин
python3 -m bench.agentpii5.build --check
```

`test_perfect` — приёмка прибора: идеальный шлюз обязан получить максимум, а
четыре подпорченных — не получить. Публикуемые числа берутся только с `max`.

В CI это разложено на две половины (ТЗ §6.2): ярус приёмки — на каждый push
(`.github/workflows/checks.yml`, работа `engine`), полный ярус — в ночном
прогоне (`.github/workflows/gates.yml`, работа `full`). Красный порог = красный
CI; полный ярус на каждый коммит — это две с половиной минуты ожидания, то
самое, которое учатся пропускать.
