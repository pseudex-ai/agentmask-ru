# Три продукта Pseudex: страницы проверки спроса

## Что сделано

- Главная сохраняет существующую воронку клиентского сервиса. Крупный блок «Лучшие ИИ-модели. С защитой ваших данных» ведёт в три направления. В первых двух карточках — лаконичные пиктограммы вместо схем; в coding — серые официальные марки и метка «Desktop-приложения · скоро».
- `/ai-security`: корпоративная платформа AI-безопасности. Вместо HTML-макета — галерея семи реальных экранов запущенной ветки must-core: политика, агенты, доступ, журнал, интеграция, проверка текста, статистика. В верхней схеме — локальные серые марки Claude, ChatGPT и Google. Заявка на beta-пилот.
- `/ai-coding`: защищённый AI-кодинг, семишаговая fullstack-сессия MCP → grep/Read → .env → локальный API → patch → тесты → история. Переключатель «Без защиты / С Pseudex» показывает риск секрета в контексте, а не только поиск по email. Bash не исполняется; результаты тестов иллюстративные. Коннекторы и ранний доступ.
- Названия карточек называют продукт. Слоганы и конкретная польза идут ниже; краткое описание каждого направления — в серверном HTML главной, не скрыто за JS.
- Отдельные title/description/canonical и записи sitemap. Нет придуманных метрик, отзывов, клиентов или гарантий совместимости.

## Источники и границы обещаний

Изучены текущий публичный https://pseudex.ru и исходники опубликованной базы `platform/v0.3.38` (`2cddd2c9`). Реализация изолирована в `feat/product-beta-pages`.

Корпоративный продукт: ветка `feat/must-core`, build brief, полный sprint/matrix/decisions/plan и все 18 контрактов `docs/must-core/`, сверены с runtime. Показаны существующие в ветке policy/access/catalog/applications/journal, но не объявлены готовыми rollout/rollback, SSO, DLP/SIEM, HITL или конструктор regex. Журнал в демо — пример безопасного журнала, не обещание отсутствия любого content logging во всех transport paths.

Coding: ветка `feat/coding-codex`, `docs/tz-ai-coding-track.md`, локальный execution note и SP07/wire/live evidence; Anthropic shim из `spike/anthropic-shim` — эксперимент, не security acceptance. DSH-диалог найден: «Таааак смотри Наша за (1)», `session-2ec1a145-845f-4944-8840-53509ccdf557`. Codex subscription transport подтверждён локально, но это не полная приёмка four-hop coding. Claude Code — в разработке; другие CLI — индивидуальная проверка; ChatGPT/Claude desktop — планы без обещанной даты.

Coding-интерактив — полностью локальная синтетическая симуляция. Корпоративная галерея — настоящие снимки Chromium из `dev_platform_demo.py`, запущенного с новым временным томом: реально арендованный бандл, SQLCipher, три сервиса с отдельными ключами, пользователи с разными правами, 54 обработанных синтетических запроса, шесть блокировок тестовых секретов и 11 проверенных восстановлений. В самой `feat/must-core` обновлены графитово-фиолетовые токены и 12 контурных иконок; внутренняя демо-плашка убрана по запросу владельца, как и верхний зазор над «Политикой». Происхождение снимков и синтетических данных указано в подписи галереи и manifest, а не повторяется полосой внутри интерфейса. Профилирование включено — задержки измерены процессом. Снимки 2× (3200 физических пикселей на 1600 CSS px) для чёткости на Retina. HTML работающего интерфейса не подменялся; PNG конвертированы в lossless WebP без изменения геометрии. Provenance, commit ветки, размеры и SHA-256 — `storefront/static/products/platform/manifest.json`. Интеграция снята в пределах viewport, остальные экраны целиком. На странице доступны прокрутка снимков и открытие полного размера; это просмотр, не живое управление админкой. Никаких uploads, доступа к файлам посетителя, вызовов модели или исполнения команд на маркетинговых страницах. Код доступен модели в разрешённом объёме: не обещаем скрыть бизнес-логику и одновременно анализировать её. Model proxy не заменяет sandbox/OS-политику.

## Fullstack coding-сценарий и источники

Новая сессия — адаптированный сценарий, **не опубликованный настоящий транскрипт** и не доказательство совместимости Pseudex со всеми показанными инструментами. Полного проверяемого транскрипта Read/Grep/Bash/API/MCP/patch/tests в доступном поиске не найдено.

- [Sentry: Agents need production context](https://blog.sentry.io/agents-need-production-context/) — MCP-расследование checkout-ошибки, стек/trace, минимальная правка, regression test и test suite. Их причина — потерянный индекс, а не наш сценарий; это источник формы рабочего процесса.
- [Claude Code: common workflows](https://code.claude.com/docs/en/common-workflows) — исследование цепочки frontend/backend, воспроизведение, правка и тесты.
- [Stripe: webhooks](https://docs.stripe.com/webhooks#handle-duplicate-events) — повторные доставки и дедупликация; raw body нужен для проверки подписи. В нашем примере повторяется локальное зачисление, **не второе списание Stripe**.
- [Claude Code sandboxing](https://code.claude.com/docs/en/sandboxing) — sandbox shell и защита модельного контекста не взаимозаменяемы.

Все значения fixtures вымышлены: почта на `.example`, внутренние адреса вымышленных проектов, никогда не выданные Stripe/GitHub credentials. Фиксированные пары `coding-session.js` — иллюстрация политик, **не детектор**. Плейсхолдеры `[SECRET REMOVED]` убраны: подмены правдоподобны и стабильны, `sk_test_`/`ghp_` сохраняют префикс, длину и посимвольный класс тела, PostgreSQL DSN остаётся URI. Механика сверена с `vault._fake_secret` и `credentials.secret_prefix` в must-core: это действительно форма подмены, а не обязательный редактирующий маркер. Настроенная политика всё ещё может блокировать SECRET; внутренние хосты, DSN, свои tenant/секреты требуют явных правил, а не обещания универсальной детекции.

Правдоподобный фейк не авторизует запрос. Настоящий ключ нельзя слепо возвращать в произвольный Bash: для выполнения — локальная подача credentials в разрешённую операцию. Подписанный raw body не переписывается как model-view. Вместо второго примера пути показан строковый tenant внутри контекста diff: до применения разрешённого патча нужно точное восстановление литерала. Вычисленный хэш/подпись от подмены не является обратимым токеном; требуется доверенное вычисление на оригинале или отказ. Тестовый дамп снова приносит ключ, а история должна сохранять те же подмены. Имена переменных, полезный код, assertions и event ID остаются. Результаты Vitest/Playwright иллюстративные, команды не исполняются. Серверные partials: `coding-hero-session.html` и `coding-session.html`; стили из `coding-session.css`.

Переходы страниц: `navigation.js` + `navigation.css`, только мягкий opacity-fade (выход 140 ms, вход 280 ms). Владелец отклонил стилизацию маскирования — полос, шторок и перемещения страницы больше нет. Нет `preventDefault`, задержки перед запросом, HTML-fetch роутера, prefetch приватных страниц или замены POST на JS. В sessionStorage только одноразовая отметка времени без URL или контактов. При отменённой загрузке уходящее затемнение снимается; BFCache восстанавливает видимую страницу. Hash, внешние ссылки, новые вкладки и downloads не запускают эффект; JS off/storage denied — обычная навигация. `prefers-reduced-motion` отключает эффект.

Галерея экранов: перекрёстный fade — публичный inert/aria-hidden снимок старого экрана 300 ms, новый экран 360 ms. Старый узел не принимает фокус/клики, не содержит дублирующихся ID, удаляется при завершении или новой команде. При reduced-motion смена мгновенная. Все экраны, включая «Проверку на тексте», открываются с scrollTop=0 — автоматическая прокрутка к результату удалена. Coding-панели и пояснение — мягкий перекрёстный fade 280/320 ms по действию пользователя, без сдвига; высота меняется за 320 ms, controls остаются на месте. Клон только статического вымышленного примера, inert/aria-hidden, без data-hooks/ID/aria-live, с очисткой при быстром переключении. Браузерный тест проверяет действительно запущенные анимации обычного режима, а не только наличие CSS.

## Пространственный motion главной — исследование Awwwards

Изучены [галерея Awwwards](https://www.awwwards.com/websites/) и live-страницы, а не только теги и скриншоты:

| Референс | Что берём | Что не переносим |
|---|---|---|
| [Moto Finance](https://www.awwwards.com/sites/moto-finance) → [live](https://www.moto-card.com/) | Продукт как физический объект: глубина планов, направленный свет, спокойная композиция | Полноэкранное кинематографическое вступление, видео/тяжёлую сцену |
| [Cerebrium](https://www.awwwards.com/sites/cerebrium) → [live](https://cerebrium.ai/) | Разная амплитуда пространства и редких фоновых точек | Огромную WebGL-сцену, непрерывный render loop, чужие assets |
| [SAFE](https://www.awwwards.com/sites/safe-security-1) → [live](https://safe.security/) | Тональную графитово-фиолетовую глубину и техническую фактуру для серьёзного B2B | Чужие доказательства, клиентские логотипы, собственные заявления о наградах |
| [Heron AI](https://www.awwwards.com/sites/heron-ai) → [live](https://heronaiapp.com/) | Связь визуального движения с продуктовым сценарием | Захват wheel/scroll, длинную загрузочную заставку; в проверенном browser-сеансе обычный scrollY не двигался |

Реализация — [spatial-motion.js](../static/spatial-motion.js), [spatial-motion.css](../static/spatial-motion.css), декоративный partial [home-depth.html](../templates/products/home-depth.html). Только главная: панель героя остаётся функциональной и ортографической, двигается по целым пикселям (не наклоняем мелкий текст). За ней две декоративные плоскости, фиолетовый рассеянный свет, контурная сетка и 24 локальные точки. Задний план двигается заметнее переднего: до 58 px на нормализованный ход сцены против 10 px панели; курсор — максимум 20 px фона против 3 px панели. Эти координаты — параметры декора, не показатели защиты или live-трафика.

Три продуктовые карточки входят с согласованным подъёмом до 54/67/80 px и небольшим углом, затем выравниваются; фон/иконки реагируют на курсор. Текст никогда не скрыт ради эффекта, CTA и href остаются теми же. Контент обычной страницы доступен без скрипта. Ни блокировки скролла, ни нового canvas/WebGL, ни видео, ни сторонней библиотеки/сети. Один demand-driven RAF с easing 0.16; останавливается после стабилизации, вне сцены и при скрытой вкладке. На ширине <900 px и с reduced-motion динамика выключена, остаётся статический дизайн. Проверки: [test_home_spatial_motion.py](../test_home_spatial_motion.py), общий браузерный прогон и brand-palette.

**До:** плоская панель и одинаковая сетка. **После:** продуктовая панель, защитный контур и фон ощущаются разными планами, без перемещения основного текста. Это локальная дизайн-проба, не заявление, что сайт получил уровень или награду Awwwards.

### Итерация 2 — полная главная и колода заказа

Владелец одобрил пространственные карточки и прямо выбрал для hero **этапы текущего заказа**, не три продукта и не скриншоты админки. Дизайн и параметры продуктовых карточек не изменены. Дополнительный [референс Awwwards](https://www.awwwards.com/sites/symbiotic-security) → [Symbiotic](https://www.symbioticsec.ai/) полезен разделением функций на отдельные предметные сцены; его заявления о harness, sandboxing и benchmark не являются нашими claims. Старый референс Google Cloud Infrastructure сейчас переадресует на общий Cloud — его движение не выдаём за наблюдавшийся актуальный пример.

[hero-deck.js](../static/hero-deck.js) и [hero-deck.css](../static/hero-deck.css) заменяют старое нарастающее сообщение шестью отдельными листами тех же вымышленных заявок: клиент → обнаружение → подмена → модель → оригиналы для инструмента → итог. Данные и DOM-helpers остаются в [landing.js](../static/landing.js), старый accumulating controller удалён. Перелистывается тело публичного экрана: старый inert/aria-hidden клон без ID/data-hooks уходит за 360 ms, новый лист приходит за 460 ms. Шапка, стрелки, pause и phase-buttons остаются на месте — маленькие hit targets не должны уезжать из-под повторного клика. Клон удаляется при завершении/повторном действии. Текст снова ортографический после движения. На <900 px — только crossfade, при reduced-motion — мгновенная ручная смена; стартовый итог показывает подмену и оригинал вместе. Системная настройка отслеживается динамически. Стрелки, клавиши ←/→ в управлении, шесть доступных phase-buttons и явная пауза; hover/focus, невидимая вкладка и уход из viewport останавливают autoplay. Повторное нажатие выбранного этапа не перелистывает ту же страницу. Без JS — статический noscript-пример и скрытое неработающее управление.

[landing-route.js](../static/landing-route.js) и [landing-route.css](../static/landing-route.css) связывают три плеча `#how` с обычной прокруткой: горизонтальная линия на desktop, вертикальная на mobile, текущий/пройденный узел. Текст и ссылки не скрываются; нет закрепления, перехвата scroll или выдуманного live-трафика. Один отдельный RAF только пока значение доходит до целевого; в покое/вне viewport/скрытой вкладке — стоп, reduced-motion оставляет полную статическую схему.

[landing-interactions.css](../static/landing-interactions.css): вместо одинакового подъёма — кромка и label у метрик, сканирующая кромка и контраст чипов у отраслей, неподвижные тарифы, заполняемые CTA без движения hit target, рамка у видео и отчёта, направленная стрелка статьи, доступные focus-состояния формы и тарифного radio, спокойное состояние FAQ. Настоящий выбор тарифа, тексты цен, accordion heights и video preload/controls не меняются. Hover-эффекты — fine pointer, keyboard focus отдельно, физическое движение отключается при reduced-motion. Нет новых библиотек, assets третьих сторон, API/LLM-вызовов, изменений согласий или отправки данных посетителя.

## Проверка спроса, а не выдуманная конверсия

Форма создаёт отдельный `ops.ProductInterest`: product, role, harness, use_case — закрытые enum; email; consent_at/revision; created_at. Нет аккаунта, лицензии, счёта, оплаты или автоматического qualified_lead. Подтверждение только после DB INSERT и с короткоживущей подписанной product-only cookie. GET-параметр сам по себе не подтверждает заявку. CSRF, honeypot, лимит попыток, DB CHECK enum.

Просмотры двух URL остаются в существующей first-party таблице Visit. Это просмотры/суточные отпечатки, не недельные уникальные люди и не доказанная когортная конверсия. Заявки считаются отдельно по продукту; качество лидов требует разговора. Внешние counters/replay на страницах формы выключены, даже если раньше принято согласие: email не должен попасть в запись сессии. Метрика goals этим изменением не создаются и не отправляются.

Оператор видит заявки в штатной Django admin: `/<PSEUDEX_ADMIN_PATH>/ops/productinterest/`, с MFA и правом просмотра модели. Поля read-only; удаление по отдельному праву. Контакты не экспортируются провайдерам аналитики.

## Локальный просмотр

Из `storefront/`, с установленными зависимостями storefront:

```bash
export PSEUDEX_DEBUG=1
export PSEUDEX_SECRET_KEY=local-preview-only
export PSEUDEX_DB_PATH="$PWD/product-preview.sqlite3"
export PSEUDEX_ANALYTICS_MODE=off
export PSEUDEX_METRIKA_ID=''
export PSEUDEX_SITE_URL=http://127.0.0.1:18765
python manage.py migrate --noinput
python manage.py seed_plans
python manage.py runserver 127.0.0.1:18765
```

Не использовать production БД/ключи. Preview ничего не отправляет клиентам; тестовые заявки записываются только в локальную SQLite. Публикация и production migration — отдельное действие владельца.

Проверки:

```bash
python test_product_pages.py
python test_product_pages_browser.py --base-url http://127.0.0.1:18765
python test_home_spatial_motion.py --base-url http://127.0.0.1:18765
python test_landing_deck.py --base-url http://127.0.0.1:18765
python test_acquisition_consent.py
python test_seo.py
```

Browser test разрешает только loopback HTTP и блокирует стороннюю сеть; проверяет responsive layout 320/390/768/1440, две темы, интерактивы, формы, confirmation, JS/CSP errors. Создаёт только синтетические контакты example.test. Изображения проверки в `.preview/` gitignored.

Официальные марки и их источники — `storefront/static/brands/README.md`. Серые логотипы показывают названия интеграций, не партнёрство и не пройденную приёмку.
