# Счётчик защищённых значений — демо и контракт подключения БД

## Статус

Пока клиентская база маленькая, блок по просьбе владельца **выключен на публичной главной**: Django не рендерит разметку, не подключает CSS/JS и не опрашивает API — посетитель не видит ни счётчика, ни запросов к нему. Код и контракт сохранены для включения позже.

Посмотреть можно только явной preview-страницей: `http://127.0.0.1:18765/?counter-demo=1#protection-counter` (noindex). Когда в `PSEUDEX_PUBLIC_COUNTER_LOADER` появится одобренный реальный агрегат, блок включится на обычной главной автоматически, уже с реальными снимками; отдельного переключателя не нужно. Включать его при отсутствии реального источника нельзя.

По просьбе владельца это финальная подача: на главной нет бейджа «ДЕМОНСТРАЦИЯ», строки «Синтетические числа / Не статистика клиентов», служебных кнопок и подписи снимка. Демо остаётся синтетическим: `data-mode="demo"` и доступная подпись числа по-прежнему называют его демонстрацией, а перед публикацией/деплоем источник обязан быть заменён реальным агрегатом БД (настройка loader ниже). Показывать синтетическое число без видимой пометки на опубликованной странице нельзя.

Визуальная идея — одно типографическое число (после обратной связи владельца desktop-максимум уменьшен с 184 до 140 px, блок стал компактнее и не спорит с hero), как в [Stats Counter / Austin Urology Institute](https://www.awwwards.com/inspiration/stats-counter-austin-urology-institute), и самостоятельная секция с сильной типографикой, а не сетка метрик. Просмотрены [Awwwards](https://www.awwwards.com/websites/) и [DePoly footer interaction](https://www.awwwards.com/inspiration/footer-interaction-depoly). Чужие assets/код не скопированы. Действующие Inter, JetBrains Mono и обе палитры брендбука.

При обновлении перелистываются только меняющиеся разряды; перенос через `9 984 → 10 016` синхронный, без случайных цифр или ложных промежуточных итогов. Рядом остаётся разность принятого полного снимка и предыдущего числа. По просьбе владельца убраны и следующий рубеж, и сообщения о достигнутых отметках: это информационная метрика, не игровой прогресс. Фронтенд **не прибавляет** эту разность повторно — это только подпись анимации.

## Реальная частота и смысл usage

Проверены исходники ветки marketing, не состояние развёрнутого production:

- [license.py](../../prototype/pseudex/license.py) задаёт `PSEUDEX_USAGE_REPORT_SECONDS=120` по умолчанию; `_report_usage` отправляет накопительный итог независимо от продления аренды, `_usage_due` — отдельный таймер. Первый проход отчётного потока отправляет сразу; тики потока добавляют несколько секунд, сеть/ошибки — дополнительную задержку. Это не SLA «ровно раз в две минуты». Финального usage flush в `stop()` нет.
- [service.py](../../prototype/pseudex/service.py) и [proxy.py](../../prototype/pseudex/proxy.py) добавляют `values` из `count_values_since(vault.db, 0)`. `requests` — успешные вызовы маскирования, включая без ПД; `entities` — события аудита, зависящие от кэша. Их нельзя выдавать за число разных защищённых значений.
- `values` — строки соответствий волта в пределах установки/области каноникализации, не глобально уникальные люди или значения во всех компаниях. Несколько воркеров одной установки читают общие накопительные счётчики; каждый отчёт не является отдельным приращением.
- В [licensing/store.py](../../prototype/licensing/store.py) есть накопление `values_total`, в [licensing/server.py](../../prototype/licensing/server.py) — приватный `pseudex_fleet_values_total`. Это **не** готовый проверенный публичный показатель. Статически видны условия, которые надо проверить до публикации: понижение показания трактуется как reset, freshness не закрывает все пути накопления, а счёт волта не исключает synthetic/self-check так же, как аудит. Это наблюдения по коду, не подтверждённые в этой работе эксплуатационные инциденты.
- Текущий биллинг использует ёмкость запросов; [services.py](../billing/services.py) считает protected values информационным числом, не единицей начисления. Почасовой `UsageDay` витрины хранит запросы и не заменяет агрегат значений.

Поэтому разнесены два ритма: установка отчитывается примерно каждые 120 с, браузер читает текущий общий снимок API каждые 5 с. Отчёты разных установок могут приходить между этими тиками; если итог не изменился, число не анимируется. Уменьшать интервал отчёта движка ради визуального эффекта не требуется.

## Полный снимок API

`GET /api/public/protection-counter`

```json
{
  "total": 158020,
  "updated_at": "2026-10-18T13:20:00Z",
  "revision": "public-snapshot-42",
  "mode": "reported",
  "poll_after_ms": 5000
}
```

- `total` — полный абсолютный итог из одобренного источника, целое от 0 до `2**53-1`. Настоящий ноль отличается от неизвестного значения.
- `updated_at` — время исходного снимка, не выдуманное время браузера; старый реальный снимок явно помечается.
- `revision` — стабильная версия снимка. Устаревший по времени ответ не перетирает новый; одинаковый итог не запускает перелистывание. Новая корректировка вниз принимается как полный итог, а не скрывается `max()`.
- Нет провайдера/источник недоступен/данные неправильного типа → HTTP 503, `total: null`, `mode: unavailable`; сайт не подставляет демо или 0 за реальные данные. Лишние поля источника (организации, ключи, тарифы) в JSON не проходят.
- Сервер кэширует один санитизированный агрегат на 5 с, включая короткое отрицательное кэширование. Браузер не кэширует ответ. Клиенты не создают отдельные записи и не меняют БД.
- Демо: `?demo=1&started=<unix>&advance=<n>`. Сервер считает синтетический снимок от общей эпохи; повтор одного запроса в то же время не накапливает его ещё раз. `advance` — ограниченный управляющий параметр демо, не число защищённых значений. Запрос без `started` начинает новую демоэпоху и возвращает `demo_started_at`; никаких клиентских часов для расчёта итога не нужно.

Демо и реальный источник имеют один основной контракт. Фронтенд всегда получает `total` через fetch, никогда не накручивает число по собственному таймеру.

## Как потом подключить БД без изменения UI

Настройка `PSEUDEX_PUBLIC_COUNTER_LOADER=package.module.read_public_snapshot` задаёт **серверный** zero-argument selector. Он должен читать подготовленный одобренный агрегат из БД и возвращать:

```python
{
    "total": 158020,                 # int, не сумма уже принятых ответов
    "updated_at": aware_datetime,    # время исходного снимка
    "revision": "public-snapshot-42"
}
```

После настройки главная сама показывает тот же компонент в режиме «ПО ОТЧЁТАМ УСТАНОВОК», а API начинает отдавать DB-снимки. Дописывать анимацию или менять клиент на другой протокол не надо. Показано интеграционным тестом с **реальной временной SQLite-таблицей**: 158000 → обновление БД → истечение/очистка кэша → API 158020, а не 316020.

**Пока selector реального лицензирующего агрегата не подключён.** Сначала требуется определить допускаемую production-когорту/согласие, исключить self-check/demo, проверить reset/replay/out-of-order и область дедупликации, затем подготовить безопасный snapshot. Нельзя просто выставить `/admin/usage`, Prometheus/admin credentials или частные поля в браузер. Эта работа не меняет accounting и не делает вид, что его корректность уже доказана.

## Движение, доступность и отказоустойчивость

- Каждое перелистывание конечное (~780 мс), линия обновления — до 1000 мс; нет бесконечного RAF. Пауза, ручное обновление, повтор демо.
- Polling последовательный, без перекрывающихся запросов; таймаут 8 с, после ошибки повтор через 15 с. Ошибка сохраняет последний принятый итог и показывает отсутствие обновления, без локальной накрутки.
- Вне viewport/в скрытой вкладке запросы отменяются, polling прекращается, движение доводится до принятого снимка. На возвращении авто получает свежий полный итог. Ручная пауза сохраняется при уходе/возврате.
- Reduced-motion: один начальный снимок, авто выключено, ручное обновление без анимации. Без JS остаётся серверное число и отключённые/скрытые dead controls.
- Число не объявляется скринридером каждые пять секунд; `output` имеет полный доступный label, live region используется для ручных действий.
- Масштаб числа адаптируется к 16-значным безопасным целым; на узком экране нет горизонтального overflow. Тема наследуется, нет новой локальной палитры.
