# storefront — лендинг, регистрация, кабинет

Работает **на нашей инфраструктуре**. С движком не делит ни строчки кода и не
имеет права: витрина не должна видеть персональных данных, а движок не должен
зависеть от магазина.

Выбор стека и что было отклонено — `../docs/tz-site-stack.md`.
Что здесь должно быть по продукту — `../docs/tz-site.md`.

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.dev.example .env.dev   # если нет
set -a; . ./.env.dev; set +a

.venv/bin/python manage.py migrate
.venv/bin/python manage.py seed_plans          # три тарифа с лендинга
.venv/bin/python manage.py createsuperuser     # доступ в /admin/
.venv/bin/python manage.py runserver
```

Без `VEILGATE_SECRET_KEY` приложение **не поднимется**, если `VEILGATE_DEBUG` не
включён. Это не неудобство: фреймворк с рабочим ключом по умолчанию — это
фреймворк, где однажды забыли его задать, а дальше подделка сессий.

## Тест

```bash
.venv/bin/python test_storefront.py
```

Поднимает **настоящий** лицензионный сервер из `../prototype` отдельным
процессом и гоняет весь путь: регистрация → выпуск ключа → кабинет. Мока нет
специально — каждый шаг метрики «15 минут до первого запроса» проходит через
другой сервис, и мок проверял бы мок.

## Что проверяется и почему именно это

- ключ выдаётся **до оплаты**, показывается **один раз** и не попадает ни в
  нашу БД, ни в серверную сессию (сессии Django — это таблица);
- на лендинге **нет поля ввода**: разрешив свой текст, мы начали бы принимать
  чужие ПД к себе, то есть потеряли бы то, что продаём;
- регистрация throttled — каждый вызов минтит ключ на лицензионном сервере;
- организация не видит счета другой;
- в кабинете нет ни диалогов, ни токенов, ни значений — и это утверждение
  проверяется тестом, а не обещанием.

## Границы

| | витрина | контур клиента |
|---|---|---|
| ключи, тарифы, счета | да | нет |
| агрегатные счётчики | да | да |
| тексты, токены, значения | **никогда** | да |

Источник правды о статусе ключа — лицензионный сервер, не эта база. Витрина
является **причиной** изменения статуса (оплатили / не оплатили), а не вторым
местом его хранения: два источника правды у рубильника однажды разойдутся, и
клиент либо встанет оплаченным, либо продолжит работать неоплаченным.
